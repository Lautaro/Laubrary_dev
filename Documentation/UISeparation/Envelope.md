# Envelope presentation bridge

`ZuiSkinEnvelope` keeps its original API, evaluator, pointer handling, selection behavior, and caller-owned `ZUIEnvelopeDef`. It now also carries the semantic classes `zui-envelope` and `zui-envelope__readout`; the old `zui-skinenvelope` and `zui-skinenvelope__tag` classes remain in place.

The optional `ZuiPilotEnvelope.uss` supplies the static readout styling and an opt-in `zui-envelope--legacy-profile`. The profile reproduces the constructor defaults of `ZUIEnvelopeDef`; it is not assigned by the control, so a window that uses a different definition does not receive a blanket replacement look.

The painter receives custom style values through `CustomStyleResolvedEvent` and caches only the resolved scalar and colour values. A style resolution first rebuilds the complete fallback from the envelope's current definition and the caller's `curveColor`, then applies only properties that USS supplied. Therefore a descendant rule on a parent root wins normally, and removing that rule resets to the current definition rather than retaining the former parent's values. Geometry padding and handle radius/hit slop use the same resolved values for drawing and hit testing.

`curveColor` remains caller data by default because it distinguishes domain curves such as volume and pitch. A stylesheet may deliberately take over that colour with `--zui-envelope-curve-color`; this is the explicit presentation bridge, not a change to runtime envelope data.

The custom properties are `--zui-envelope-background`, `--zui-envelope-border-color`, four `--zui-envelope-border-{top,right,bottom,left}`, `--zui-envelope-grid-color`, `--zui-envelope-grid-rows`, `--zui-envelope-grid-thickness`, four `--zui-envelope-padding-{top,right,bottom,left}`, `--zui-envelope-curve-color`, `--zui-envelope-curve-thickness`, `--zui-envelope-curve-hover-thickness`, `--zui-envelope-hit-radius-extra`, `--zui-envelope-selected-color`, `--zui-envelope-selected-stroke-thickness`, `--zui-envelope-selection-box-fill-alpha`, `--zui-envelope-hover-saturation-scale`, `--zui-envelope-hover-value-scale`, `--zui-envelope-uncertainty-{fill-alpha,stroke-alpha,stroke-thickness}`, `--zui-envelope-dotted-{white-mix,min-width}`, and `--zui-envelope-ghost-opacity`. Each of `editable`, `x-editable`, `y-editable`, and `not-editable` also accepts `--zui-envelope-<state>-{radius,hover-radius,fill,hover-fill,border-color,border-width}`.

All numeric custom properties are unitless because the resolver requests `float`. Thicknesses, padding, borders, handle radii, and hit slop clamp to finite nonnegative values. Opacity and colour-mix values clamp to `[0,1]`; grid rows clamp to `0..256`. Sampling density, dashed-segment construction, edge safety, and minimum plot geometry remain dynamic algorithmic behavior rather than theme tokens.

For an exact pilot fixture, the coordinator should read the `ZUIEnvelopeDef` passed to that fixture and copy its resolved values into a descendant selector such as `.lau-tool-pilot .zui-envelope`. Capture background, border colour and all four widths, grid colour and rows, all four padding values, both curve widths, hit slop, selected colour, and all six values for each handle state. This preserves the fixture's actual sheet/palette values; `zui-envelope--legacy-profile` is only correct when the fixture uses the built-in defaults. Capture the caller's curve colour separately unless the pilot intentionally sets `--zui-envelope-curve-color`.
