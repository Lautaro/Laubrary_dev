# Optional Laubrary ZTracker

This sibling package depends on Laubrary 0.9.0; core Laubrary has no tracker dependency. Install both packages using Unity Package Manager's local package option, selecting the core package first and this package second. Native playback supports Windows x64 Editor and Windows x64 player only. The plugin importer excludes every other platform and disables preloading. Data and editor code remain portable.

Open **Laubrary > ZTracker**. **New song** saves a synth instrument and a four-note looping song under the host project's Assets/ZTracker folder. Choose a song and press **Play**, or choose an instrument and press **Audition**. **Stop**, closing the window, assembly reload, exiting Edit/Play mode, and an audio-device change release the owned engine. Edits to tempo and first-channel gain/pan are undoable and take effect on the next Play. Full pattern/instrument authoring migration is owned by ZTracker T-0004; this preview window is deliberately limited.

Import the optional **ZTracker Demo** sample to get a saved scene, song and synth instrument. Open its scene and enter Play mode; **Space** explicitly starts or stops the song. The development host's saved copy lives under Assets/Demos/ZTrackerDemo. This sample's keyboard dependency does not enter the production tracker assemblies.

Runtime: add `Laubrary.ZTracker.ZTrackerPlayer`, assign its `song`, then explicitly call `Play()` and inspect its boolean result and `LastError`. There is no auto-play or engine creation from Update, enabling a component, or querying status. Subscribe to `EventReceived` for events delivered on the main thread. One tracker playback owner is allowed at a time; another request returns an error without replacing someone else's playback.

Existing song and instrument class names, their assembly name `ZTracker`, script GUIDs, and serialized fields are retained. Copy authored assets with their .meta files and referenced audio into the consuming project's Assets area; never install both the standalone legacy tracker assemblies and this add-on together. The keyboard test components, alternate audio host, legacy editor, and legacy ZUI copy are excluded. The data assembly retains the legacy explicit upload helpers and native declarations for source/asset compatibility; these declarations do not load the DLL until called. High-level playback checks platform and ABI first. Low-level upload/interop calls are caller-owned, main-thread-only, and must never race a render; use the high-level player instead.

**Audio-host limitation:** rendering currently enters C++ through Unity's managed audio callback. Enabling playback therefore defeats Zounds SAP's GC immunity across the mixer. Package absence guarantees no tracker callback or binary; installed-but-idle creates no engine or source. Simultaneous playback has not been certified GC-safe. There is no project-wide audio configuration rewrite.

The managed host uses a stereo streaming clip callback so Edit-mode preview and game playback use the same renderer; it does not bounce a song into a file. Unity buffers the stream, so song events describe native render progress rather than a measured physical-speaker timestamp. Glitch-free output and event-to-speaker latency have not been certified. Native structural setters still follow the existing POC API; upload through the high-level host before its stream starts, rather than changing native song/instrument storage while rendering.

Removing the add-on: remove explicit tracker components/references from game code and scenes, remove this package, and restart Unity to unload the native DLL. Songs remain in the project's Assets folder, but require reinstalling the add-on to edit or play.

The native source snapshot lives in the development host's Tools/ZTrackerNative folder; it includes the source working copy's sample-blend changes without modifying the original. Build with CMake/Visual Studio 2022 x64 Release and copy ZTrackerEngine.dll to Plugins/x86_64. Its version handshake is ABI 1. Do not replace a DLL already loaded by Unity; close the editor first.
