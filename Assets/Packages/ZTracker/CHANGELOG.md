# ZTracker add-on changes

## [Unreleased]

- Many-note clipping checked on every instrument type (T-0647): without the output limiter, many loud notes overload the mix on the subtractive synth, samplers and drum kits too (12 saw keys at Volume 100% are +18.6 dB, a 3-layer sampler +27.7 dB, 12 drum pads +15.6 dB). The limiter added in T-0635 already holds every one of them at full scale (no sample above it, on live keys, the clean preview, pattern notes and the master), and the level meter reads the summed peak for all of them. New measurement checks per instrument type; a verification-only limiter bypass flag; no change to how anything sounds.
- AutoArp (T-0642): with Legato on and Poly, AutoArp plays the notes held on the track (pattern notes and live keys) one at a time, upwards, each for Arp ms (Per note) or Arp ms shared by the notes (Per cycle). A key let go while others are held keeps its place for Window ms, so keys released a little apart release together: if every key goes within the window the release plays the whole last chord, still arpeggiated; otherwise the arpeggio carries on with the held keys. Retrigger: First (envelopes start only with a new arpeggio), Single (every step restarts its note's envelopes), All (every key press restarts them). Allocation-free; sounds without it unchanged.
- LFO on any envelope or ADSR (T-0641): right-click a value that is an Envelope or an ADSR › LFO adds a wave to it on every note, with Depth (in the value's own units, either side of the envelope), Speed (Hz, or rows per cycle for an envelope measured in song rows, so it follows the tempo), Delay (the time it takes to fade in, ms or rows) and a shape (Sine, Triangle, Saw, Square; each starts on the envelope's value and rises). The result stays inside the value's own range (Volume never below 0, Pulse 1..99%). The merged wave is drawn faintly over the curve; Static hides the LFO and keeps it. It runs per note on the audio side (no allocation), keeps moving through the release, is saved with the instrument, and changes apply to a playing song without stopping it; sounds without an LFO render bit-identically. ADSR stage edits and an envelope's Maximum also apply live now (they used to ask for stop and play).
- Output safety limiter and level meter (T-0635): many loud notes at once (a chord on an FM sound, whose operators all start in phase) could add up past full scale and be clipped flat by the output device, heard as a click. The renderer now holds its output at full scale when the mix would go over, recovering in about 100 ms; below full scale it does nothing, so every sound that never exceeded full scale plays bit-identically. The ZTracker window shows the same level meter as Zounds along its bottom edge (song and instrument previews, measured before the limiter: red above 0 dB means the limiter is working; click to clear). `TrackerSapGenerator.TakeOutputPeak()`, `TrackerState.limiterReduction`, render-ticket slot `TrackerRealtime.PeakSlot`.
- FM Level explained (T-0636): the routing was measured correct for every routing (a modulator at Level 0 leaves a plainer tone, a carrier at 0 silences its branch). A carrier's Level now says it is loudness, a modulator's that it is modulation depth, not a volume; the diagram fades an operator at Level 0 and its arrows.
- No leak at script reload (T-0637): a renderer destroyed just before or during a script reload (the instrument preview when the window closes) left its prepared songs and rings parked in a list the reload wiped ("Leak Detected: Persistent allocates 57/104 individual allocations"). They are now freed during the reload once the render is quiet; the graph's late acknowledgement writes to a small untracked cell.
- The ADSR is drawn to time (T-0638): an attack of 0 is a vertical wall, each stage is as wide as it lasts (the sustain plateau keeps a fixed width), a change to one stage moves the stages after it, and faint grid lines with their spacing in the corner ("100 ms", "1 s") follow every edit. The stage sliders stay one row in stage order.
- Envelope Maximum (T-0640): right-click a value in Envelope mode › Maximum sets the top of the curve's range in a number input (prefilled, validated, Undo, reset arrow), where the engine allows more than the slider shows: Volume and FM Level up to 1600%, Tune 12000 cents, Ratio 64, PM 64 cycles, Detune and Vibrato depth 1200 cents, Vibrato rate 100 Hz, Vibrato fade 20 s, Output feedback 16. Stored with the envelope (display only; the engine's clamps still apply).
- ADSR as a value mode (T-0639): every value that can be an envelope (synth, FM operators, presets) can also be Static, Envelope or ADSR (right-click). In ADSR mode the slider is the peak, Start sits beside it and the compact ADSR under them; the stages are stored on the parameter's envelope and written as its points, so playback, playheads and the Envelope mode keep working, and a note released early leaves from the level it reached, like the amplifier's ADSR. Saved instruments are unchanged; the amplifier's own ADSR stays.

- Glide arrives in the time it states (T-0627): a slide moves evenly in pitch and reaches the new note exactly at Glide ms. It used to approach the note gradually, with Glide ms as the time it took to cover about two thirds of the way, so a 100 ms glide got within 5% of the note only after 270–340 ms (measured on synth, FM and sampler). Glide ms is shown for Glide, Legato and Both (hidden for None, where it does nothing) and, in Legato and Both, is also how long an overlapping note takes to slide to the new pitch; 0 jumps. A Legato instrument saved before this keeps jumping until its Notes mode or Glide ms is edited. Glide 0 ms plays exactly as no glide.
- Polyphonic legato (T-0633): with Legato or Both, the new Legato choice Poly makes a note that starts while another note of the same instrument is held on the track (in another column, as in a chord or overlapping lines) join that note's running envelopes, modulation and vibrato instead of restarting them; it differs only in its own pitch, level and pan. With no note held, or only released notes, a note starts as usual. Live keys (computer keyboard, MIDI) follow it too: with Poly each key keeps its own voice and column, where Mono legato still moves the held key's voice to the new pitch. Mono (the default, and how instruments saved before this behave) is unchanged.
- Legato velocity (T-0628): with Legato or Both, Velocity chooses what an overlapping note does with the new note's velocity: Follow (jump to it, as before), Ignore (keep the held note's level) or Slide (move there over Slide ms); Scale % sets how much of the change applies. A volume command takes over a slide at once. Saved instruments read Follow at 100%, which plays exactly as before.
- Instrument envelopes (T-0629): the synth's own per-note envelopes (Blend, pulse width, B ratio, PM, detune) kept time with a clock that drifted by up to 0.7% once a note had been held a few seconds, so a loop drifted out of time (a 200 ms loop was 100 ms late after 20 s); they now stay on time. An envelope can be measured in song rows (Time in › Rows) so it follows the tempo, including a tempo command on a held note. The curve shows one playhead per sounding note of the instrument, the loop as a shaded band between two markers dragged on the curve (forward or ping-pong arrows), the sustain point as a dashed S marker dragged on the curve, and a labelled time axis in seconds or rows; right-click the curve's background to switch the axis legends. The Loop % and Sustain % sliders are replaced by the markers. Shared ZUI pieces: the envelope's loop band and sustain markers, several playheads, tick labels, switchable axis captions and a background context hook; `ZuiValueControl.Options.decorateEnvelope`, `xTickLabel`, `yAxisLegend` and `SetAxisLegends`. The renderer publishes each voice's envelope positions in fixed records (no allocation on the audio side).
- The separate Blend envelope (fixed ADSR) is shown only on sounds saved with it switched on, as Older blend ADSR (T-0630): Blend's own per-note envelope does the same job with more (loop, rows, playheads). Older sounds keep playing their ADSR exactly as saved.

- Renoise/Redux import v1: inspect bounded XRNS/XRNI archives from the modern format family, import arrangements and simple WAV/FLAC sampler instruments, and retain the source archive with a linked mapping recipe. The mapper identifies instruments/plugins/chains/devices, shows usage and pitch ranges, supports replacement sounds, clean excerpt audition and persistent review marks, and preserves existing ZTracker instrument sound design when applying a source revision. Automatic effects are restricted to mixer settings, centered gain and non-muting centered sends; only held/linear mixer-pan automation is converted. Unsupported data and approximations remain visible rather than being executed by guesswork. The new [composer guide](Documentation~/RENOISE_IMPORT.md) defines the actual profile, sound-design ownership, manual chain replacements, format/memory limits and known calibration gaps. No plugin-patch decoder or original-host sound-parity claim is included.

- Reverse-row transport now decelerates forward for 0.75 seconds before changing direction, then accelerates backward and reaches the same pattern's start at exactly three seconds total. Note pitch reaches a 2% near-stop floor, volume reaches 50%, and the public phase/turn-row readout plus direction-tagged clock/events distinguish both stages. Pause and cancellation apply throughout; no history allocation is needed.

- Public `RetriggerNote` replaces all voices and release tails on the first note column with one fresh attack group, independent of authored new-note action/legato. Layers and unison inside the new group remain intact; command handling stays native and allocation-free. `TrackerRetriggerCheck.Execute()` verifies 512 consecutive attacks and release across three buffer sizes and all three new-note actions.

- Note cells retain readable pitch and octave in every note column, including drum-displayed synths and missing drum mappings; mapped icons complement the pitch instead of replacing it. The model editor follows the matching game-owned song through independent heard-clock and native block snapshots, showing actual/queued tempo, row, direction/tape progress, activity, game pitch offsets and gates/mutes. Preview controls are disabled while the game owns playback. A 30 ms poll targets at most 100 ms visible readout lag on a responsive editor; authored controls remain authored values. Checks: `CheckNoteDisplayMatrix()` and `TrackerLiveReadoutCheck.Execute()`.

- Reverse row transport retriggers the current pattern's rows in descending order while each row's samples, envelopes, effects and ticks continue forward. Row timing is normalized to the requested deadline (three seconds by default), with a slowing traversal and half-volume fade, then row zero starts once in the same order. Game tempo/pitch offsets and trigger gates survive landing. Direction-tagged clock anchors and events retain monotonic sample times across the transition; timing/flow commands cannot redirect it. Pause freezes progress, transport changes cancel, and tape/row reverse refuse each other explicitly. Native state is fixed-size and allocates no history. `TrackerRowReverseCheck.Execute()` covers offline samples, event/clock order, partition invariance, controls, cancellation and refusal.

- Optional bounded stereo history enables tape-style game resets: slow the actual rendered master mix while lowering it to half volume, reverse that captured pass to its pattern start, then resume the same order normally within the requested duration (three seconds by default). No history, a missing start or insufficient buffer space explicitly refuses the request. Pause freezes the effect; repeated requests refuse; Stop/Seek/Refresh cancel. Native history is allocated only before publication and freed with its prepared-song owner. Public playback status and engine events report progress and completion; musical callbacks and row-clock queries pause during tape playback. Check `TrackerRewindCheck.Execute()` uses rendered stereo samples and deterministic partitions without hardware or forced collection.

- Row scalar writes no longer emit a tempo command a second time after the row clock is fixed, preserving next-row game tempo precedence and the same BPM in events, readouts and rendered duration.

- Games can set a persistent tempo override at the next row boundary, clear it back to the evolving authored tempo, drive a song command/effect by stable definition identity, and add independent semitone and cents offsets per track. Pitch offsets affect active and future voices after authored tuning, macros and envelopes without changing sample selection or note events. Compatible refresh preserves controls; Play, Stop and Seek clear them. Command targets reuse the existing ramps and automation precedence. Offline verification: `TrackerGameControlCheck.Execute()`.
- The generator exposes stable command writes directly, so the playback facade crosses the engine assembly boundary through its public API without exposing prepared-song ownership.

- Older-format (schema 0) songs and instruments: the committed demo song and synth are now kept deliberately in the older format as the fixture for old saved work, and a new check opens each without changing its file, converts it to a valid model, upgrades an in-memory copy and renders it audibly and bit-identically before and after the upgrade (the package sample copies are compared to them). Opening and playing older songs was already correct; the Command model migration step had been feeding the older instrument straight to the engine instead of going through a playback snapshot like the product does, and now does it the product's way. The engine now refuses an older-format instrument handed to it directly with "Instrument requires schema 1 at slot N" instead of failing with a null reference. Check `ZTrackerModelWindow.CheckCommandModel()` (7 steps).
- The instrument envelope (attack, decay, sustain, release) is a compact control at 30% of its old area (its stage sliders use a slightly smaller type so every readout still clears its letter), titled ADSR instead of Amplitude: a small filled shape whose points still drag, and one slider per stage directly under its lane. Values use useful steps instead of tenths of milliseconds: whole milliseconds below 100 ms, 10 ms up to one second, 0.05 s from one second (shown as "1.25 s"), sustain in whole percent. Saved values are unchanged (seconds and 0..1) and an older value such as 5.7 ms is only shown rounded until it is edited. The same control is used for the synth amplifier, each FM operator, the synth blend envelope, the second sample's envelope, the AHDSR modulator and a preset's ADSR section; inside a box already titled ADSR or AHDSR it carries no second title. Double-click still resets every slider and lane. Check `ZTrackerModelWindow.CheckCompactAdsr()`.
- ZTracker reopens as it was closed: the same song, instrument, view (Pattern, Mixer, Automation, Instrument, Song), sequence slot, cursor, track, octave, step, Edit and Follow, instrument and mixer tabs, selections, and each page's folds and scroll positions. Script reloads and editor restarts already kept an open window's state; closing and opening the window again now does too, through a small per-user file (UserSettings/ZTracker/ViewState.json, never committed, never inside a song, so viewing never dirties an asset). A song or instrument that no longer exists, a song that has shrunk, or a damaged file fall back quietly. Fixed on the way: after a script reload the pattern grid came back scrolled to the top (its own rebuild ran after the saved position was put back); scroll positions are now retried until the page is laid out. The empty window (no song) uses the same compact skin as the editor. Check `ZTrackerModelWindow.CheckViewRestore()`.
- Songs and instruments (drum kits included) are LauAssets, browsed, picked, created, duplicated, renamed, tagged and opened the same way as every other Laubrary tool's assets. The ZTracker window uses the shared asset window base: its toolbar is the shared one (song field, New with a name and folder, Browse, Duplicate, Rename, Delete) with Save, Undo, Redo and MIDI on the same row; with no song open it shows the song library, each song drawn as its first pattern. Instruments are added with Add… (the shared asset browser: search, sort, tags and pictures, or Save as new) and have Rename, Duplicate (the copy joins the song with its own identity), Select in Project and Tags on their header row; renaming a song or an instrument renames its file and the name shown in ZTracker together. Song tags sit beside the song's name. A drum kit's synth source is the shared asset chip, offering only synths. Double-clicking a song or an instrument in the Project window opens it in ZTracker; any LauAsset field that references one gets Edit and New. Every instrument shows a picture in browsers: a sampler's waveform, a synth's amplitude envelope, a drum kit's pads. Existing songs and instruments open unchanged, and an open ZTracker window keeps its song across the change. Check `ZTrackerModelWindow.CheckLauAssets()`.
- Command ids for effects inside an instrument's own chain: right-click a setting of an instrument chain effect (Instrument › Effects) and choose Command id…, or pick it in Song › Commands › Add…. Every track plays its own copy of the instrument's chain, so the command changes only the copy of the track it is typed on (and an envelope column drives only its own track's copy); typed on a group, send or master track it is reported and does nothing. A preset's override value offers the same command as the Base parameter (one id for Base and presets); the sampler's Volume and Pan keep theirs. The Alt+B bind menus of FX and envelope columns show each command's id in its colours; the shared ZUI menu gained `ChipItem` (a coloured id chip before the label, matched by search together with the label). The suggestion list's scope column is wide enough for "Instrument effect". Checks `TrackerInstrumentEffectCommandCheck.Execute()` and `ZTrackerModelWindow.CheckInstrumentEffectCommands()`.
- Envelope columns: each track can have up to eight lines drawn down the pattern that drive one command smoothly (a song command, or the built-in 0L track pre gain / 0P track pre pan): left edge 00, right edge FF. Add them with + on the track header or the Env count, bind with the menu that opens (Alt+B or right-click the title). In Edit mode click adds a point, dragging a point moves it, dragging across rows draws, Alt snaps to sixteenths, right-click deletes a point or makes the segment straight or held; Left/Right nudge, hex sets, Delete removes. The command follows the line between its first and last point (gliding onto it without a click where it begins), a typed command for it takes its own row, and seek/loop/Stop behave as for typed commands. Older songs open and play bit-identically. Ctrl+Left/Right move between columns everywhere. Design: `Documentation~/COMMAND_MODEL_DESIGN.md` section 10; checks `TrackerEnvelopeCheck.Execute()` and `ZTrackerModelWindow.CheckEnvelopeColumns()`.
- Copy, cut, paste, Paste Insert and clear work on every column type, alone or in a mixed block. - Checks: every simulated mouse press in the window checks is now released. - Command suggestions are context-aware: typing in an FX column lists only the commands that belong on that row (the instrument playing there, the track's effects and mixer, the song's own, then the built-ins), each with its id chip, friendly name and scope. - Colour-coded commands: built-ins are coloured text by kind (pitch, volume, pan, sample, timing, track/devices, song); song commands are dark text on their own colour, given automatically (different from the song's other commands, kept through renames) and changeable in Song › Commands (colour field; double-click the chip for a new automatic colour); an id that names nothing is white on red. - Bound FX columns: right-click an FX column's title (or press Alt+B with the cursor in it), type a command id and press Enter to bind the column to that command (built-in or a song command; a song command is remembered by its permanent key, so renaming its id keeps the binding). A bound column's title shows the id, typing in it takes only the hex value, and another command found in it is kept, still plays and is shown in amber. Binding, bar view and unbinding never move or change a stored command. The searchable ZUI menu now runs its best match on Enter.
- Song commands (dynamic parameters): any mixer value, track effect setting, instrument parameter or macro, and the song tempo can be given a two-character command id and a short name together (right-click the slider, or Song › Commands › Add…).
