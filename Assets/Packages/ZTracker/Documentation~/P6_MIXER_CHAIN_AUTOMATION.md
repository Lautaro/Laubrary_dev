# P6 mixer, shared chains and automation authoring

This phase adds the Mixer and Automation workspaces to the canonical model editor. It is an implementation handoff to the instrument phase and independent reviewer; final integrated Handover Walk and runtime verification belong to the root task.

## Shared chain authoring API

`Laubrary.Audio.Editor.AudioChainEditor(Func<AudioEffectChainData> getter, Action<string,Action,bool> editCallback, Action<string> nodeRemoved = null)` lives in `Assets/Packages/Laubrary/Editor/AudioCore/AudioChainEditor.cs`, assembly `com.Lautaro-Arino.Laubrary.AudioCore.Editor`. Record complete Undo before invoking the supplied action; persist and refresh prepared data afterward. The bool identifies topology changes. The widget rebuilds its own controls for topology; scalar callbacks keep the gesture's control attached. The optional removal callback runs inside the same transaction and receives the removed node's stable UID. Instrument consumers can use an instrument-owned getter and their instrument transaction callback directly.

The existing Zounds editor uses the extracted `NodeAuthoring`, `Scalar` and `DisplayValue` methods, retaining its skins, layout, preset callbacks, continuous Undo, live overlays and analyser. The portable widget uses the same descriptor-based node/parameter rendering and includes effect/modifier creation, enabled switches, binding target pickers, operations, depth, curves, steps, deletion and drag reordering. Shared scalar rendering supplies logarithmic normalization, integer snapping and descriptor defaults; no DSP kernels were changed. The shared editor assembly references Zounds runtime because its effect descriptors remain there; it does not reference the Zounds editor.

## Mixer and reference rules

All five track roles are creatable. Master creation refuses a duplicate, and Master removal/clone is unavailable. Track add/clone/remove updates every pattern's sparse track records. Cloning remaps the copied effect, source-device and automation identities, while shared instrument assets remain shared. Track deletion clears dangling output/send/sequence-mute references and flags cross-track lanes. Group/output/send pickers filter destinations by model graph validation; unsupported imported automation is preserved without authoring mutations during UI build.

Effect reordering remaps index-based modifier bindings and follows the original tapped effect for send positions, including a tap originally at the chain end. Source-device ordinals belong to the declaration addressed by literal commands and deliberately stay stable when effects move. Effect removal flags affected lanes and retains its source declaration as unsupported. Full model Undo restores removed records, references and payloads.

Pre/post gain and pan, stereo width, output/trigger mute, solo, track beat events and routing appear in Levels; Devices hosts the shared chain widget; Sources hosts command-profile metadata. Sequence controls expose per-occurrence track mutes. Song controls expose voice capacity, unsigned random seed and song beat events. Workspace scroll offsets survive rebuilds.

## Automation and source metadata

Automation has a searchable destination picker for supported mixer parameters, continuous effect parameters and all eight instrument macros. Device ordinals and external IDs are picked from declarations, never typed as references. New native effect lanes explicitly declare source metadata with `id = node.uid`, physical units from `TrackerEffectMetadata.ParameterUnits`, and physical ranges. Memory-sizing/discrete domains that P5 cannot prove equivalent are excluded from native automatic declarations and lane choices. Source metadata remains editable: source role, instrument, name, ordinal, enabled, parameter labels, defaults, range, quantum and native equivalence. External source declarations are mirrored into `externalSources` so the P4 external route compiler uses the same identities and parameter slots; changing a link/name/ordinal updates the mirror.

Automation points support Step/Linear interpolation, normalized values, explicit fractional-line fields quantized to 1/256, point deletion, and canvas double-click/drag authoring. Imported unsupported lane payload is shown as flagged and retained. Validation accepts explicit source-device identities in addition to native node identities; source-instrument links and declared external parameter identity are checked before those lanes can prepare. Source picks exclude missing or ambiguous linked instruments and missing external mappings.

Live prepared identity normalization allows compatible chain modifier parameters, same-count step/curve edits, binding scalar changes, source defaults and names. Modifier enabled/topology, voice count, route changes and other incompatible changes continue to report that explicit Stop/Play is needed; the authoring UI never stops/restarts an active graph to hide this. Native chain parameter changes also update the explicit source default so the source declaration cannot restore an obsolete parameter value.
