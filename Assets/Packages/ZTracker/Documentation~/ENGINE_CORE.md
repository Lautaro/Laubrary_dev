# P3/P4/P5 tracker engine core

This is the opt-in schema-1 engine in `Laubrary.ZTracker.Engine`. It does not replace the existing DLL player or compatibility bridge; that switch belongs to P7. Preparation reads the canonical song/instrument models and their typed retained parameter extension, never the old compatibility views or archives. It makes no authored asset changes. P4 adds subtractive/unison, four-operator FM, paired PCM and audio-thread macros. P5 adds the proposed command profile, prepared future-note parameter sets and automation described below. Legacy authoring playback continues to use its DLL and `PumpMacros`; the new renderer never depends on that pump.

## P5 command and automation execution

The prepared owner allocates command operations, per-source memory banks, resolved row descriptors, source devices/parameters, automation points, visit counters and bounded routing scratch arrays. Audio code reads POD/native storage only. Compiler and realtime partials separate source decoding/preparation from scheduling. Commands reuse the P4 typed parameter/macro evaluator rather than introducing another parameter implementation. The witness is `P5-command-automation-native-core-v1`.

At a row boundary the engine evaluates lanes, resolves supported setters/enable winners and contributor stops, then launches or captures events and applies active tick-zero commands. Exact unquantized deadline ordering is retained even when distinct deadlines quantize to one frame. A local action accompanying an ordinary new note binds only after a successful probability/mapping/launch; a rejected or unresolved new note does not reset or modify its predecessor. OFF and instrument-only events keep captured foreground handles. Detached tails are excluded from later column commands. Fresh notes start at command gain1/pan0 before same-row setters; matching-instrument glide retains the held patch and zone selection.

Rendering mixes each deadline slice with the controls valid for that slice, so an automation/device/mixer/routing change cannot retroactively affect samples rendered earlier in the caller block. AudioCore's existing control grid remains independent from tracker tick boundaries. Combined pitch exponents are bounded before exponentiation/fetch; finite increments are clamped to [2^-20,2^20], and loop normalization has bounded work. Supported envelope clocks advance independently; E cannot reactivate a finished clock or silently reinterpret Stepper.

Step/Linear lanes evaluate at ticks and explicit point deadlines, with timing lanes restricted to integer rows. Same-boundary direct setters override lane values; later ticks resume the lane. Disabled control sources retain latent values and last emitted destination values, and enabling emits the current latent value. Audio bypass clears only the addressed node's history and restores its prepared kernel metadata so enabling can rebuild fresh history. Unknown defaults, units, physical mappings, curves, memory-sizing parameters and undeclared discrete enum domains are preserved and diagnosed.

At a coincident automation and delayed note/OFF boundary, automation writes happen before the event captures launch/release state, then the newly launched foreground receives that tick's commands. Distinct exact deadlines sharing a quantized frame still run in their exact chronological order. The scheduler retains each automation point's original musical coordinate alongside its frame deadline; it never reconstructs the coordinate by reversing cumulative clock arithmetic. This avoids evaluating just below a Step point and scheduling that same point repeatedly. Pending/rejected/unmapped note-local commands stay with their own event; broader track/Master descriptors continue on the predecessor until a successful launch detaches it. Ambiguous instrument or parameter-set identities refuse stable-ID bindings rather than selecting the first slot; explicit instrument-index notes remain independent of that refusal.

Seek cuts voices/history, then silently replays supported scalar/device/memory events in chronological tick/point order along actual bounded flow, including held-row end values and per-source occurrence counters. It flags discarded voice-dependent state and unreachable targets. Clock guards apply before integer conversion during live rows, holds and replay. X00 traverses current output/send edges, clears exclusively owned history and flags inseparable downstream history; contributor expansion can also flag send contributors feeding other buses. Internal J changes are refused if the proposed edge creates a cycle, and processing order includes sends.

## Preparation and ownership

`TrackerPreparedSong.Prepare(ZTrackerSong, rate, maxFrames)` requires an explicitly migrated schema-1 asset. The `SongData` overload is useful for an independent golden adapter without creating song assets. Instrument slots still reference schema-1 instrument assets; transient, unsaved instances are sufficient. Preparation copies mono/stereo, Decompress On Load PCM on the main thread, deduplicated by clip identity within each prepared song. Every voice borrows that immutable pool. Settings and per-voice state remain separate when multiple samples share a clip.

Preparation validates model references, capacities, finite data, PCM, loop bounds, visible note-column layout and the routing DAG before publication. Failure disposes partial native allocations. Track outputs and insertion sends both participate in cycle detection. Runtime tables, voices, columns, modulation state, buffers, chain layouts and state arenas are flat unmanaged storage allocated before rendering. Each chain processor has one disposer; copied structs alias its arrays and are not additional owners.

An offline engine or SAP host consumes one fresh prepared owner. `Published` means ownership was claimed, including a configured host before its first callback. Direct disposal of a claimed owner throws. Do not edit or dispose its state arrays, and do not hand the same owner to another renderer. Prepare a fresh owner to make a change. The PCM copy is released together with the owner's quiet render ticket, never per voice.

## Offline API

```csharp
using var engine = new TrackerOffline(TrackerPreparedSong.Prepare(songData, 48000));
engine.SendCommand(TrackerCommand.Play(loop: false));
engine.Render(leftNativeArray, rightNativeArray, frames, blockFrames: 1024);
while (engine.ReadEvent(out TrackerEvent e)) { /* compare or consume events */ }
bool burstActuallyRan = engine.Compiled;
long lostEvents = engine.EventOverflow;
```

Output arrays are planar floats supplied by the caller. Subsequent renders continue every voice, modulation, chain timeline/RNG and clock scalar. The job operates on a persistent native pointer to the same realtime struct used by SAP; it does not lose scalar updates in a copied job field. `Compiled` is an actual BurstDiscard witness, not an attribute inspection. `RenderManaged` exists for controlled baseline experiments. It deliberately increments the managed audio guard and must not be used to claim native proof. `Snapshot` is a borrowed synchronous inspection view for offline checks, not an ownership transfer. Offline swaps are refused; create a new owned engine. `Dispose` is idempotent, and subsequent API calls throw instead of touching a freed pointer.

## SAP host and lifetime

On a GameObject with an AudioSource, add `TrackerSapGenerator`, call `Configure(freshPrepared, playSong: true)`, then use the AudioSource's SAP generator playback API. The host declares stereo and the prepared sample rate. There is one generator for the complete song. Main-thread commands travel through the SAP control-to-realtime pipe. They take effect when SAP delivers its between-block update, without a prefetched audio buffer or inserted output latency. Preparation and pipe submission may allocate on the main thread; rendering does not.

```csharp
var host = gameObject.AddComponent<TrackerSapGenerator>();
host.Configure(TrackerPreparedSong.Prepare(songData, AudioSettings.outputSampleRate));
var source = gameObject.GetComponent<AudioSource>();
source.generator = host;
source.Play();
```

`SwapPrepared(next, playSong)` queues an already validated, independently allocated same-rate owner. The realtime update finishes the previous owner's ticket before replacing state. The new state starts a fresh row clock at the preserved absolute playing counter and preserves the renderer's monotonic voice-generation counter. The event ring has a separate lifetime across swaps. Each retired owner must have a terminal ticket and a stable even observation before reclamation. Event consumers must keep the appropriate payload table when retaining events from an earlier prepared owner; a payload index is local to that owner.

`StopAndConfirm(timeout)` first refuses commands/publication and stops the carrying AudioSource, then observes stable even tickets for a full settling interval, flushes pending control work, destroys the graph instance, flushes its disposal, and observes a second quiet interval. The external ticket outlives both rendering and control disposal. A timeout retains the complete ownership bundle, including the native graph handle. Destruction never frees arrays based on an odd or moving ticket. The registry destroys the remembered handle after quiet, flushes disposal, then waits quiet again before freeing the retained arrays and ring. Accepted replacement owners that never reached realtime need no terminal mark once the whole graph is detached. Normal between-block retirement still requires a terminal mark. Quit refuses new rendering, silences hosts, and waits at least two actual frame updates and 0.3 seconds before teardown and the final quit. Independent standalone callback, swap, timeout-retention, destruction and quit proof is recorded in [P3 verification](P3_VERIFICATION.md).

`RenderedFrames` and `RenderedBlocks` accumulate actual completed renders across prepared owners; swap/control-disposal ticket operations do not count as renders. `RenderCompiled` is a BurstDiscard marker written by the actual SAP render entry point, including retired owners that rendered at least one frame. An unused replacement cannot taint that witness. These counters are observational diagnostics, not a synchronization substitute.

## Clock, commands and events

The clock follows COMMANDS.md P-CLOCK: binary64 Kahan cumulative row durations and its eight-ULP near-integer Q snap, otherwise floor. Row entry is applied before its first sample. Tick deadlines are computed from the row origin; delay `d` uses `Q(E + (d/256)*D)`, independently from audio partitions. Distinct fractional deadlines sharing one frame preserve their unquantized order. The next row owns the row-end boundary. There is no tick rounding of delayed notes.

The original P3 scope supports note/OFF, literal instrument selection, volume0..128, pan0..128 and delay0..255. Instrument/volume/pan/foreground/delayed-cell state is per column. A note/OFF/instrument-only event carries its setters to the delayed deadline. Without a note or instrument-only selection, numeric volume/pan apply at row entry and ignore delay. Numeric zero remains distinct from empty. P5 extends this scope with the command, automation and prepared parameter-set behavior above; unsupported destinations and selectors remain diagnosed without guessed effects.

Global commands are evaluated once per row in canonical track/column order. ZT supports decimal32..255 and zero hard stop; decimal20..31 gives `BPM_RANGE_DISPUTE`; other invalid values are preserved and ignored. ZL supports1..255 and zero hard stop. ZK supports1..16; zero is invalid. ZB selects the next sequence slot at the raw byte row after completing the current row; a shorter destination clamps to its last row with a bounded diagnostic, and an explicit final-slot break wraps to the first slot. ZD repeats duration without replaying row commands or note/probability launches and freezes automation at the original row-end value. Fresh Play cuts voices, clears histories and restores authored scalar/source defaults, memory, occurrence counters and successful column selection. Stop cuts voices/history immediately. Idle stopped audition advances voice/FX time while freezing the playing counter; Pause freezes both, and Resume preserves state. Seek reconstructs supported scalar/device/memory/automation state along actual bounded flow, discards voice-dependent state with a warning and refuses unreachable targets.

At48000Hz/137.5BPM/LPB4/TPL6, v1 row frames are `0,5236,10472,15709,20945,26181`; the native P0 floor-countdown engine's equivalent trace is `0,5237,10473,15710,20946,26182`. This one-frame fractional difference is intentional contract characterization, not native event parity. Integral120/4 sampler fixtures remain directly comparable. Initial BPM32..999, LPB1..256 and TPL1..16 are accepted subject to at least one output frame per row. Subframe ticks are allowed and coincident deadlines retain exact ordering. Nonfinite timing, invalid row duration and the2^40 frame limit stop before unsafe integer conversion during live rows, holds and seek.

`TrackerEvent` contains kind, cumulative playing `samplePosition`, sequence/pattern/row/tick, track/column/note/instrument and payload. Unused identifiers are -1. Kinds are Row, Tick, NoteOn, NoteOff, Beat, Authored, VoiceStolen, PreparedSwap, Stopped, Diagnostic and Started. Accepted Play emits Started before its initial row. Audition events use the same playing-counter domain, which stays frozen while stopped. Authored payload is an index into `eventPayloads`; no string allocation happens on audio. Diagnostic payload codes are SeekUnreachable=1, PitchLimit=2, InvalidPitch=3 and BreakClamped=4. Events use a bounded raw-memory SPSC ring: one audio producer, one main-thread consumer, release/acquire cursor publication, drop newest on overflow, cumulative overflow count. Host capacity is65536; offline capacity is configurable2..1048576. Never poll the realtime NativeArrays concurrently; main-thread event/ticket observation uses independent native pointers.

Audition accepts either integer velocity or exact normalized float gain. The float overload preserves gain and separately rounds its 0..127 zone-selection velocity. `ReleaseVoice(slot, generation)` releases only an active voice whose cohort equals the captured generation; a stale handle cannot release a replacement, including after a prepared swap. Handles belong to their renderer instance and must not be sent to a different host/offline engine. Obtain the cohort through synchronous offline inspection or an application-owned launch protocol, never by concurrently reading live voice arrays. Column AuditionOff remains a cohort release.

## Sampler and mixer behavior

Key/velocity zones have inclusive boundaries; overlapping zones launch simultaneous components. Key tracking off preserves fixed pitch. Each component has an independent linear AHDSR including hold, frozen-level linear release, cursor/direction, modulation state and filter history. OFF releases only the current column's cohort and ignores one-shot components. Each old sample's Cut/NoteOff/Continue NNA applies only when a mapped successor launches, keeping mixed-layer NNA and detached tails independent. Sampler-global NNA is retained authoring data; per-sample NNA is authoritative for playback. Nonzero mute groups choke matching components and tails on the same instrument and Sequencer track, not other tracks. The fixed pool steals an idle slot first, then the quietest released envelope, then the quietest active amplitude; every reused field is reset. P4 steals the selected old cohort together and does not steal components already launched into the new cohort. A note requiring more simultaneous components than the whole pool is refused before NNA or replacement; no partial cohort or unbounded overflow voices are created.

Forward, Backward and PingPong loops use exclusive frame ends and bounded remainder/reflection for large increments. Backward starts at end-1. Release-exits-loop resumes forward playback from the current cursor through the clip. Linear and Catmull-Rom cubic interpolation are implemented. New samplers wrap/reflect interpolation neighbors within their active loop; migrated native samplers retain clip-clamped neighbors for equivalence. Pitch is bounded before exponentiation to2^-20..2^20 source frames per output frame; clipping/invalid input emits bounded diagnostics.

Ordered AHDSR, multipoint sustain/loop, four-shape LFO, velocity, key tracking and fader devices target volume/pan/pitch/cutoff/resonance/drive with Add/Multiply/Replace. Time fields and curve-point positions are seconds; rate is cycles/second, phase is cycles, pitch output is semitones, cutoff is Hz, other targets use their numeric normalized/linear domains. Unit labels accept seconds/normalized/semitones/Hz and do not convert authored numbers. LFO state and multipoint cursors are per component. The first enabled volume AHDSR uses the incremental envelope for lifetime and supplies that value at its authored device position; every operation stays ordered, so a later Replace can replace the envelope's volume and Add can add to it. Additional envelopes remain ordered device stages. PCM and multipoint PingPong preserve the forward intro before a nonzero loop start; reflection happens only on crossing the bound in the current direction. Filter types0/1/2/3 are Off/LowPass/HighPass/BandPass, with per-component coefficients/history and cutoff/resonance modulation. Drive uses tanh on the voice stage.

Modern mono uses cosine/sine equal-power pan and stereo uses center-unity balance; authored sample/instrument/note/modulation pan sums then clamps. Explicitly migrated instruments retain native square-root pan and native authored/note pan combination, selected only by typed v1 provenance equal to `native-v0` or starting with `native-v0;`, never by arbitrary metadata or a compatibility view. Exclusively migrated songs receive the native voice-slice1/sqrt(active components) normalization ramp and master soft knee above0.9, with `LEGACY_MIX_NORMALIZATION_AND_SOFT_KNEE`. A unison bundle counts as one active component for this ramp and has its own 1/sqrt(member count) member gain. Newly authored or mixed songs add components linearly and have no hidden automatic normalization/knee. Track/group/send/master center pan is unity at every stage.

Tracked retained native samples also preserve the measured Windows MSVC `/O2 /fp:fast` pitch profile: float exponent subtraction plus fine-tune, `powf`, and multiplication by float `440*(1/440)` (`0x3f7fffff`). The original P0 held-pitch witness is `0.9999999403953552` at base pitch; a standalone compilation of the original arithmetic emits that exact constant. Native kits constant-fold their base/base pitch to 1 and do not use this sample profile. Modern v1 pitch retains the mathematical double-power path. This is a deliberate retained compatibility calculation, not an unexplained cursor epsilon or a claim about other native compiler targets.

Instrument FX has an independent chain history per `(Sequencer track, instrument, FX chain)` partition; two tracks using one instrument never merge before their track chains/faders. Track outputs and sends process in DAG order: instrument FX, track prefader width/volume/pan, device segments, insertion taps, postfader and output routing. Send taps can precede, split or follow a chain and select pre/postfader gain/pan. Live postfader gain/pan ramp over64samples; every postfader tap uses the exact same per-frame ramp. Trigger mute blocks only new notes. Output mute suppresses every outgoing tap while allowing new voices to launch; their cursors and effect histories continue. Solo exclusion and sequence mute suppress taps and gate new launches while existing voices and histories continue. Sequence changes within a caller block use per-frame mute masks.

All16 AudioCore effects and5 modifiers use the shared P1 kernels, with a portable preparation compiler and the existing numeric parameter schema. Chains run on the caller block, independent of tracker tick cuts; AudioCore owns its64sample control grid. Segments at insertion taps duplicate modifier state with the same seed/timeline. Arbitrary caller partitions can retain P1 coefficient/presence sensitivity; no universal bit-identical effect partition claim is made. A constant-PCM phaser check measured333vs1024 caller blocks at max error2.98023224e-8, while changing tracker TPL1vs6 at fixed1024caller blocks stayed within1e-7. Continuous bus chain context uses sourcePeak1 and a30second normalized envelope domain with elapsed sample time; it does not pretend a summed bus is an individual PCM source. Source-stage bindings are refused because a bus has no source pitch/speed stage. Live ZPOC/control mapping is outside P3.

Typed retained filter scalars compile to each voice, with a diagnostic and native normalized cutoff times Nyquist. Retained vibrato compiles cents to semitones plus fade and deterministic cohort-derived rate variation; this seeded variation is not a native rand parity claim. Arpeggio compiles a looping step curve. Retained sends resolve to the first explicitly authored Send track containing the matching Delay/Reverb device. Missing destinations refuse preparation rather than creating hidden buses. Sample-B-related retained curves remain diagnosed P4 work. Retained effects never mutate the instrument asset.

## P4 synthesis and provenance

`TrackerToneCompiler` produces flat tone/envelope/route tables. `TrackerToneRealtime` shares the renderer with sampler voices; it does not call the legacy DLL. Subtractive voices combine two oscillators using Mix/Ring/Sync/PM, native-compatible wave shapes, smooth blend/pulse-width/B-ratio/PM/unison-detune targets, all five authored envelope targets, ADSR, filter, vibrato, variable-speed arpeggio and optional exponential instrument glide. FM uses four sine operators, individual ADSRs, ratio or fixed-Hz pitch and algorithms 0–5: serial chain; two pairs; two modulators into a chain; pair plus two carriers; chain plus carrier; four parallel carriers. Saved choices 6/7 compile to the existing parallel algorithm 5 with a diagnostic. They do not create new algorithms. FM operator waveform choices other than sine are diagnosed, preserving the legacy engine's sine-only contract.

`InstrumentParameters.enumDomain` and `envelopeEnumDomain` are independent, defaulting to `SavedAuthoring`. Saved waves 0/1/2/3/4 mean sine/triangle/saw/square/white; compiled native numbers are 0/4/2/1/5. Direct native waves 0–6 remain direct, including reverse saw and pink. Saved loop numbers 1/2 mean forward/ping-pong; direct native numbers 0/1 mean forward/ping-pong. Explicit native loop 2 is invalid; the correction adapter declares that fixture's loop domain as saved authoring while preserving its integer 2. Saved integer fields and envelope points are never overwritten by preparation. `native-v0` mix/pitch provenance remains distinct from these enum domains. Note initialization explicitly stores the rounded float32 frequency product before double division, preserving both managed/offline initialization and native/AOT initialization without cursor offsets or relaxed tolerance.

PCM B has its own pitch, frame cursor, direction, loop bounds and release-exit flag. Mix crossfades A/B; Ring multiplies B by A before blending; Sync resets B after A wraps; PM reads B at its cursor plus A-left times depth (frames), wrapped to B's PCM length. Both B stereo channels use that shared phase offset. A and B advance independently; B ends silently if its unlooped cursor ends, while A retains voice lifetime. B loop release resumes forward from B's current frame cursor, including backward and ping-pong loops, independently of A's release-exit policy. B zone defaults are authoritative unless explicitly routed. Whole-note unison/layer cohorts release together and are stolen together; reused slots reset oscillator/FM/filter/envelope/cursor/noise state. Stale release handles cannot address a replacement cohort.

White noise uses seeded per-member/per-oscillator xorshift state. Pink uses independently seeded white input and a three-pole spectral filter. No process-global random state or audio-thread allocation is involved. Seed identity includes cohort generation, preventing correlated unison members. A freshly prepared identical control sequence repeats exactly; changing partition sizes does not change the noise stream.

## P4 parameter and macro operations for P5

`TrackerCommand.SetMacro(instrument, index, normalized)` changes one of eight macro values. `TargetMacro(instrument, index, normalized, stepPerTick)` sets a target and positive normalized slew step. `MacroAdvance` (`a=instrument`, or -1 for all) exposes the same tick advance P5 can use; normal sequencer ticks already advance it. A slide advances only while that instrument has an active, unreleased foreground cohort. It moves by at most the step, clamps to the target and stops there. Released/background-only/inactive instruments do not advance. This is instrument-owned P4 state; G/H/I command decode and channel ownership belong to P5. Play/Seek restore authored macro defaults and clear direct parameter overrides; commands sent afterwards establish new live values.

Both `TrackerOffline` and `TrackerSapGenerator` expose `SetMacro`, `TargetMacro`, `ObserveMacro` and `SetExternal`. Offline commands are synchronous. SAP setters publish POD operations through its preexisting pipe, applied by the compiled audio callback; observe reads one atomic float, not a coherent bank snapshot. Prepared state owns all eight values/targets/steps and compiled route arrays; none resize on the audio thread. `TrackerCommand.SetParameter` sets one physical typed parameter. Every render slice resolves authored defaults/direct overrides first, then macro index 0–7 and each mapping-list order (last valid write wins), then per-voice envelopes/modulation. Macro inputs alone are normalized. Explicit mapping curves are normalized piecewise-linear points; empty points mean Linear. Reversed endpoints and equal endpoints are intentional. A retained scalar `curve` other than 1 without explicit points is diagnosed, never guessed as a transform.

Preparation resolves canonical parameter spellings (`TrackerParameters.Resolve`) to `TrackerParameter`. Units must match `TrackerParameters.Units`; the explicit `legacy parameter units` marker preserves prior common sampler/synth mapping conventions and converts legacy normalized cutoff endpoints to Hz. Concrete PM-depth units are checked against the destination family: `cycles` for subtractive synth and `frames` for paired PCM. The registry's composite `phase cycles or sample frames` label resolves through that typed destination; an explicit wrong-family unit is refused without dropping neighboring valid routes. Typed Sample targets support instrument sampler globals with index -1; typed Synth targets require Synth instruments. Documented legacy common Synth links may target Sampler globals. FM operator/feedback routes require FM, unison/pulse/ratio require subtractive synth, and paired-sample blend/PM require an authored B source. Unsupported sample/member indices are diagnosed rather than ignored. All this checking occurs before publication; audio code resolves neither strings nor model objects.

`TrackData.externalSources` declares a source device identity, plugin identity, linked instrument identity and ordered parameter-number strings. The slot indexes that list, yielding the exact `ExternalParameterMapping.externalId` on the linked Synth instrument, then a typed parameter or `InstrumentMacro` index 0–7. Display names never resolve ownership, and a slot ordinal is never substituted for external ID. Duplicate instrument identities cannot resolve explicit links. External target instrument/track/device ownership must agree with the source; a foreign route is skipped independently. `TrackerPreparedSong.TryExternalCommand` resolves the immutable address on the main thread and emits a numeric route command. `SetExternal(trackId, deviceId, slot, normalized)` uses it; unresolved addresses return false.

`TrackerCommand.AmplitudeModifier(track, column, depth, Hz)` applies to the current foreground cohort, resets its phase, then advances the phase once per output sample and multiplies amplitude by `max(0, 1 + sin(phase) * depth)`. Depth is 0–16, frequency 0–1000Hz, and zero disables modulation. It is shared by sampler/subtractive/FM. P4's command07 correction adapter demonstrates this operation after initializing the first sample; it does not decode any raw legacy command or replace P5's separate proposed tremolo policy.
