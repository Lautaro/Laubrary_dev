# ZTracker P5 command profile and P2 migration contract

## Instrument-editor rework: pattern arpeggio

The current renderer supports `0Axy` for sampler, subtractive synth and FM foreground notes. The pattern editor has separate identifier and hexadecimal argument fields: enter `0A` and `37` for the shorthand `A37`. It cycles offsets 0, 3 and 7 semitones on successive ticks, starting from the base note at tick zero. Row absence clears the row-scoped arpeggio; the existing zero-argument command-memory policy remains unchanged. No speed extension is introduced: TPL and tempo determine tick duration. Instrument-owned arpeggio settings are retained in migration/archive data and are ignored by playback. They cannot enable arpeggio on a row that lacks the command.

**P7 status:** the command policies below remain normative for the current Burst/SAP renderer. The P4/P5 phase notes and original specification evidence boundary are retained historically; their statements that the DLL authoring backend remains active are superseded by P7 retirement. See [P7 verification](P7_VERIFICATION.md) for current public playback, complete reference accounting and limits. Policy conformance does not certify Renoise playback equivalence.

P5 implementation coverage (2026-10-06): the opt-in native engine executes sample A/U/D/G/V/I/O/T/C/S/B/E/N, M/Q/Y/R, supported volume/pan commands and numerics, fractional delay, L/P/X00/internal J, explicit base36 device/parameter addresses and bypass, ZT/ZL/ZK/ZG00/ZB/ZD, and Step/Linear automation through declared equivalents. It compiles prepared parameter sets bound to future notes without cloning canonical slots. The exact grouped checks, native comparison scope and player evidence are recorded in [P5_VERIFICATION.md](P5_VERIFICATION.md). These are ZTracker policy conformance claims, not Renoise playback equivalence.

Preserve-and-flag remains the default for unsafe legacy ratio/glide/gain/pan/tremolo/macro/preset conversions, MIDI/phrase/hardware/width/groove-on contexts, unknown source profiles/ordinals/parameters/units, undeclared DSP enum domains, memory-sizing targets and unsupported curves/scaling. Direct Sample/Synth/Modulation automation lanes without a declared source equivalence are retained with target diagnostics; supported typed external routes reuse the P4 evaluator. No conditional legacy mapping was selected implicitly. The old DLL authoring backend remains active until P7.

Implementation migration boundary: a command retaining unsafe legacy provenance cannot execute merely by changing its profile to `renoise-p5-v1` or setting `migrationDecision` text. Those rows remain preserved/flagged; P5 does not validate or activate conditional legacy proof packages. The only executed retained-byte conversions are the previously approved P2 timing subset, with an exact match required: F1..16→ZK same amount and F32..255→ZT same amount, plus the retained timing-event-difference diagnostic. F00→ZK01 remains a model migration candidate and is preserved by this executor; F17..31 and forged identifier/amount/profile/decision combinations execute nothing. Explicitly authored modern commands without retained legacy provenance follow the normative tables below.

P4 implementation seam (2026-10-06): the opt-in engine exposes typed macro set/target/tick-advance/observe/external operations and a foreground-cohort amplitude modifier. It does not decode legacy G/H/I, native command07, presets or extended identifiers, and does not assign P5 channel ownership. The command07 golden correction adapter proves the standalone amplitude operation's specified multiplier without claiming raw migration. Legacy DLL authoring playback and `PumpMacros` remain active until P7. See [engine contracts](ENGINE_CORE.md) for exact units, routing identity, order and audio-thread behavior; the command policies below remain P5's contract.

Specification revision 1, task T-0017, 2026-10-06. This document specifies future implementation; it does not describe commands already implemented or certify Renoise playback parity. It follows `ARCHITECTURE_RENOISE_PHASE.md`: one sample-counted Burst generator, independent note columns, Sampler and Synth instruments, instrument-owned eight macros, and track/group/send/master chains. Import/export remains a follow-on; P2 must retain enough source identity and provenance for that follow-on.

**Evidence boundary:** command names, documented units, serialization fields and API ranges below are sourced. Every scheduling, conversion, conflict, random, reset or migration rule marked **P** is **proposed ZTracker policy, unverified against Renoise**. P rules are nevertheless normative for implementing this revision and writing fixtures. A future observation may justify a versioned profile change; it must not silently change existing assets. No Renoise songs were played, no scratch songs were created, and no Unity/editor/build/test operation was performed for this specification.

## 1. Status, inventory and terminology

| Status | Required behavior |
|---|---|
| IMPLEMENT | P5 must execute the specified supported behavior. A proposed policy is an implementation commitment, not a parity claim. |
| PRESERVE-AND-FLAG | Retain original command, argument presence, source address and unsupported data; compile a diagnostic and execute no guessed substitute. Supported independent parts may execute only where a row explicitly permits partial support. |
| N/A | Documented domain excludes this component. Preserve the source token for round-trip; do nothing to that component. Emit a domain diagnostic when the whole target is inapplicable, rather than silently giving it a synth meaning. |

The completeness baseline is the official [Effect Commands inventory](https://tutorials.renoise.com/wiki/Effect_Commands): 13 sample identifiers `0A 0U 0D 0G 0V 0I 0O 0T 0C 0S 0B 0E 0N`; five instrument identifiers `0M 0Z 0Q 0Y 0R`; six device identifiers `0L 0P 0W 0X 0J` plus addressed parameter/bypass forms; six global identifiers `ZT ZL ZK ZG ZB ZD`; numeric volume and pan; volume `Ix Ox`; pan `Jx Kx`; shared column forms `Ux Dx Gx Cx Bx Qx Yx Rx`; numeric delay; four special MIDI forms `M0 M1 M2 M3`. “Six device identifiers” counts parameter/bypass addressing as the sixth family, not an invented built-in identifier. Tables below cover every family and phrase variation; no sequence-position jump is documented.

Correct the architecture's examples when implementing: **`0O` fades volume out; `0J` routes output; `Jx/Kx` slide pan; `OFF` is the note-off token.** `0Cxy` changes gain without releasing or stopping the voice; `Cx` hard-cuts without note-off actions. There is no `ZJ` command in this profile.

“Local FX” means the sample-fx sub-column of a note column. “Master FX” in the manual means a track's effect columns; it does not mean only the song's Master track. A **bundle** is every voice component launched by one note-column note event: all overlapping sampler zones and their Sample-B extension components, or all oscillators/unison/FM components of one synth note. A component retains its instrument/sample identity, zone mapping, tuning, modulation state and FX-chain route. A **foreground bundle** is the most recently launched surviving bundle owned by that column. A **detached tail** is a predecessor retained by NNA; it no longer receives foreground column commands. Shared FX-chain decay is not a voice and has no note-column ownership.

|---|---|
| `0U10`, general `0Uxx` | Identifier is two text characters, argument is a hexadecimal byte. `xx` is a byte 0…255; `xy` is high/low hexadecimal nibbles 0…15. The official dash notation `-U` becomes canonical text `0U`, as observed in bundled song XML. |
| Installed API packed identifier | For present ASCII command characters c1,c2, the numeric `effect_number_value` packs their character bytes as `(byte(c1)<<8)\|byte(c2)`: `0U` is0x3055, not numeric base36 value30. The API's numeric empty-effect sentinel0 is separate; retain source field presence and use canonical text internally. Ordinal base36 decoding applies only to addressed device/parameter characters, never to the entire packed identifier. |
| Note | MIDI-like number 0…119; `OFF` = distinct release event (API 120); empty = no note event (API 121). Do not infer OFF from any effect letter. |
| Instrument | Explicit source index 00…FE, or empty. **P-DECODE:** empty uses last successfully selected instrument for this column; fresh start has no selection, so a note with no resolvable instrument is preserved and flagged and launches nothing. An instrument-only cell updates that selection at its note-event deadline but does not launch audio. Explicit missing/out-of-range index does not fall back to another instrument. |
| Numeric volume/pan | Text `00`…`80` inclusive. `80` is accepted despite the Effect Commands volume-list heading saying `00–7F`; its own endpoint and Tracker Interface say `80`. `81`…`FF` without a recognized letter command is invalid, not a clamped numeric value. |
| Delay | Present `00`…`FF`, or empty; both empty and 00 schedule zero fractional delay but keep different source presence. |
| Argument absent | Keep identifier presence separately from argument presence. Bundled songs have identifiers without values. **P-DECODE:** a recognized present identifier with absent byte executes its explicit zero semantics, with diagnostic `IMPLICIT_ZERO`; raw omission survives export. An argument without identifier, malformed digit, or wrong-length token is PRESERVE-AND-FLAG, no execution. Never convert malformed text to zero. |
| Device address `abzz` | Decode `a,b` separately using base36 `0…9,A…Z`. `a=0` reserves built-ins; `a=Z` reserves globals; `a=1…Y` is proposed device ordinal 1…34. Parameter `b=1…Z` is ordinal 1…35; `b=0` is bypass. Argument `zz` remains hexadecimal, not base36. Devices beyond this representable profile are retained and flagged. This upper device limit is P-DECODE, not a verified Renoise bound. Observed prefixes A/C/I and parameter A/B forbid a hexadecimal-only parser. |
| Address identity | A device ordinal is never a note-column selector. Resolve source ordinal to stable track/device identity before device translation or removal. Preserve zero-based XML indices versus one-based pattern/API ordinals explicitly; do not increment every index indiscriminately. |
| MIDI context | First detect rightmost note-column panning `M0`…`M3`, explicit valid instrument, and effect payload; consume that payload as MIDI before decoding built-ins/device addresses. Rules in section 9 resolve missing and extra payloads. |

**P-DIAG:** compile each unsupported/malformed/out-of-domain occurrence into a stable diagnostic keyed by song identity, sequence/pattern/row/track/column/sub-column, raw identifier/value/presence, resolved target, profile revision and reason. Keep diagnostic counts, never allocate or repeatedly log on the audio thread. A warning is not permission to erase a command. Phrase mode, old timing model, old sample-offset compatibility mode, unknown device type, or unresolved target must not silently select this profile's defaults.

## 3. Normative proposed execution policies

Every rule in this section is **proposed ZTracker policy, unverified against Renoise**. Tables reference policy names rather than hiding missing per-command decisions. Fixture outcomes appear in section 12.

### 3.1 P-TIME: sample clock, deadlines and tick zero

At entered row tick zero, resolve enabled timing automation, then winning ZT/ZL/ZK commands. Freeze that row's `B` BPM, `L` LPB and `N` TPL. The mathematical row duration is `sampleRate*60/(B*L)` frames; TPL does not change musical row duration. **P-CLOCK is a specified floating-point approximation, not exact rational arithmetic:** use IEEE-754 binary64, round-to-nearest ties-to-even after each operation, with no fused operations, reassociation or fast-math in clock calculations. Compute `D=(sampleRate*60)/(B*L)` in that order. Store cumulative row start E and Kahan compensation c, both initially zero. At each row end (including a held cycle), compute `y=D-c`, `next=E+y`, `nextC=(next-E)-y`; schedule the end from next, then assign `E=next,c=nextC`. Do not instead schedule the end from an uncompensated E+D. Retain fractions and compensation across pattern/tempo changes and render blocks; never accumulate rounded integer tick lengths.

Define frame quantization Q(x): let n be the nearest integer to x, ties-to-even; let `ulp(x)=2^(floor(log2(max(1,abs(x))))-52)`, obtaining the exponent from binary64 bits rather than computing a rounded log2. If `abs(x-n)<=8*ulp(x)`, return integer n; otherwise return integer floor(x). This deliberate near-integer snap prevents a few floating-point ULPs below a boundary from moving an event one whole frame early; a mathematical deadline inside that window may be moved to the adjacent integral frame. It is not a Renoise or exact-rational parity claim. Quantize the row start with Q(E), delayed events with Q(E+f*D), tick k with Q(E+(k/N)*D), k=0…N−1, and the row end with Q(next). Compute event offsets in the parenthesized order, independently of audio block boundaries. Render frames before the resulting boundary, apply all events there, then render that frame. The row-end boundary belongs to the next row. If distinct unquantized deadlines quantize to one frame, preserve their unquantized order before the conflict tie order. Do not round delay-column deadlines to ticks.

Reject nonfinite/nonpositive timing inputs and durations below one frame with `INVALID_CLOCK`; source data remains preserved/flagged. Keep E/next in `[0,2^40]` frames; approaching that bound, integer conversion overflow, nonfinite compensation/deadline, or a quantized end not greater than its start stops safely at the last valid boundary with `CLOCK_LIMIT`, retaining source and diagnostic. Stop/seek/fresh Play initialize or reconstruct E/c consistently. Timing-fixture calculations must use this policy, not repeated uncompensated double addition or an unstated epsilon. All render block sizes must produce the same event frames, while agreement with rational Renoise deadlines remains unverified.

Resolve Q per column: last panning `Qx` overrides volume `Qx`, which overrides track `0Qxx`, which overrides Master `0Qxx`; these are replacements, not sums. Add delay-column fraction: `f=q/N+d/256`. A missing delay is d=0. Qx=0 explicitly overrides a nonzero track Q. Track 0Q accepts q=0…N; Qx accepts 0…15, but a deadline `f>=1` cancels this row's note/OFF/instrument-only event with `DELAY_OUTSIDE_ROW`, retaining its source. No carry into next row, no clamp, and no retrigger at row end. Values of track Q>N are invalid and PRESERVE-AND-FLAG; local Q beyond N still decodes but its resulting deadline is cancelled. Delay without a note/OFF/instrument-only event has no effect.

Volume/pan numeric setters, Local FX initializers and column operations travel with a present note/OFF event to that deadline; with no note they execute at tick zero and delay-column is ignored. A track sample-command row descriptor starts at tick zero and does not delay itself. A local 0S/0B/0E follows the note deadline; track variants initialize each new sampler bundle at launch and act on existing bundles at tick zero. Local row updates after a delayed launch occur only at tick boundaries `k/N>=f`: there is no catch-up or redistribution for missed ticks. Static state initializes at launch even between ticks. Thus a one-semitone slide with N=4 and delay 80 receives only k=2,3, total half a semitone.

Cut deadlines are absolute row ticks, not additional delay. Cx deadline `x/N`, 0Cxy deadline `y/N`. If k>=N, cancel that cut/volume-cut with `CUT_OUTSIDE_ROW`, not next-row carry. A same-row note whose Cx deadline is at/before its launch is suppressed (including equal deadlines); Cx never cuts the predecessor merely because the new note is waiting. A same-row 0Cxy due before launch initializes the new bundle's sample-command gain to x/15 at launch; equal deadlines launch then set gain before audio. With no note, the action binds the foreground handle at tick zero; if that handle disappears, the action does not chase its successor. OFF follows Q+delay like a note; a 0C volume cut does not create OFF.

P-TIME uses the same tick-zero update on first playback row and later rows. This deliberately differs from the native reference's missing first-row tick-effect pass. Delayed launches, OFF, cuts and retriggers cannot be scheduled from Unity frames.

### 3.2 P-ORDER: conflicts and stages

Scan source tracks in stored song order; within track scan effect columns left to right. Last **valid enabled** writer to the same global or exact device/mixer target wins. An unsupported writer emits a diagnostic but never suppresses a supported one. Global duplicate commands resolve per identifier; ZT00 or ZL00 wins over all note/flow events when that stop value is the winning value. Winning timing setters apply to the entering row. ZD holds the row end; ZB is consumed when that hold finishes. Pattern-ending natural advance loses to ZB. Effect-column device addresses resolve against the pretranslation source chain, not mutable runtime slot order.

For a given note-column command family, select one descriptor at row entry: Master sample descriptor < owning-track sample descriptor < Local FX < volume command < panning command. Last source effect column wins within a level. U/D/G are one **pitch-motion** family, I/O one **gain-slide** family, J/K one **pan-slide** family; opposing slides never secretly sum. A/V/T/N and C/R each have their own family. Q has the explicit precedence in P-TIME; Y has P-RANDOM. More-specific sample descriptors suppress the broader descriptor only for that component/column, not every column in the track. Resolve each source command's memory even if a more-specific valid command wins execution; unsupported commands never update memory.

At one exact time apply: (1) global timing/stop and mixer/device/automation writes; (2) probability gates already drawn at row entry; (3) OFF/hard-cut actions targeting pre-existing handles; (4) allowed new notes and their NNA/choke; (5) numeric note volume/pan, then selected static sample initializers in order B direction → S cursor/region → E modulation-clock position → G instantaneous target → C volume-cut; (6) retriggers; (7) selected tick updates and command LFO evaluation; (8) instrument macro destinations, instrument modulation and final audio parameter combination. The special same-event Cx suppression in P-TIME happens before launch. A cut voice cannot be retriggered at that time. Numeric setters establish base values, slides modify their distinct command stage, tremolo multiplies it; no command is erased by adding two stages accidentally. B0 plus S80 therefore starts at the explicit half-sample frame and traverses backwards, rather than reflecting S80 around the sample end. If a slice selection would change PCM extent, determine that extent before choosing a default reverse start; an explicit S cursor always wins that default.

### 3.3 P-MEM and P-RESET: explicit state lifetime

Zero-repeat exists only for documented U/D/G/V/I/O/T/N and their equivalent U/D/G/I/O volume/pan shorthand. Bank key is `(source track, source column/sub-column, identifier)`; track effect columns are distinct banks; a Master descriptor has its own bank, not one bank per receiving column. U/D and I/O do not share memory. For a zero byte/nibble repeat, use the last **valid complete nonzero decoded argument** for that bank; if none, execute no update and emit `EMPTY_MEMORY`. Zero-repeat reactivates only on an explicit command. Blank rows cancel the previous row descriptor without deleting remembered values. No partial-nibble memory: nonzero V30 means speed 3, depth 0; V03 means speed 0, depth 3, not “reuse previous speed.” V00 repeats the complete last byte. J0/K0, A00, C00, B00, E00, S00, Q00, R00 and every device/global zero have their own table semantics and never use this bank.

Persistent sample-command state is cumulative pitch offset, sample-command gain (initial 1), direction (initial forward), and current playback cursor; pan-slide modifies note pan. Arpeggio, vibrato, tremolo and auto-pan are transient row modulators, neutral on a blank row. LFO phase belongs to each foreground bundle/component, not the source argument-memory bank; phases carry across consecutive explicit rows but freeze when inactive. Fresh ordinary note creates phase zero, zero pitch offset, sample-command/retrigger gain 1, note gain 1 and note pan 0 unless a numeric row setter replaces them. Authored sample/instrument gain and pan are separate stages; never duplicate them in note defaults. Instrument-only selection does not reset an existing bundle. Glide retains the voice/phase. Retrigger resets bundle command LFO phases and instrument modulation as specified in P-RETRIGGER, but retains command memory and cumulative pitch offset.

Fresh Play from start, load or non-continuation prepared song swap: cut voices, clear FX histories, reset timing/mixer/device/macros to authored defaults, command memory, instrument selection, LFO phases, flow holds and occurrence counters. Pause freezes clock/state; resume preserves all. Stop by transport or ZT00/ZL00 cuts voices, cancels deadlines, clears chain histories and row descriptors, then clears command memory/selection/phase; next Play is fresh. There is no release-tail render after a stop. Pattern boundary, natural sequence wrap and ZB do not clear command memory, instrument selections or mixer/macro state, but each row descriptor expires normally.

Seek is an explicit discontinuity: cut all voices and chain histories; replay scalar state/command-memory/global/device/macro events silently from the start along the sequence's actual flow to the seek target, with no note/voice generation, no NNA or retrigger audio and no random draw dependent on voice allocation. Recover row-entry occurrence counters and automation state. Bound replay to 1,000,000 entered rows; if target is not reached because of looping/stop or limit, flag `SEEK_UNREACHABLE` and do not start at a guessed state. Skip runtime voice-dependent slide/gain/envelope updates during silent seek; warn `SEEK_VOICE_STATE_DISCARDED` if they occur. This is a deterministic seek policy, not a Renoise autoseek claim. Section 10 defines automation/device reconstruction.

### 3.4 P-NNA: bundle and tail ownership

NNA is applied only when a probability-accepted ordinary note actually launches at its deadline, after mapping zones, and not at row parsing. For each old sampler component use its sample's NNA: Cut destroys it; Note-Off starts release and exits loop when loop-release is enabled; Continue detaches it unchanged. Mixed-zone NNA can therefore leave a subset as tails. Synth uses its instrument NNA. A glide with a matching instrument and a foreground bundle changes its pitch target without reselecting zones, launching new voices or invoking NNA. If no suitable bundle exists, G launches an ordinary note at target pitch with `GLIDE_WITHOUT_VOICE`; no glide from silence. A same-row instrument change during glide is PRESERVE-AND-FLAG for that glide and launches the new instrument normally; it must not splice a new patch into a held bundle.

OFF releases foreground components, not already detached tails; sampler one-shot components ignore OFF, but not hard cuts or X00. Sample mute groups cut matching sample components of the same nonzero group and instrument on the same Sequencer track, including tails, when a new mapped component launches. A muted/rejected/delayed-out-of-row note performs no choke or NNA. Group/master audio buses are unaffected by this ownership distinction. On detachment freeze the latest command pitch/arpeggio/vibrato offset, command gain/tremolo factor and pan/auto-pan offset; authored per-voice modulation continues. Later S-SAMPLE or S-COLUMN operations cannot revive/chase that tail. Shared instrument macros/parameter maps and S-MIX/S-DEVICE remain live on tails because their ownership is wider. Voice stealing destroys the selected bundle component's state and scheduled handle-specific events without rebinding them.

### 3.5 P-MATH: gain, pan, slides and LFOs

All gain units below are linear amplitude unless explicitly dB. State uses floating point; never quantize an incremental slide back to a byte each tick. Clamp note gain/sample-command gain to 0…1 and pan to −1…1 after each update. A line slide total a is divided into N updates at k=0…N−1; amount per tick a/N, including tick zero. With a delayed launch only remaining updates occur. Pitch slide state is semitones, not restricted to the note-entry range, but **P-PITCH-SAFETY** clamps cumulative commandPitch to −1536…+1536 semitones after every slide/glide update. Hitting that bound leaves it saturated until a later opposing update; report `PITCH_LIMIT` once per affected bundle through bounded diagnostics, never allocate for repeated saturation.

Compute the sampler increment safely before exponentiation. Let h=`(keyDifference+transpose+fineCents/100+commandPitch+transientCommandPitch+modPitch)/12+log2(sourceRate/outputRate)`, where keyDifference is launchNote−baseNote (zero for key-tracking-off zones). Validate finite inputs and positive finite rates, require finite intermediate sums, rate ratio and h, clamp h to −20…+20, then increment=`2^h`, bounded to `[2^-20,2^20]` source frames/output frame. A zero rate ratio caused by underflow also fails validation. Report `PITCH_LIMIT` for a clipped h even when commandPitch itself is in range. Unexpected nonfinite/intermediate-invalid voice state hard-cuts only that component with `INVALID_PITCH` before exponentiation or sample fetch. All zones retain their tuning in the unclipped range; clipping is an explicit numerical safety deviation, not audible-parity certification.

Compiled PCM/region lengths must be 1…2^31−1 frames, and loops must have valid nonempty bounds inside that region. Keep the fractional cursor in binary64. Before each fetch, normalize loop traversal into its valid interval using bounded remainder/reflection arithmetic (not one loop iteration per crossed frame); without a loop, an out-of-region cursor ends that component before fetching. Re-check `0<=floor(cursor)<regionLength` before index conversion; interpolation neighbors must wrap/clamp within that same region. Never cast an unbounded cursor or increment to an index. The bounded increment and region lengths keep finite one-step arithmetic well below binary64's exact-integer limit. These safety rules also apply after offsets, reversals and retriggers.

**P-GLIDE-COORDINATE:** retain the immutable launchNote N0 for the bundle. Glide's current tracker pitch is `N0+commandPitch`; a target note T requires commandPitch=`T-N0`. Each finite-speed update adds `sign(T-(N0+commandPitch))*min(abs(T-(N0+commandPitch)),step)` to commandPitch, then applies P-PITCH-SAFETY. Instant glide assigns `T-N0` directly. Zone base note, transpose/fine tune, key-tracking mode, arpeggio, vibrato and authored pitch modulation do not enter glide distance or alter N0; they are applied only during final component pitch evaluation. Matching-instrument glide does not reselect zones. A remembered target stores tracker note T, not a rendered frequency or offset that changes with tuning.

For `0Vxy`, `0Txy`, `0Nxy` choose sine LFO rate `x/16` cycles per line and phase increment `2*pi*x/(16*N)` radians per active tick. At a tick evaluate current phase, then increment/wrap for the next tick; initial phase is 0. x=0 is stationary, y=0 neutral. V depth is y/16 semitones peak, so command pitch offset is `(y/16)*sin(phase)`. T depth is a=y/15 and gain multiplier is `1-a*(1-cos(phase))/2`, giving range 1−a…1 and initial 1. N depth is y/15 of the full center-to-edge normalized pan range; pan offset is `(y/15)*sin(phase)`. These rates/depths/waveforms are chosen ZTracker conversions, not documented Renoise conversions. Command modulation is held between ticks. Use separate A/V/T/N phases/state and never permanently multiply pitch on every tick; compute transient modulation against the accumulated pitch each time.

Audio amplitude stages are note gain × sample authored gain × sample-command gain × tremolo × instrument modulation × track instrument gain × prefader gain × postfader gain. The launch velocity used for zone selection/modulation is not multiplied again as a second copy of note gain; an authored velocity modulator can intentionally add its own response. Synth omits sampler-only command stages and includes its independent retrigger gain (initial 1) plus authored patch gain. Numeric note-pan, sampler authored pan, instrument modulation pan and command auto-pan sum then clamp before track pan. For mono pan choose equal-power `left=cos((p+1)*pi/4)`, `right=sin((p+1)*pi/4)`. For stereo sources choose balance (center unity each side): p<0 scales right by 1+p; p>0 scales left by 1−p. Stereo surround/phase widening is not this pan rule. Existing ZTracker synth note-pan uses this same balance as an explicit limited extension (section 7), not a Renoise plugin pan assertion.

**P-SLICE (proposed):** retain a root sample's ordered slice-marker frame array `m[0…s−1]`, plus any mapped slice identity, even though the architecture's shorthand omits marker fields. Retain bounds on reverse/retrigger; do not run into the next slice except explicitly stored slice-loop behavior, which is PRESERVE-AND-FLAG if not represented. Unsliced playback uses all N frames rather than loop bounds for offset calculation. Multiple layered components resolve S independently; one unsupported slice component does not discard the others. This requires P2 marker/parent identity storage; absence of that storage makes sliced S PRESERVE-AND-FLAG, never unsliced reinterpretation.

**P-ENVPOS (proposed):** let u=xx/256. Multi-point Envelope seeks to u times its authored final-point time; loop/sustain gates apply on subsequent updates, not by wrapping the initial seek. AHDSR while held seeks to u*(attack+hold+decay) seconds; while released seeks to u*releaseDuration, using the amplitude captured at release start. A zero total duration evaluates its end state. Sample modulation lists can include multiple clocks; seek each supported active clock independently. Stepper requires discrete-step/play-direction semantics absent from this architecture and executes nothing with an individual diagnostic. Unsupported nonlinear Fader or incompatible envelope format is likewise retained/flagged, not converted to AHDSR. These E conversions are explicit ZTracker policy, not observed Renoise units.

## 6. P-RANDOM: normal probability and Y00 exclusive mode

This entire random/weight policy is **proposed ZTracker policy, unverified against Renoise**; command meanings come from [Effect Commands Y forms](https://tutorials.renoise.com/wiki/Effect_Commands). One immutable uint64 song seed is compiled with profile revision; default seed 0. Do not use process-global, Unity or System random state, voice pool index, render block size or wall clock. Define counter hash H with unsigned wraparound: start h=`14695981039346656037`; feed little-endian 64-bit fields `[seed, sequenceSlotIndex, patternIndex, rowIndex, rowOccurrence, trackIndex, columnIndex, purpose]`, for each byte `h=(h xor byte)*1099511628211`. Then `z=h+0x9E3779B97F4A7C15; z=(z xor(z>>30))*0xBF58476D1CE4E5B9; z=(z xor(z>>27))*0x94D049BB133111EB; z=z xor(z>>31)`. Uniform u=`(z>>11)/9007199254740992.0`, range [0,1). rowOccurrence starts at 0, increments each actual entry to that source sequence slot/pattern/row; held ZD cycles do not increment. Reset/replay P-RESET. Formula defines draws even for empty/muted candidates; skipped candidates cannot shift another result.

Nonexclusive track 0Yxx>0 uses one draw (columnIndex=0xFFFFFFFFFFFFFFFF, purpose=1); accept all eligible note/OFF/instrument-only events on that track iff u<xx/255. More-local ordinary Y gates then independently filter their column: local FX 0Y01…FF uses byte/255, volume/pan Yx uses x/15, priority pan > volume > Local FX. Each column's resolved gate uses purpose=2; YF/0YFF always passes, Y0 outside exclusive mode always fails. Local FX 0Y00 outside track Y00 is not a nested exclusive group: flag `LOCAL_EXCLUSIVE_WITHOUT_TRACK`, execute no guessed gate. Numeric setters without note are not “maybe notes.” Track Y cannot suppress track sample descriptors or automation.

When winning owning-track 0Y00 is present, make one weighted exclusive choice among **ordinary note-ons** on that track; OFF/instrument-only events execute normally. Exclude muted/no instrument/unmapped notes before selection. Weight from highest-priority column Y value (pan nibble > volume nibble > Local FX byte); convert nibble to integer weight 17*x, byte to xx. No local Y means weight 255; explicit Y0/local 0Y00 means weight 0. Choose one using purpose=3, sentinel column index above: integer b=`floor(u*sumWeights)`, and first candidate in ascending note-column index whose cumulative weight exceeds b. All-zero weights or no candidates select none with `EXCLUSIVE_NO_WEIGHT`; never divide by zero or choose uniformly. Exactly one accepted note may still be cancelled by P-TIME/Cx or trigger mute at its deadline; do not choose a replacement. Y weights in exclusive mode are not additionally independent draws. Ineligible data stays preserved. Rejected/delayed-out notes never choke predecessors or start NNA.

Source: [MIDI Commands](https://tutorials.renoise.com/wiki/Effect_Commands#MIDI_Commands), [Instrument Devices](https://tutorials.renoise.com/wiki/Meta_Devices#Instrument_Devices_.28Renoise_only.29). MIDI messages have no tracker effect-memory/zero-repeat, no NNA/voice allocation, and would dispatch at row tick zero independently of note delay if a backend existed. This phase has no MIDI/plugin backend.

## 10. Device parameters, graphical automation and eight macros

Sources: [Instrument Automation / Instrument Macros](https://tutorials.renoise.com/wiki/Meta_Devices#Instrument_Devices_.28Renoise_only.29), [Graphical Automation](https://tutorials.renoise.com/wiki/Graphical_Automation), [Sampler macros](https://tutorials.renoise.com/wiki/Sampler), installed Song67 `InstrumentAutomationDevice` (`ParameterNumber0…34`, `ParameterValue0…34`, `LinkedInstrument`), `InstrumentMacroDevice`, macro mapping destination/min/max/scaling, `pattern/automation.lua`, `device.lua`, `instrument/macro.lua`. These establish slot structure, normalized values and available scaling names, not exact engine evaluation order.

### 10.1 P-IDENTITY: resolve before translation

For *Instrument Automation preserve `(source song identity, track identity, source device identity/type, device ordinal, parameter ordinal, linked source instrument identity, plugin format/vendor/unique plugin ID, external parameter integer ID)`. A device parameter ordinal selects visible slot s (ordinal−1); **slot s maps through ParameterNumbers to the external ID**, and that ID maps through the linked Synth instrument's explicit parameter map. Slot 2 is not necessarily external parameter2. The compiled route is source track/device/slot → linked instrument → external plugin parameter ID → synth parameter or one of eight macros → optional macro destinations. A display name is explanatory metadata, never identity. Missing plugin identity/external ID/map/linked instrument is PRESERVE-AND-FLAG; do not use another instrument whose name happens to match. A linked Sampler needs an explicit supported macro/parameter map as well; no plugin parameter automatically becomes a sample setting.

For *Instrument Macros preserve source device/linked instrument identity plus slot-to-control metadata. Resolve eight ordinary controls to macro indices0…7, then each destination `(instrument/sample or modulation-set/FX-chain identity, device identity, parameter identity, units, min, max, curve)`. Additional MIDI-controller and phrase controls are not macros9…12 and remain PRESERVE-AND-FLAG. Destination identity survives device reordering; route editing must recompile addresses, never silently bind an old ordinal to a new device. A ZTracker chain device needs an explicit equivalence mapping from source parameter identity to AudioCore parameter identity; same name/type is not evidence of sonic equivalence. Unknown source FX remain preserved/flagged even if the plugin automation slot is otherwise resolvable.

### 10.2 P-VALUE: conversion and curves

Addressed byte zz normalizes to u=zz/255; envelope values must be finite 0…1; a macro is a normalized float0…1. For a map with **normalized destination endpoints** a,b in0…1, choose `n=a+(b−a)*C(u)` then clamp0…1. Reversed endpoints are valid, not an error. For a physical synth target with min/max in its declared unit (Hz, seconds, semitones, cents, dB, gain ratio or discrete enum), store that unit/range explicitly, calculate `v=min+(max−min)*C(u)`, then clamp to target domain. Target quantum q>0 rounds using `lower+q*floor((v−lower)/q+0.5)`, clipped to domain; enum targets require an explicit allowed-value table, not guessed ordinal casts. No hidden logarithm for Hz or dB. Default/linear C(u)=u. Equal min/max gives a constant destination. Nonfinite/out-of-range map, missing unit, forbidden enum value or unknown target flags and executes no map.

P5 supports **Linear** imported macro scaling only. Imported `Log Fast`, `Log Slow`, `Exp Slow`, `Exp Fast` or unspecified nonlinear transform are PRESERVE-AND-FLAG **per destination**, retain raw scaling and endpoints; do not flatten them to Linear. Other supported destinations of that macro may execute, and the macro itself still holds its normalized value. ZTracker-authored parameter maps may use an explicit sampled piecewise-linear curve `{u_i,c_i}` with endpoints(0,0),(1,1), strictly ascending finite u_i and c_i in0…1: C is linear interpolation between surrounding knots. It is an explicit authored ZTracker curve, not a claimed reconstruction of those Renoise scaling names; absence of such a curve selects Linear. No unsupported automatic curve approximation in P2/P5.

### 10.3 P-AUTO: time, interpolation and arbitration

Normalize source automation time from API one-based lines to internal zero-based pattern units: `t=(sourceLine−1)+fraction/256`. Retain the source convention in provenance; do not decrement XML coordinates already zero-based. Valid t lies in the source pattern, values finite0…1. Off-grid times/duplicate timestamps/invalid values are retained/flagged and the **affected lane** executes nothing; do not silently sort duplicates into a new meaning. Unordered unique valid points may be sorted for compile while original order survives. For Points use step hold: latest point at/before t. For Lines with zero scaling use `v0+(v1−v0)*(t−t0)/(t1−t0)`. Before first point use authored target default, after last point hold last; empty envelope leaves other sources alone. **Curves and Lines with nonzero scaling are PRESERVE-AND-FLAG for the whole lane**, no invented tangent/exponent interpolation. Separate lane interpolation from mapping C(u).

Evaluate supported lanes at entered-row tick zero, every effect tick and every authored point deadline (1/256-line grid), quantized by P-CLOCK; hold resulting control value until next evaluation. Linear interpolation is sampled at these boundaries, not every audio sample. This control rate is P-AUTO. A delayed note sees the latest held shared parameter at its actual launch. Tempo/LPB/TPL lanes evaluate **only row entry**, time quantum one line; fractional points for them invalidate the lane. Other source parameter time quantum>1/256 must be retained and checked; off-quantum points invalidate that lane. Row/global timing command wins over timing lane at the same row entry. ZD freezes pattern automation time at original row end under P-FLOW.

For each exact scalar target, stored authored default < held effect/device setter < enabled supported graphical lane value < an effect/device setter issued at the **same evaluation instant**. Thus a row effect setter wins tick zero, but an active lane resumes control at next tick/point; without a lane the setter holds. Winning device-source changes are resolved before mapping; instrument-wide conflicts from different tracks follow P-ORDER. Then apply direct target maps in source track/device/slot order, and macro destinations after them in macro index0…7, then mapping-list order; last valid write to an exact destination wins. This defines rather than hides direct-map vs macro conflicts. All writes affect instrument-owned live state, including detached tails/future notes; per-voice modulation evaluates after this base value and does not overwrite the saved asset. Parameter maps must reject non-live memory-sizing targets requiring arena reallocation; PRESERVE-AND-FLAG rather than resizing on audio thread.

### 10.4 P-DISABLE and seek

Disabling an audio-chain device (a000): dry bypass, cease its processing, clear its internal delay/filter/reverb history once; parameter base/automation values remain writable while bypassed. Enabling starts with cleared history and current resolved values; no hidden stale-tail burst. This is proposed, not a Renoise bypass measurement. Disabling a control device (*Instrument Automation/Macros): freeze its destination at last emitted value, continue recording held setter and evaluating supported source lanes into its latent source values, emit no destination changes while disabled. Enable emits current resolved latent values once at that same boundary. Bypass state setters/lane arbitration follow P-AUTO; an unsupported mapping produces no destination writes in either state. Macro values set directly by another enabled device still control that instrument; disabling one source does not disable the instrument's eight macros globally.

Fresh-start defaults load the saved eight macro values and device/map defaults. Seek P-RESET replays enable/disable and setter changes plus automation evaluations in event order, so disabled controls can reconstruct their last emitted value and latent source value; it does not merely sample a target lane at destination time. Shared chain histories/voice modulation remain cleared. Pattern transition without a lane retains previous setter/emitted instrument value; a lane with first point after transition uses target authored default until first point, P-AUTO. Instrument parameter changes are global to that instrument identity, not channel-owned. Macro-channel migration conflicts require section 11 treatment.
