# ZTracker song and instrument data contract

P2 introduces version 1 authoring data. It implements architecture sections 2, 3-data and 4-data, and migration decision 7. The retained script assets remain global `ZTrackerSong` and `ZTrackerInstrument` in assembly `ZTracker`. Their existing script GUIDs are `c9234bbc80b22ff41a0ffb03c40c7bad` and `2b96e89e657daa44898819eea2fce0f6`; their files and metas were not replaced. Legacy `InstrumentType` remains Sample=0, Synth=1, Kit=2, FM=3. The new instrument family and synth mode use separate enums.

## Ownership and versions

`schemaVersion` deliberately has no current-version initializer: a missing serialized field means legacy version 0. The explicit `ZTrackerMigration.Upgrade` overloads prepare and validate a deep candidate, retain the original structured payload in `legacyArchive`, publish `model`, then set version 1 last. Version 1 is idempotent. Negative and future versions are rejected before any mutation. Deserialization does not migrate, dirty, import or save assets. There is no bulk conversion or asset scan. New editor-created assets explicitly upgrade after their legacy defaults are authored.

After migration, `model` is authoritative. Retained public legacy fields are a compatibility view, not a second source of truth. Original structured archives preserve Unity object references as well as dense tails, hidden columns, inactive engine sections, disabled preset overrides, null slots, raw commands and unusual values. Archives are not reconstructed from a lossy inverse. Duplicate instruments receive new instrument identities; existing patterns, tracks and sequence slots retain identities through editor reordering/removal, while additions and clones receive fresh identities. References use stored identities rather than names or ordinals.

## Song data

`SongData` stores BPM as a double, LPB and TPL independently, an authored positive voice capacity (default 128), instrument references in unchanged slot order, ordered tracks, pattern pool and sequence slots. Global beat events have a separate enable and line interval (legacy default enabled/every four lines). Groove is outside this phase.

Tracks are Sequencer, Group, Send, Master or the ZTracker Event extension. They store name/colour, independent parent group and explicit output route, prefader gain/pan/width, postfader gain/pan, trigger mute, output mute and solo. Empty explicit output means parent group, then Master. Exactly one Master is required. Sequencers have 1–12 visible note columns; all tracks have 0–8 visible effect columns; buses and Event tracks have zero note columns. Each note column has volume/pan/delay/local-FX visibility. Hidden payload is retained and marked inactive rather than activated by migration. The model allows at most 64 sequencer tracks and does not allocate a native-sized dense grid.

Every track and instrument FX chain stores `Laubrary.Audio.AudioEffectChainData` directly. Its ordered nodes, modifiers, bindings, enum integers and UIDs remain portable. The data/editor assemblies reference AudioCore; neither depends on the Zounds assembly. Sends are ordered tracker routing records with destination track identity, gain, device insertion position (0 before first node, node count after last) and pre/postfader tap selection. They are not counterfeit AudioCore effect nodes. Group ancestry and the combined output/send graph are validated independently for cycles, missing identities and illegal destinations.

Patterns hold 1–512 lines and exactly one pattern-track record for each track identity. Pattern tracks store sorted sparse line records and automation lanes. A read of an absent line returns a detached empty view without insertion. `WriteLine` replaces by line index and removes the line when its last payload is cleared. Column ordinals are explicit, so an empty interior column never shifts another column. Note-only, instrument-only, volume-zero, command-zero-argument and event-only lines remain stored. Dense arrays exist only in the temporary legacy projection/archive.

`ZTrackerPatternOperations.Resize/InsertLine/DeleteLine` operate on every sparse payload category and fractional automation position. They return a deep complete pre-edit pattern archive for the caller's Undo/history, including cropped/removed events and points. Insert/delete retain fixed pattern length; removed content is available from the returned archive. P6 authoring must wrap these operations in its own Unity Undo transaction.

Notes distinguish Empty, Note (0–119), Off and retained Legacy values. Instrument selection has explicit presence, including authored index zero. Volume and pan distinguish empty, numeric 0–128, command and retained legacy values. Delay has presence plus 0–255 value. Local sample FX and effect columns retain identifier presence independently from argument presence. Commands store text identifiers, scope (column/track/global/unresolved), target column, profile, unsupported flag, diagnostic and reversible legacy command/parameter/column/address fields. Events retain full text, profile and provenance. Per-note parameter-set selectors/legacy extras are retained extension fields.

Each sequence slot holds a pattern identity and its own list of muted track identities; repeated use of a pattern does not share slot mute state. Automation has a typed mixer/device/instrument-macro target with stable device/parameter/instrument identity, enabled state, fractional line points and Step/Linear interpolation. Points must be finite, ordered and unique; duplicate timestamps are rejected rather than normalized. Device and macro references must resolve unless explicitly retained as unresolved. These are authoring structures, not P5 evaluators.

## Sampler and Synth data

A sampler stores global volume/pan/transpose/fine tuning and Cut/NoteOff/Continue NNA, sample records and keyzones. A sample references an existing `AudioClip`; PCM is immutable shared source data, not per-voice data. Runtime compilation will deduplicate PCM by source identity. Playback settings remain separate even when samples share a clip: level/pan/transpose/cents/base note, Off/Forward/Backward/PingPong loop with frame start and exclusive end, release-exits-loop, Linear/Cubic interpolation, one-shot, NNA, modulation/FX indices and mute group. Unassigned indices use -1. Velocity ranges are inclusive 0–127; note ranges are inclusive 0–119. Overlapping active zones are simultaneous layers. Key tracking off expresses a fixed-pitch drum.

Modulation sets store filter type and ordered devices targeting volume, pan, pitch, cutoff, resonance or drive. Device kinds are AHDSR (hold included), multipoint with sustain/loop, LFO, velocity, key tracking and fader. Stable device identities, units and Add/Multiply/Replace operations are explicit. Legacy amplitude envelopes are migrated as AHDSR with hold zero. Existing parameter curves, loops, vibrato/arpeggio and per-voice filter/send settings remain in the typed retained parameter extension; those effects are not silently recast as a summed instrument chain. The new modulation devices and chains have no realtime evaluator in P2.

Both families have exactly eight normal instrument macros. Each has name/value and ordered typed mappings with min/max/curve. Legacy macro order, zero defaults and link names survive; unknown links are explicitly unresolved; overflow beyond eight is archived and diagnosed. Synth retains subtractive/oscillator/blend/unison/vibrato/arpeggio/parameter-envelope data and all four-operator FM fields under Subtractive/FM mode. Saved wave, FM-algorithm and envelope-loop integers are preserved without correcting P4 defects. Synth also has an external-ID-to-typed-parameter map with bounds/curve and unresolved status; duplicate external IDs are invalid.

`ResolveParameterSets` returns a deep independent Base set plus one set per authored preset. Each section inherits Base unless its override flag is enabled. Disabled payloads remain authored. Sample A/B references/tuning, applicable envelopes, synth scalars, ADSR, vibrato and effects are resolved. Curves, arrays, modulation and chains do not alias the authored source. Presets add no canonical instrument slots. The old DLL still uses temporary contiguous preset slot bands during compatibility upload, bounded by its 512-slot bank; those bands are not part of this authoring model.

## Explicit legacy conversion

| Source | Version 1 result |
| --- | --- |
| Sample | One sample and full-note/full-velocity keytracking zone, preserving clip/base/cents. Global gain/pan is applied once; sample level stays unity. Loop Off, Linear interpolation, NNA NoteOff. |
| Sample B | One paired ZTracker-only extension on the zone, with B clip/base/cents, blend mode/amount/PM depth, blend ADSR and curves. It is not a second layer. Renoise interchange warning is explicit. |
| Kit | Fixed-pitch zones with per-entry sample/name/level/ADSR. Duplicate mapped notes retain earlier entries as inactive superseded history; out-of-profile keys stay inactive. Authored zero volume/base note remain in raw fields; effective legacy defaults are level 1/base 60. Overlap true maps Continue, false NoteOff. Existing global settings/curves/effects remain retained extensions. |
| Shared row fields | Instrument and volume fan out to all visible note columns, including empty/OFF columns, and all saved hidden extras. -1 instrument and 255 volume remain empty; native 0–64 volume converts to 0–128 by multiplication by two; raw 65–254 remains flagged with effective full level. |
| Notes 120–126 | Retained Legacy note kind and raw pitch, not clamped or confused with OFF127. |
| Hidden/malformed data | Hidden notes/effects retain original ordinals and inactivity. Saved channel count is used as the dense stride before any widening. |
| Commands | The committed T-0017 revision 1 section 11 governs conversion. F with p>=32 becomes ZT p; p=1–16 becomes ZK p; F00 becomes ZK01. Original bytes/address and `LEGACY_TIMING_EVENT_DIFFERENCE` survive. TPL17–31, ratio slides, conditional glide/break/preset conversions, per-channel macros and unsupported bytes remain preserved and flagged. Decimal16/17/18 are distinct from hexadecimal16/17/18. No ZJ or guessed semantics are introduced. |

## Temporary editor/backend compatibility

`ZTrackerLegacyCompatibility.Project` validates and proves an exact roundtrip through the old shared-row view before authoring is permitted. It is deliberately conservative: new-only routing, buses, devices, automation, divergent column instrument/volume, local pan/delay/FX, parameter-set selection, sampler zones/loops/layers/interpolation/NNA, extra macro/map features and unknown future versions are retained read-only in the old editor. Odd 0–128 volume cannot be silently rounded into 0–64. Multiple nonempty effect columns landing on the same native note channel are rejected rather than reproducing last-wins loss. Empty legacy list padding is semantically equivalent and does not overwrite the saved dense container shape.

Every old UI mutation goes through `ZTrackerLegacyEdit`: prove compatibility, record a complete-object Undo snapshot, explicitly upgrade if needed, perform the existing edit, validate/reconcile the result, then dirty the selected object. A failure restores the entire original serialization. Only the proved legacy-representable subset is reconstructed; no omitted new-only fields can be overwritten. The original archive survives. The live-scalar branch and both envelope gesture paths use the same transaction. The existing base-window Undo/Redo rebuild stops preview, refreshes the projection from restored authority and rebinds captured controls. Dense resize/delete snapshots restore cropped data. Creation and duplication explicitly handle schema and identities. No UI layout was redesigned; incompatible controls are disabled and the existing transport tooltip reports the reason. Future-version assets cannot be saved through the old Save action.

Instrument projection reads canonical sample/zone PCM, pitch, Sample-B, ADSR and sampler globals, canonical kit entries, synth parameters/mode and representable macro edits. It preserves inactive legacy fields but never uploads an obsolete wrapper in place of those canonical fields. Unsupported independent playback settings still fail the exact roundtrip. Kits keep neutral effective global volume/pan because the old backend ignores their original globals; those original values remain explicitly diagnosed legacy extensions. A null PCM kit entry does not displace an earlier uploaded duplicate. Modern kit silence (sample volume zero) is refused because the old backend interprets zero as unity. Preset resolution inherits current canonical values and changes only overridden fields, retaining extra modulation devices, hold/filter data and independent blend settings.

Scalar refresh uses the instrument references captured at upload time, including repeated references, so subsequent source-list edits cannot retarget native slots. It validates every affected snapshot before modification and refuses engine/PCM/preset-structure/curve/macro/effect changes that require a prepared restart. The old backend evaluates four macros; changes to modern macros five through eight are refused. Existing ignored legacy links/bank entries and the old volume-macro zero floor are retained with diagnostics. Active envelope/arpeggio/FM data exceeding the old native capacities (32 points, five notes, four operators) is rejected before upload rather than truncated. A rejected later move in a repeated gesture restores its entire original serialization.

Unity JSON can normalize null managed records, strings and collections into default or empty values, including on the source being serialized. Capture, cloning, projection comparison and transaction snapshots explicitly restore original null paths. Each asset keeps serialization null-path metadata for Undo/Redo and save/reload, and each migrated asset also stores immutable archive null-path metadata. Partial projection refresh discards stale target metadata before deserialization and records the resulting nulls, so new non-null fields cannot be erased by an earlier snapshot. Null legacy preset records are retained and migration/playback/editing is refused until explicit repair; they are never replaced with fabricated presets. Malformed dense cells remain archived and read-only.

`Prepare` builds owned detached snapshots for song and instrument upload. It never migrates/dirties the authored assets. Whole-song validation, capacities, effect collisions and PCM readability run before native mutation. The old limits remain 32 native channels, 256 pattern lines/patterns/order slots, 512 instrument/preset slots and 512 sample uploads, 128 voices. Each note column claims a native channel. All public song/instrument upload paths route through preparation; raw internal upload requires a marked prepared snapshot. Audition, song preview and runtime playback share preparation. Active macro polling and scalar refresh read/update the same detached snapshots, preserving source identity-to-slot mapping. AudioClip references remain shared. The P/Invoke ABI, DLL and native source are unchanged.

The existing Event-track API supports one event lane per logical Event track. Native preparation assigns one channel, validates nonempty printable ASCII text up to 63 bytes, uploads it once and exposes native-channel-to-track/column mapping. Full longer/non-ASCII strings remain canonical and are explicitly rejected for this backend, never truncated. Per-track event mutes/effects and multiple events on one line are refused because the native event branch cannot express them. Global beat enable/interval uses the existing native setter. Event type/pattern/row/channel/note/instrument/string/sample-position contracts remain intact. Independent event sub-columns on audio tracks remain data-only until P3/P5.

## Verification and rerun

Use `Laubrary/ZTracker Model Check`, or invoke `Laubrary.ZTracker.Editor.ZTrackerModelCheck.Execute()` by reflection through `unity command --project-path "D:/UNITY/Laubrary Dev" eval_file <file> --json` in canonical editor port 7802. Do not use Test Runner. The check owns and tears down its temporary objects/Undo records/contexts. It refuses to take over another active preview. The saved-demo checks create a uniquely named `Assets/ZTrackerP2Scratch-*` folder, copy only YAML, let Unity issue fresh asset metas, remap the scratch song to its scratch instrument, migrate, save only those objects, unload/reload and confirm persisted versions/identities/references/script GUIDs. Both `Samples~/ZTrackerDemo` and `Assets/Demos/ZTrackerDemo` are checked independently. All eight live asset/meta hashes are compared. The absolute scratch path is verified under Assets before deleting only that folder.

Compilation must be checked with `EditorUtility.scriptCompilationFailed` and the fresh `ImplementationWitness`, not cumulative console text alone. Model checks cover capacities/empty semantics, portable chain roundtrip, routing cycles, automation, sample/kit/B/preset preservation, command bases, versions, projection refusal, real legacy editor methods, Undo/Redo, snapshots, Event upload, null archive save/reload and both saved demo sets.
