# AudioCore: reusable effects, modulation and SAP lifetime

AudioCore separates the flat audio engine from Zounds asset lookup and playback. Its assembly is `com.Lautaro-Arino.Laubrary.AudioCore`; public engine APIs use `Laubrary.Audio`. It has explicit assembly-definition references to Burst, Collections and Mathematics, with unsafe code enabled. Unity engine references remain enabled because this Unity version defines `NativeArray` and `Allocator` in `UnityEngine.CoreModule`. It has no assembly reference to Zounds or ZUI and no asset lookup, generator, registry, source playback, editor window or menu.

## Authoring and compilation boundary

`AudioEffectChainData` is portable managed authoring data: ordered effect nodes, modifiers, bindings and plain envelope points. Its serialized field shape matches the existing Zounds chain, including envelope fields and integer authoring metadata. It is never read by the audio thread. Zounds retains its existing authored classes and editor behavior; `ZoundsAudioCoreData.ToAudioData` / `ToZoundsData` provide main-thread JSON conversion. A tracker can store the portable form directly without acquiring Zounds assets or ZUI objects. Compilation of authored parameters, bounds, bindings and initial modifier state remains a host responsibility; this task does not add a second authoring compiler.

Serialized effect/modifier/operation/mode/combine enums now reside in AudioCore but deliberately retain their historical `Laubrary.Zounds` or `Laubrary.Zounds.Dsp` namespaces and unchanged explicit numeric values. These namespaces do not introduce a Zounds assembly dependency. Existing field types and JSON enum integers remain compatible. Nine enum groups and an exact authored-chain JSON roundtrip are checked. Assembly-qualified external reflection or custom serializers naming the previous assembly need to resolve these enums in AudioCore; no compatibility is claimed for such third-party serializers.

`AudioChainTables` contains ordinary arrays and logical counts for the complete flat layout: nodes and state/parameter offsets, base/bounded/ratio parameters, precomputed derived sizes, native envelope points, modifiers/steps/control coefficients, ordered bindings, ramped target indices, and total state/tail requirements. `SapChainLayout.Create(tables, allocator)` copies these arrays into owned native buffers. Null/empty arrays receive a one-element backing buffer while their logical counts remain zero. The host must supply consistent counts, offsets, parameter order and state reservations; the factory does not infer or repair malformed authored data. `AudioEffectSizing` supplies unchanged effect/modifier sizes, delay ring sizes and reverb tuning lengths. `ZoundsAudioCoreLayout.Create` is the retained asset-aware adapter from Zounds' compiled managed layout.

## Processor ownership and render contract

`AudioChainProcessor.Create(in layout, sampleRate, allocator, randomSeed, envelopeSeed)` allocates its own state arena sized to `max(1, layout.stateFloats)`, parameter/control buffers and two 64-sample dry scratch buffers. It borrows the layout; it does not own or dispose it. One processor represents one independent chain state. Struct copies used by jobs alias the native buffers, so only one owner may dispose them. Keep scalar timeline/RNG changes from the rendering copy when handing work back to the owner. Neither the layout nor processor may be mutated, reset, replaced or freed while another thread renders them.

`Reset` clears effect/modifier state, restores base parameters and initial control/presence values, and resets the sample clock. It does not perform asset-keyed trigger-history or project-level seeding. A host may initialize modifier arena slots after reset, before publishing: random modifiers need their per-trigger draw, free-running steps need their starting index, and random-walk LFOs need their initial native walk state. Zounds continues to do this in its existing setup path. Reusable primitives are `EnvelopeRandomMath`, `ChainModulation.DrawRandom`, `ChainModulation.NextRandom01` and the flat modifier offsets. The kept parity check copies the same seeded native state into both render paths, including all five modifier kinds plus free-running-step and random-walk variants.

`Process(in layout, left, right, offset, count, in context)` processes planar stereo native arrays in place over the valid requested range. Left/right buffers must have sufficient length and distinct storage. Use a positive sample rate and the same rate used for layout sizing/reset. Calls may span or end inside the 64-sample control grid. At each grid boundary the processor evaluates modifiers at the end of that control block, combines bindings in authored order, clamps targets, and computes the same 64-sample parameter slopes as the Zounds voice. Partial calls preserve grid position and continuing ramps. Direct parameter/control/presence changes must occur on the owning render thread at the host's defined control boundary; the public native buffers are not cross-thread command channels.

`ChainProcessContext.effects.elapsedSeconds` is the time origin at processor sample zero, not the current call's time. The processor adds its sample-clock elapsed time. `sourceProgress` is source progress at the first sample of the current call; `sourceProgressPerSample` supplies the lookahead slope. `followSource`, source duration and source exhaustion control source-relative envelopes. These values must describe the same source trajectory as the host's playback. Effects and source/output gain, completion decisions, snapshots, glides, repetition and playback ownership are different responsibilities: the chain processor applies effects and modulation; Zounds retains its existing voice behavior around that shared engine.

Example after the host has filled valid flat tables:

```csharp
var layout = SapChainLayout.Create(tables, Allocator.Persistent);
var processor = AudioChainProcessor.Create(in layout, 48000, Allocator.Persistent);
// Seed host-specific modifier state before publishing either object.
var context = new ChainProcessContext {
    effects = new VoiceContext { sampleRate = 48000, sourceDuration = duration },
    followSource = false,
};
processor.Process(in layout, left, right, 0, frameCount, in context);
// Stop publishing rendering, then establish quiet before disposal.
processor.Dispose();
layout.Dispose();
```

The processor is unmanaged and usable inside a registered Burst job. Its processing path allocates no managed memory and does not call asset/editor APIs. Allocation and disposal occur outside rendering. `AudioThreadGuard` exposes the shared diagnostic counters; the actual callback/job calls `CountBlock` once at its entry when diagnostics are wanted. `ZoundAudioThreadGuard` remains a Zounds forwarding facade so existing witness and overlay sources compile unchanged.

Buffer partition independence is not guaranteed. Some existing effects compute coefficients once per slice; the phase-modulation effect and fade can therefore produce different output when the host changes slice sizes. The extracted processor preserves this behavior. The parity check compares matching partitions and separately reports the original voice's partition difference rather than hiding it or increasing the numerical gate.

## Shared SAP lifetime contract

The host owns `SapRenderTicket.Create`'s three-long native ticket independently of the realtime object's own memory: block counter, rendered frames and first terminal frame. `Enter` makes the block counter odd; `Exit` records frame/terminal progress and makes it even. Pair these on the render path. Main-thread `Read` uses volatile observation through a native pointer without taking a NativeArray safety lock. One even reading is not proof that future callbacks cannot arrive.

First stop/silence the host graph and prevent new publishing. Then use `SapQuietWindow.Observe` over successive observations or `SapLifetime.WaitUntilQuiet` on the main thread. Reclamation requires an unchanged even counter for the full settle interval. Movement or an odd value restarts that interval. `DefaultSettleSeconds` preserves the existing 2.2-buffer interval, clamped to 5–60 ms with the existing fallback. A timeout means retain the memory, not permission to free it. Blocking quiet waits may allocate/sleep and must never run on the render thread. The host must enforce stop/publishing and keep tickets alive throughout observation.

`SapQuitDrain.Begin(now)` starts a host-driven quit gate after stop/silence. Refuse new rendering while `RefuseNewRendering` is true and keep normal frame updates alive. Call `Tick(now)` once per actual host frame; it permits the final quit only after at least two updates and 0.3 seconds. It has no platform hooks or Unity quit call. Zounds retains those hooks, editor/play-mode decisions and audio-source operations, while its registry uses this gate and shared quiet wait. Its generator and realtime voice use the shared ticket and stable-window logic. Retired tickets that cannot be proven quiet remain retained; the safe outcome may be a small leak rather than freeing memory under a late callback.

## Verification and release notes for T-0010

The kept editor checks are `AudioCoreChainCheck.Execute()` and `AudioCoreLifetimeCheck.Execute()`. Invoke by targeted Unity CLI `eval_file` / reflection in the Laubrary Dev editor (port 7802), not Unity Test Runner. The chain check covers all 16 effects separately and combined, envelope/LFO/random/step/code modifiers, random walks and free-running steps, in-place partial calls, precise arena sizing, actual compiled Burst execution, block/managed guards and thread-specific managed allocation measurements. Matching managed and compiled voice paths had maximum difference zero in all 18 cases; each measured processor case allocated zero bytes. The lifetime check covers empty generic layouts, ticket ownership/counters, stable-even observation, odd/moving timeout refusal, settle sizing, quit frame/time bounds, enum values and exact portable JSON roundtrip. Runtime/editor Zounds, Chunks, Launimator and Zoetrope dependent assemblies loaded after recompilation.

Existing baseline checks were run before and after extraction without changing their 1e-5 threshold. Default delay difference remains `1.29733235e-5` and high-pass remains `0.000338494778`, so both pre-existing default checks still fail that threshold. Generator compiled delay difference remains `0.000481254421`; generator reverb and LFO differences remain `8.940697e-8` and `2.98023224e-8`. The compiled witness remains true and reports the same largest delay difference. Existing allocation cases finished with three zero readings each; one earlier global-heap reverb sample transiently rose 12,288 bytes between zero readings, and the isolated rerun returned all zero. This global-heap observation cannot identify the allocation's origin; the processor's current-thread measurement was zero throughout.

Verified by probe: editor compilation, dependency separation, native ownership sizing, fixed-input managed/Burst parity, scoped zero allocation and counters, serialization, lifetime state machine and unchanged baseline numbers. Verified by eye: not applicable; no UI was developed. Not verified: player/device audio callback timing, audibility, live graph teardown under device changes, platform quit/reload behavior, full-game GC-in-player behavior, and external assembly-qualified serializers. This is a reusable engine extraction, not a claim that those integration environments have passed.

Release note for the next package release: extract shared effect/modulation/layout/state-sizing primitives into AudioCore; add an owned-state native chain processor, portable authored-chain data and shared SAP lifetime helpers; route Zounds through the shared implementation while preserving serialized enum values and existing DSP behavior. `CHANGELOG.md` was intentionally left untouched because it contains unrelated owner edits. No package version bump is included.
