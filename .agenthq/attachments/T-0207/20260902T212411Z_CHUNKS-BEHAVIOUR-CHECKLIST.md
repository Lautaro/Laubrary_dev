# W0.2 — Chunks behaviour checklist: the acceptance test (T-0207)

**What this is.** Every user action the capability-stack Chunks window (`ChunkWindow` rebuilt per `CHUNKS-DESIGN-DECISIONS.md`) must support, the visible result the user is entitled to expect, and how to check that result *temporally* — over seconds, with the clock running — rather than by asking an API whether a field changed. This is written **before the window exists**: `ChunkSpec` today (`Runtime/Chunks/ChunkSpec.cs`) is still the legacy fixed-field model (schemaVersion 0), and the capability stack, `ChunkModuleContext`/`ChunkModuleRunner`, and the multi-lane timing control are all still to be built. Every row is therefore derived from `CHUNKS-DESIGN-DECISIONS.md` (the spec, wins on disagreement), cross-checked against the **actual field lists** of the legacy modules each capability is built from (`ParticleSplashModule.cs`, `PyreSpawnModule.cs`, `PyreMotionModule.cs`, `FragmentSlicerModule.cs`, `SpawnFormationModule.cs`, `SpawnFormation.cs`, `LayerSpec.cs`, `ChunkTimeline.cs`), and against Pyre's own transport/chrome (`Editor/Pyre/PyreWindow.cs`, `PyreWindow.Preview.cs`) wherever the spec says Pyre is the behavioural reference (§4, §6).

**Why it exists.** Per `verify-behaviour-over-time-not-parts` (Lautaro, 2026-09-02, Shaper programme): a tool that passes every static probe and screenshot can still be unusable — Shaper's Play button existed and did nothing, and nobody caught it because nobody watched the preview move. This document is the walk, not a spec restatement: every row says what a human sees change, and how to prove it changed by capturing at two points in time and diffing, not by reading a field back through the API.

**How to read a row.**
- **Citation** points either at the design-decision section the row is derived from (`§N`), at the legacy field(s) that field-level rows must carry forward (`file:line`), or at the Pyre file:line the behaviour is modelled on. Where a fact needed verifying in source rather than trusting a doc, it is marked **(verified)**.
- **PM walk** is deliberately blank. Nobody has operated this window yet — it does not exist. Fill this column during the real handover walk once it is built: ✅ matches / ⚠️ differs (say how) / ❌ missing.
- "Diff the preview" means capture the schematic's pixels (or the transport readout, or the timing lane geometry) at two named times and compare — a preview that has stopped and one that is playing an identical, non-moving picture are indistinguishable any other way.
