## Description

No dependency on T-0001/T-0002 — this is pure data model and can be built in parallel with the ZUI control work.

Add a new MetaLayer mode that authors a **vector per frame** (origin position + direction + optional length, default normalized), alongside the existing `Point`/`Shape` modes.

**Current state (confirmed by reading `Runtime/Launimator/MetaLayer.cs` this session):** `MetaLayer` has `mode` (`MetaLayerMode.Shape | Point`), and `List<MetaFrame> frames`. `MetaFrame` is a byte-mask grid (`cells`, 0-10 painted values, row-major) — it's a PAINT-based representation. **There is no vector/direction concept today, and `MetaFrame`'s byte-mask shape is not reusable for this** — a vector needs continuous float data (origin x/y, direction x/y or angle, length), not a painted grid. Point mode's existing resolution (`TryComputeCentroid`) is a value-weighted centroid over the mask — not applicable here either.

**What to build:**
- `MetaLayerMode.Vector` added to the existing enum.
- A new per-frame data class for vector frames (name it to fit alongside `MetaFrame`, e.g. `VectorMetaFrame` or similar) holding: origin (Vector2, in the same frame-pixel coordinate space `MetaFrame`/points already use), direction (Vector2, normalized), length (float, meaningful only when the layer is configured to allow non-normalized/adjustable length — see below), and whatever "is this frame authored at all" flag mirrors how Point mode already handles an unpainted frame (don't invent a different convention for "nothing authored here" than what Point mode already does).
- A layer-level setting for whether length is meaningful/adjustable for this particular vector layer, vs. always-normalized (this is what T-0001's `allowLength` will ultimately be configured FROM when the authoring UI, T-0006, wires it up — but for THIS task, just make sure the DATA can represent both cases; don't build any UI yet).

Keep this additive: existing `Shape`/`Point` layers and all their consumers must be completely unaffected — same rule the project already follows everywhere else in this codebase (MotionPose, Zoe events, etc. are all additive-and-unauthored-by-default).

**Stay domain-agnostic (user clarification, 2026-08-16):** this type must know nothing about weapons/muzzles/projectiles — it's generic per-frame vector metadata, exactly as domain-agnostic as `MetaFrame`/Point mode already is. See T-0005's note for why: the weapon system is the consumer that assigns meaning to a named layer, not this data type.
