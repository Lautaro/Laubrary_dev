### 2026-09-27T17:02:07Z — agent — in_progress -> done
Done: found, fixed, and verified quiet.

WHAT THE CONSOLE SHOWED: an IndexOutOfRangeException ('Index 28280 is out of range of 8192') on every redraw, followed each time by 'Invalid GUILayout state', the window's layout left half-built by the exception.
SOURCE: not the wide-layout pass (T-0437 to T-0441). It was the live analyser from T-0434. Its silent display voice always asked the engine for the SMALL working memory (8,192 floats), while real playback sizes it from the chain. The owner had just added a Reverb: that chain needs 28,288 floats (Gain + Low pass + Reverb + his Step modifier), so the modifier's state landed past the end of the small memory, and it threw on every redraw.
FIX:
1. The display voice now sizes its memory exactly as playback does, from the chain's own layout.
2. The analyser's live update is now guarded. If it ever fails, for any reason, it reports once with the full exception and pauses until the chain is edited, instead of throwing on every redraw and breaking the window's layout.
VERIFIED:
- Console empty after clearing it and running the owner's real window (Gain, Low pass, Reverb, Step) with the analyser open for 6 seconds.
- The display voice is running and 3 live pictures were taken; the guard did not have to trigger.
- All 16 effects tested, each alongside a Reverb (so the large memory is needed) with an LFO bound: display voice plus live measurement, no exceptions, 16/16.
- Seen by eye: the owner's window drawing normally, with the Reverb inline and the live bars showing.
LESSON: the T-0434 checks used chains with only filters, which fit in the small memory. The large-memory case was never exercised until a Reverb was added. The 16-effect sweep above covers it now.
