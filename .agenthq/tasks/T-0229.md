### 2026-09-03T22:24:48Z — agent — in_progress -> done
DotGen's four module sections are now the tool they were meant to be.

Placement is a choice of method plus the dials of whichever method is chosen, and each method keeps its own dials: trying rings on a lattice you spent ten minutes tuning and changing your mind hands the lattice back exactly as it was, while a method you have never used arrives on the numbers its type was written with, not on blanks.

Selectors, Mutators and Drawers are lists of cards. Each card is added from a button that names what it adds, renamed in place, switched off without losing a setting (the card says so and puts its dials away), and removed - all undoable. A mutator's and a drawer's position is the order it runs in, so both are draggable by a grip; a selector has no grip, because it is reached by name and its position decides nothing.

Anything that reads a selector points at it by picking a name this generator declares - never by typing - the list relabels itself the moment a selector is renamed, a selector that is switched off is shown as off (it counts as All dots), and deleting a selector puts everything that referenced it back on All dots instead of leaving a reference to something that is gone.

A Fill drawer painting from a list gets that list in order: a flat colour or a gradient added to the end in one press, on the documented colours, and the last remaining entry cannot be removed.

Hovering a card draws that module's overlays on the picture and outlines the card in the same cyan, so the overlay and the card that owns it read as one thing. Clicking a card's header makes it the sticky overlay target and folds it away; its own controls (the enable, the name, the remove) stay usable without folding anything. Folds are remembered for the session only, per module.
**Details:**
DECISIONS I MADE (owner away; recorded, not parked)

1. Placement method PRESERVES, per the W0.2 ruling (D-1): the switch activates the generator's banked instance for that type, or creates it from its field initializers plus the role defaults on a first visit, and mints its id from the document. The Method tooltip says so, because "will I lose my grid?" is the question the control actually raises.

2. Method is a MiniRadio, not Segmented, even at three options - the build spec names MiniRadio for it explicitly and the registry can grow past three. This also keeps it consistent with every reflected enum inside the cards (see the open item below).

3. Selectors get no drag grip. Their order is meaningless (they are referenced by id), and a grip promising an order that changes nothing is a lie. Mutators and drawers have grips.

4. Cards carry a grip and an x, not up/down/x buttons. The layout table in the build spec said up/down/x; its own Cards bullet and the UI guide's card-layout rule say grip + x, and that is the newer, more specific statement.

5. The Fill drawer's selector picker is shown only when it is painting Placement cells. Painting whole generator areas never reads the selector (the runtime's Targets() proves it), and an inert control is worse than no control. Checklist row B-119 says the same.

6. Card bodies use ZuiReflect.FlowFields, not BuildFields: short dials sit beside each other instead of one per full-width row, which is the card-layout rule's own "short fields fill the space beside an existing row". Pyre still stacks; this is the deliberate difference.

7. The add button for a category with exactly one kind (Drawers today) names that kind and adds it on the press ("+ Fill drawer") instead of opening a one-item menu - the "a label must do what it says" rule. With several kinds (Selectors, Mutators) it opens the ZuiMenu.

8. The cyan outline is a real shared USS rule, .zui-root .zui-box.zui-card--gizmo in ZuiToolkit.uss (border colour only, so nothing moves when it lights up). A class with no rule renders nothing, and any tool with a hover-driven overlay can now wear this one.

9. Nudge's Bias angle stays visible at bias 0, as the runtime already decided - [ZUIShowIf] matches a value, and "above zero" is not one.

OPEN ITEM FOR THE PM (not a defect in this task)

Every enum INSIDE a card renders as a wrapped MiniRadio, never Segmented, because ZuiReflect.EnumControl draws all non-flags enums that way (inventory section 1, verified in the source). The build spec's "Segmented for <=3" therefore holds only for hand-built controls - and the Generator section (W2.1) does use Z.Segmented for Shape. So the window mixes the two looks for equally short enums. Fixing it means changing EnumControl for every tool that reflects fields (Pyre, Chunks, SpriteFx, Lathe...), which is a systemic ZUI decision, not a card task's call. Flagging rather than doing it.
