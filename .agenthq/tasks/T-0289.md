## Description

Found by T-0288's fourth pass, measured on the live Shaper window (Cherry Framing on, three slots) and against the engine directly.

**What happens.** Right-clicking a cherry slot opens its editor popover (the ONLY way to edit a slot). It draws, all live, all ungreyed: `Variable length` (a toggle), `Length x`, `Min`, `Max`. Exactly two of those three dials are dead at any moment, and which two is decided by the toggle sitting directly above them.

**Measured** against `ShaperCherryFrame.ResolveLength` (`Runtime/Shaper/ShaperCherry.cs:77-83`), which reads `if (!useMinMaxLength) return Max(0.05f, lengthMultiplier);` and otherwise draws between Min and Max:

| Variable length | change | resolved beats |
|---|---|---|
| OFF | Min 1 -> 0.25, Max 1 -> 8 | 1 -> **1** (dead) |
| OFF | Length x 1 -> 4 | 1 -> **4** (live) |
| ON | Length x 1 -> 7 | 2 -> **2** (dead) |
| ON | Min 0.25 / Max 8, three loops | **2.66 / 7.91 / 6.57** (live) |

**Why it matters.** This is the exact defect class T-0276 (Combine card), T-0277 (Posterise) and T-0281 (Jet ring dials) closed everywhere else in this window: a dial that cannot act is greyed with the condition in its tooltip. The cherry popover was never swept because it only exists behind a right-click.

**Not fixed under T-0288** because the popover is built by the SHARED panel `Editor/Pyre/PyreCherryPanel.cs:526-540`, a Pyre file this programme treats as read-only reference (PROGRAMME_RULES "Pyre's own files ... are read-only reference"). Fixing it there fixes Pyre's own cherry panel at the same time and needs its own verification pass in both hosts.

Suggested shape: `Length x` disabled while `useMinMaxLength` is on, `Min`/`Max` disabled while it is off, each with the condition in its own tooltip (`ZuiReflect`'s `Inert` pattern, which T-0284 already extended to stamp the reason onto a control's caption as well as its number).
