## Description

Coordinated upgrade of the agent-to-Unity-editor connection stack. Needs ALL Unity editors closed, so it was deferred on 2026-09-28. Everything below was researched and partly tested that day.

**Why:** Unity's official Claude Code plugin (skills only, no MCP server) targets Unity CLI 1.0.0-beta.10+. We run CLI 1.0.0-beta.3 with the Pipeline package (com.unity.pipeline) at 0.4.0-exp.1 in Laubrary Dev, Laubrary Dev - Shaper and OutBurner. Newer CLI + newer Pipeline give the Safe Mode recovery playbook, a screenshot fallback when a modal dialog blocks the editor, and skills that assume the newer command syntax.

**Hard constraint - CLI and Pipeline must move together, all projects at once:**
- CLI beta.11 needs the editor's Pipeline >= 0.6.0 for `unity command eval '<code>'`. With Pipeline 0.4.0 it fails with "package is too old to parse command lines". The beta.3 form is `--code '<code>;'`.
- Pipeline 0.8.0 binds loopback only (127.0.0.1:7800); 0.4.0 binds 0.0.0.0:7800. A 0.8 editor opened beside a 0.4 editor silently takes over its port and the 0.4 editor shows "unreachable" (401). Diagnose with netstat -ano | grep :7800.
- The built-in `unity upgrade` silently does nothing while other unity.exe processes (MCP servers of other Claude sessions) are running. Download the binary from the URL `unity upgrade --check --channel beta` prints (public-cdn.cloud.unity3d.com/hub/prod/cli/<version>/unity-windows-x64.exe), rename the old unity.exe aside, copy the new one in.

**Current state (2026-09-28):** active CLI is beta.3 at C:\Users\Lauta\AppData\Local\Unity\bin\unity.exe; the beta.11 binary is kept beside it as unity.exe.beta11 (beta.3 also kept as unity.exe.beta3). Laubrary Dev - Shaper's manifest was trialled on Pipeline 0.8.0 and reverted to 0.4.0. Pipeline 0.8.0 + beta.11 was verified on Shaper only: eval, console and 161 commands worked.

**Also done that day (nothing to redo):** ten Unity plugin skills copied to ~/.claude/skills and ~/.agents/skills (physics-3d-collision, urp-postprocessing, validate-urp-render-graph-renderer-feature, shader-graph-create-custom-node, manage-sprite-atlas, tilemap-palette-create, tilemap-ruletile-createempty, tilemap-ruletile-createfromsegment, localization, setup-multiplayer-services). The plugin itself is deliberately NOT installed (its /ui router conflicts with the ZUI policy; 29 skill descriptions would load every session). Findings are recorded in D:\Unity\UNITY_DEV_GUIDE.md (bullet "Unity's official Claude Code plugin") and the D--UNITY memory project_unity_mcp_vs_coplay.md.

**Watch out:** other Claude sessions run `unity mcp` over stdio from the old binary; restart them after the swap. Check beta.11's `unity mcp` still works with each project's .mcp.json (only `--project-path` is used there, no removed `--instance` flag).
