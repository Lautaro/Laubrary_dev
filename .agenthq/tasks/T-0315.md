## Description

**Filed by T-0313 (A27, ninth structural pass). Measured live at HEAD ae66d31c; write-up in `workspace/T-0313/A27-NINTH-PASS.md` sec 2.2, dump `out/togglebar-chunks-bar820.txt`.**

`ChunkWindow.minSize` is **(820, 520)** - the smallest the user can drag it. At exactly 820 the section bar's `ZuiSegmented` measures **1008.0px** and ends at x=1026.2 against a window root that ends at 820.0:

```
btn 'Sampled'      x=716.0.. 784.0
btn 'Cut Preview'  x=784.0.. 871.1   << off the window
btn 'Animated'     x=871.1.. 944.0   << off the window
btn 'Hits'         x=944.0.. 984.0   << off the window
btn 'Trail'        x=984.0..1026.2   << off the window (206.2px out)
```

**Four of Chunks' seventeen sections cannot be shown or hidden at all** until the window is dragged to >= 1026px; at 1000px `Trail` is still 26.2px off. The four audits also report it as 1 overflow-X (216.4px out of the bar's 799.6px content box) and 5 off-window findings at 820, 2 at 1000, 0 at 1400.

**Why it cannot self-correct.** The outer `ZuiSectionToggleBar` is `flex-wrap: Wrap`, but all seventeen buttons live in ONE `ZuiSegmented` whose own style is `flex-wrap: NoWrap`, `flex-grow/shrink: 0/0`, so the wrap the container offers can never engage and no button can give a pixel.

**Why no Shaper-only sweep ever saw it.** Same control, nine sections: Shaper's bar measures **636.0px at an 820px window** and fits with room to spare. This is a section-count threshold, not a Chunks-specific bug - any window whose section names total more than ~810px hits it.

Not measured: Pyre's own bar (it was not drawn in the state to hand), and whether any other tool crosses the threshold.

Scope: `Zui/Toolkit/ZuiSectionToggleBar.cs` / `ZuiSegmented` (a segmented group that can fold, or a bar that breaks its sections across rows), or Chunks' section roster. No serialized data changes.

**Technical details:**
Three changes:

1. `ZuiSegmented.Wrapping()` (new, opt-in) adds `.zui-segmented--wrap`. Nothing else in ZUI opts in, so every existing radio/multi group is byte-identical.
2. `ZuiToolkit.uss`, new block: `.zui-segmented--wrap { flex-wrap: wrap; flex-shrink: 1; }` — the shrink is load-bearing, not decoration: a wrap container's flex base size is the single-line max-content sum, so with the class's `flex-shrink: 0` inherited from `.zui-segmented` the wrap could never engage. Plus `.zui-segmented--wrap > .zui-segmented__seg { border-left-width: 1px; padding-left: 7px; }` so the first segment of a broken row is not left open where the strip's leading border used to be; the 1px comes out of the padding (8 -> 7), so the swap is width-neutral by construction.
3. `ZuiSectionToggleBar`: calls `_bar.Wrapping()`; its own container goes `flex-wrap: Wrap` -> `NoWrap` and `align-items: Center` -> `FlexStart`.
