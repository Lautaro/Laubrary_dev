## Description

Follow-up to T-0059 (commit b7cd69fa). The preview frame cache fills one frame per editor tick on the main thread — Arc Burst / Lichten at 128 px × 24 frames = 24 × ~360 ms ≈ 10 s wall. Frames are independent by the renderer's contract (pure `RenderFrame(spec, frameIndex)`; the only state between frames is the Fire/Fireball/sim replay harness). Render the fill on all cores so the wall time drops ~cores×, with byte-identical output to the serial path (0 px, every frame, every form), and the main thread stays responsive. Gate: a test that renders a multi-layer spec serially and in parallel and asserts every frame identical, several runs. Renderer thread-safety fixed at the source (statics → `[ThreadStatic]`, per-worker form isolation, main-thread-only layers fall back to the serial fill). GIF export untouched.

Standing rules: autonomous, never stall, commit after each verified milestone, log handovers here. Never touch the user's assets (temp probe assets only).

- `PyrePlusRenderer._layerSalt` (static int, written per layer, read by Eval's d-slot, sims, globals) → `[ThreadStatic]`.
- `_textReady` (static bool, written for EVERY layer in the loop) → `[ThreadStatic]`.
- `_plusFireEmitters` / `_plusFireSpawns` (static readonly List scratch filled by ComputeSpawns for every swarm-on form layer) → `[ThreadStatic]` lazily-created lists behind the same names.
- `_postReflectResolved` / `_simReflectResolved` + their MethodInfos (resolve-once flags) → `volatile` flags (idempotent resolve; benign race made explicit).
- `_fireSims` / `_plusFireSims` / `_fireballSims` (ConditionalWeakTable replay harnesses keyed by layer, frame N depends on N-1) → serial-only: Fire, Fireball, `simulationModifier` layers make the spec fall back to the serial fill.
- `_spritePixelCache` + `Texture2D.GetPixels32` (Sprite form), `ZuiFill.GetTexturePixels` (a Fill with `texture == Sprite`), TMP atlas snapshot statics `_textFont/_textSdf/...` + `AssetDatabase` auto-pick (Text — note `EnsureTextGlyphs` runs whenever `shapeForm == Text`, form or not), Playback3D (PreviewRenderUtility) → serial-only, main-thread APIs.
- `PlusFormDebug.FieldSink` (parity dump) → serial-only while a sink is installed.
- Forms' per-instance scratch (`ArcBurstForm` planes, `PlasmaBloomForm` `_E/_scratch/_fit`, Inferno/ForkBlast buffers) and every `Prepare`-stored dial, modifier instances' `Prepare` state → per-worker deep clones of the whole spec (`Object.Instantiate` on the main thread, `HideAndDontSave`; `[NonSerialized]` scratch resets exactly as on a cold load, which the cold-vs-warm contract already guarantees renders identically).
- `PlusPrepassCache` (CWT keyed by form identity, unsynchronised Entry) → made thread-safe (immutable snapshot per entry + a per-entry lock around `build`, so N workers missing at once build ONCE and the rest wait) and keyed by `PlusForm.PrepassIdentity`: a worker clone is linked to its origin form so the Plasma fit / clip stats computed by the main thread's first frame are SHARED, never recomputed per worker. Duplicated layers (the editor's Clone) are NOT linked — they keep their own entry as before.
- `PlusSupersample._scratch` already `[ThreadStatic]`. `PlusNumpyRng` / `PlusPyRandom` are instantiated per draw inside Render (never shared). `Gradient.Evaluate` / `AnimationCurve` are thread-safe in Unity's bindings (`IsThreadSafe = true`) — verified empirically by the test (gradient fills on worker threads). `Mathf`, `System.Random`, `Debug.Log` safe. No `Mathf.PerlinNoise` / `UnityEngine.Random` / `Time` anywhere in the PyrePlus or modifier per-frame path.

**Design decisions (taken without asking):**
- Predicate `PyrePlusRenderer.IsParallelSafe(spec, out reason)` in the core: false for Fire / Fireball / Text / Sprite / Playback3D / an enabled simulationModifier / any Fill (shape, border, background) with a Sprite texture / an installed FieldSink. The Kiln forms are parallel-safe.
- New core class `PlusFrameFill` (Runtime/PyrePlus/PlusFrameFill.cs): K dedicated background threads (not the ThreadPool), each owning one spec clone, pulling frame indices from a shared counter in the requested order, pushing `Color32[]` results to a concurrent queue; the main thread drains with `TryTake` and uploads (`SetPixels32`/`Apply`). Cancellation token checked between frames; an in-flight frame finishes and is discarded. Clones destroyed on `Dispose` (main thread, after the workers exit). `RenderAll` = blocking convenience for tests.
- Editor: the on-screen frame still renders synchronously first (the "current frame first" rule), then the fan-out covers the rest. The fill object is replaced on every invalidation — stale results stay in the dead object's queue, so a stale frame can never land in the new cache. While a cancelled fill's workers are still mid-frame (a dial drag), no new fan-out starts — bounded thread count under a drag. Cheap specs stay serial: if the first frame's time × remaining frames is under two tick budgets, the thread overhead is not worth paying (the 64 px Disc rule).
- Workers = `Environment.ProcessorCount - 1` (min 1).
- GIF export left serial.
