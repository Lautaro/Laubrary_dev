**Technical details:**
Mechanism: [ZUILabel(string)] / [ZUIGroup(string group, string Tooltip = null, bool Advanced = false)] -- both already existed from T-0235 (Zui/Scripts/Runtime/ZUILabel.cs, ZUIGroup.cs), nothing new added to ZUI. A group's box is created where its first member is declared and keyed by owning TYPE (ZuiReflect.EmitGroup), so the SAME group name string reused across ArcBurstForm's 10 layout classes or across Jet's per-family settings classes produces separate, independently-foldable boxes rather than merging them -- verified by reading ZuiReflect.cs:311-325 before relying on it, not assumed.

All edits were produced by a small local Python script (scratchpad only, not committed) that: (1) matches each field's `public Type name = value;` declaration line via regex, (2) walks backward to find that field's own [Tooltip(...)] line (whether on its own line, as in most forms, or combined on one line with [Range]/[Tooltip]/public as ArcBurst's per-layout classes use), (3) inserts the new [ZUILabel]/[ZUIGroup] line immediately after the Tooltip (or immediately before the combined line when there is no separate Tooltip line), matching the surrounding indentation. Guarded against two real hazards found while building it: (a) a naive 'previous line starts with [' backward-scan walks straight through a PREVIOUS field's combined '[Range(...)] public ... = ...;' line since it also starts with '[' -- fixed by stopping at any line containing 'public '; (b) several forms declare a `public struct Live { public float a, b, c; }` one-liner immediately after the real fields, whose comma-joined field list can otherwise regex-match as if it were one of the real field declarations -- excluded any line containing 'struct '/'class '/'{'/'}'.
