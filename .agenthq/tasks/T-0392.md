## Description

**Owner request (2026-09-21), after asking why Mirage's PPU wasn't given the same treatment as today's Chunks fixes (T-0390/T-0391):** "Is there any reason to keep it [as a one-time snapshot]? ... I want it to also change." Agreed after re-examining: there is no real tradeoff — the override capability survives the conversion unchanged (an author can still pin a view to its own PPU), the only thing that changes is the DEFAULT stops silently going stale.

**What changed, by hand, this session (verify + commit; do not re-derive):**

1. `Runtime/Mirage/MirageView.cs` — `displayPixelsPerUnit` renamed to `displayPixelsPerUnitOverride` (`[FormerlySerializedAs("displayPixelsPerUnit")]` — a real rename of a real serialized field this time). Added `useProjectPixelScale` (bool, default true) + `EffectivePixelsPerUnit`, same shape as `DebrisScatter`/`FragmentFracture`/`PaletteSplash`. `CreateTransient` no longer needs to seed anything for the common case (the toggle already defaults to tracking the project setting) — it still seeds the override field with a sane starting value for whoever later turns the toggle off.
2. `Runtime/Mirage/MirageRig.cs` — both read sites (`ApplyBackdrop`-ish backdrop scale, `ApplyScale`) changed from `view.displayPixelsPerUnit` to `view.EffectivePixelsPerUnit`.
3. `Editor/Mirage/MirageWindow.cs` — `InitializeNewAsset` updated to the new field name (seeds the override, not the toggle — toggle's C# default already does the right thing). The "Display PPU" row in `BuildViewRow` replaced with a "Use project pixel scale" toggle + conditional override field + live readout, same UI pattern as `ChunkWindow.DebrisScatterCard.cs`.

**Verified by hand (re-verify, don't just trust):** `Assets/Mirage/MirageDemo.asset` and `Assets/Mirage/Test 2.asset` both currently serialize `displayPixelsPerUnit: 16` — already equal to the project's own Pixel Scale (16), so this migration should be a pure no-op for both: they'll deserialize as `displayPixelsPerUnitOverride: 16` (dormant, since `useProjectPixelScale` defaults to true on a field that's absent from their YAML) and `EffectivePixelsPerUnit` will still return 16 either way. No visual change expected for either asset.
