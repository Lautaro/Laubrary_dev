THE MODEL. One clock in SECONDS. Three consecutive bands: ACTIVE [0, active) stack applied, life = t/active, active = PreviewSeconds(spec); HOLD [active, active+hold] stack STILL applied frozen at life 1; GAP (active+hold, total] stack BYPASSED (plain sprite, what SpriteFxFilter.Restore leaves behind). One helper is the only resolver -

    void ResolveAt(float t, out float progress, out bool bypass)
    {
        float active = ActiveSeconds(spec);           // floors at 0.001, never divides by zero
        float hold = Mathf.Max(0f, HoldEnd);
        float total = active + hold + Mathf.Max(0f, IdleGap);
        t = Mathf.Clamp(t, 0f, total);                // CLAMPED not wrapped - the bar's right edge must mean
        if (t < active) { progress = t / active; bypass = false; return; }   // the END of the loop, not the start
        if (t <= active + hold) { progress = 1f; bypass = false; return; }
        progress = 0f; bypass = true;
    }

Both scrubbing and playback go through it and nothing else, so the two can no longer disagree - which they could, and did, when hold/idle ran on separate state. Returns PROGRESS not life on purpose: RenderPreviewAt is the single place that turns progress into life because it is also the place that inverts it for Reverse, and progress must keep running forward for SubjectFrame even when life runs backward.

REMOVED: the 0..1 'Life' MicroSlider (_lifeSlider), and the whole _previewHeld / _previewPause / _previewIdle / _previewIdleLeft / _playProgress state machine, replaced by _scrubTime (resting) + _playTime (transient), both seconds. Verified repo-wide: no orphaned references remain.
