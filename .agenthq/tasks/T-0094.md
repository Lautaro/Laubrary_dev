## Description

Step 5 of the build plan from `D:\UNITY\Laubrary Dev\ZOE_PALETTE_BUILD_PLAN.md` (task 5 — read that file and `D:\UNITY\Laubrary Dev\ZOE_PALETTE_TAKE.md` in full before starting). Must land before T-0095 — not because it's technically blocked by other tasks, but because authoring the first real death look (which T-0095 makes possible) is exactly what turns this bug from dormant to an everyday occurrence.

Plain-language: if a character is partway through reacting to being hurt and a stronger reaction (dying, or a new action) takes over, the hurt reaction is currently just cut off — dropping any queued effects and never sending its "I'm finished" signal. This is invisible today only because no character has both a hurt look and a death look authored yet.

Cover: attach the toolkit's existing interruption/priority-arbitration mechanism to every character (currently it's only attached to characters with authored directional movement, and only one thing uses it — this is more work than "wire it up," it needs attaching plus routing three things through it: reactions, plain movement, and named states). State an explicit priority ladder (death outranks hurt, hurt outranks ordinary states) rather than relying on "higher priority wins," since an equal-priority newcomer currently takes control from an existing reaction. Make sure whoever requested an interrupted reaction is told it was interrupted, instead of assuming it completed. Stop dropping an interrupted reaction's pending effects and completion signal.

Recommend shipping this alone, with nothing else in the same update to any consuming project, since it's the one genuine behaviour change in this whole plan and is worth watching in isolation.

## Handover Log

### 2026-08-26T13:34:23Z — agent — todo -> done
Characters can now actually show a reaction, and the toolkit has one clear rule about what is allowed to interrupt what. The headline discovery: on a character built from separate parts — which the ProtoGuy demo character is — no hurt look, death look or named look could EVER play, and every effect timed to a particular animation frame was silently dead. That is now fixed, along with seven other faults found by an independent review of the first attempt.
**Details:**
How to use this: nothing to operate. The rule is simply that dying beats being hurt, being hurt beats an ordinary named look, and an ordinary named look beats plain walking around. Something already playing is no longer cut off by something arriving at the same level of importance.

Also fixed in the same pass: a character that played a death animation could never move again after being brought back to life; a misspelled animation name on one reaction used to destroy a different, perfectly valid reaction that was already playing; walking could stomp a hurt reaction through a side channel that ignored the rule; three places pushed animations straight to the character while bypassing the rule entirely; the three kinds of reaction disagreed about how they report 'this didn't play'; and the 'wait a while, then clean up the body' option started its countdown at the moment of death instead of when the death animation ends, which cut long death animations short.

One visible change you should expect: ProtoGuy's muzzle flash now spawns at the painted muzzle point on the gun rather than at the middle of the character, because the effect can finally read the character's own view.

Deliberately left for the next task: telling a reaction to speak for one specific body part ('this look is for the legs only'). What works today is that a look plays on whichever parts actually have that animation, so 'walking legs plus a firing upper body' is already expressible by drawing the animation on one part only.

Not yet verified by eye: nobody has walked the character around with a gamepad since this change. The automated check confirms both halves of the body still have their own working animation drivers and that the demo runs without a single error, but a human has not looked at it moving.

This change is not committed to version control yet.
