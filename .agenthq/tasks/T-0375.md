Scoped the real-hit Play-mode rig for UC4-6. Key finding: Health.Kill() (used in the T-0347/348/349 walks) is not a shortcut that skips real behaviour -- it calls the exact same Health.ApplyDamage path a real weapon hit does, firing Damaged (Hit reaction) then Died (Death reaction) in the same order and reading the Zoe's live sprite/frame the same way. So the walks' Hit-before-Death sequencing and live-frame sampling already ARE representative of a real hit; T-0348's open question about death-without-a-preceding-Hit cannot happen in this codebase at all (Health has no path to Died that skips Damaged). The one real difference a real hit adds: a genuine attacker-to-target direction, which drives burst aim on cards with 'Inherit burst direction' on (UC5/UC6 Fragment Fracture) instead of falling back to the recipe's authored default -- a correct improvement, not a bug to fix. Best of all: ProtoGuyDemo.unity already wires the exact rig needed (ProtoGuySpawner with a real 2-weapon loadout firing at FlyingDiscSpawner-spawned real Floating Disc Zoes, health overridden low so they die in a few real shots) -- no new pipeline or recipe code is needed, only duplicating the Floating Disc asset (reuse UC Floating Disc (walk copy).asset) and pointing its Death row at UC4/5/6 in turn inside a copy of that scene.
