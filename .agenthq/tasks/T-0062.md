Findings that shape the design: (1) `Put` is pure MAX on both planes, so deposits commute — but `FadeAngular` / `Hollow` / `ScaleAlpha` / `Bloom` are full-plane multiplies applied BETWEEN deposits inside a draw (Weave's shutter, Pinch's sweep, Lichten's hollow), so a collector must flush before each of them and at the end of the frame — the flush points are where the order matters, nothing else. What changed (all inside `ArcField`, all bit-exact): (1) **the skip test in `Seg`** — `Put` is a pure maximum, so a pixel whose E and A already sit at or above the most this stroke could deposit there is a no-op; the stroke's bound comes from two monotone tables sampled below the true argument (a shared 4096-entry `exp(−x^1.7)` over x ∈ [0, 64], a per-field 1024-entry `pow(a, agamma)`) widened by 1e-5, so they are upper bounds even if the CRT's exp/pow are not monotone at the last bit; a skipped pixel costs a sqrt and two table reads instead of pow + exp + pow. Overlap is the common case (a channel's core inside its own sheath, crossing branches, swarm stacks) — that is the 2×. (2) **`Blob` scans a bbox** of radius `rs·max(profile)` (+1 px) instead of the whole plane: outside it u ≥ 1, the soft edge clamps e to exactly 0 and `Put` is not called. The far-field early-out the brief suggested is empty: the source's bbox pad `3·width + 2` already stops at `exp(−3^1.7) ≈ 1.5e-3` of the amplitude, far above where the float rounds to zero (x ≈ 15.5 widths), so a "rounds to zero" bound never tightens it — derived, not guessed. Exact `Math.Exp` / `Math.Pow` / `Mathf.Pow` are kept; the falloff-LUT and gamma-LUT replacements are deferred to step B where float drift is accepted anyway (decided without asking).
**A real gotcha found on the way (Crown's hash moved, E28A6428 → 37F9CD1F, with every new branch disabled):** Mono evaluates `Math.Pow(d * invW, 1.7)` with the float product promoted to double UNROUNDED, while `float xw = d * invW; Math.Pow(xw, 1.7)` rounds it first — a last-bit change that survived into Crown's bytes. Verified by stashing to the original (E28A6428 twice), then restoring the inline product (all ten hashes back to BEFORE). Consequence for step B: even the non-transcendental arithmetic of a managed kernel is not guaranteed to match Burst (which rounds every float op), which is one more reason the Burst kernel must be the only path. The inline form is kept with a comment.
