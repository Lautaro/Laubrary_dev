## Description

**Owner's design, in his words:** "I wanted LFO to work in 2 modes. A) starts when Zound is triggered. B) oscillates all the time and wherever it is when audio is played will get the current value. The envelope is an exception since it always modifies the modification in sync with Zound being triggered."

- **Mode A, restarts on play:** each play starts the oscillator from the same point of its cycle.
- **Mode B, always running:** the oscillator runs on its own clock whether or not anything plays; a play picks up wherever it has got to.
- **Envelopes are excluded:** they always follow the sound's own trigger.

**Surfaced in:** T-0426, where 'a sine looks like a ramp' was traced to the display. That diagnosis stands; this is new design scope.

**Plan:** establish what the engine does today, by reading the code and measuring; make any missing mode real; give the choice a real, clearly labelled control on the LFO; verify by measurement and by eye.

### 2026-09-27T14:50:27Z — agent — in_progress -> done
Done. Both of the owner's modes are real, selectable, and verified.

WHAT WAS THERE ALREADY (established by reading the code, then measuring):
- For an oscillating LFO, both modes existed, behind the 'Reset phase' on/off. On = mode A: every play starts at the top of the cycle. Off = mode B: when a play starts, its phase is worked out from a clock that never stops (elapsed real time multiplied by the rate), so it lands exactly where a continuously running oscillator would be. Measured with three plays 300 ms apart: mode A started 0.006, 0.006, 0.006; mode B started 0.918 / -0.198 / -1.000 against a continuously running sine's 0.920 / -0.191 / -1.000. This was already covered by kept check 9, which still passes.
- What was missing: (1) the choice was presented as an unexplained 'Reset phase' on/off, which the owner did not recognise as these two modes; (2) in the LFO's Random mode (gliding between random values) the setting did nothing. Every play started its own fresh random walk, so there was no mode B at all.

WHAT CHANGED:
- The control is now 'Runs: Always | Per play', a two-option choice laid out like Shape and Mode, with an explanation of each option on hover. Stored values are unchanged (Per play = 1, Always = 0), so every existing sound behaves exactly as before; the owner's sound shows 'Always', which is what his old toggle was set to.
- Random mode + Always: every play of that oscillator now follows ONE random walk that runs all the time. Time is cut into intervals of the 'New target every' length; each interval's target is a fixed function of the interval's number and a seed from the sound's name and the oscillator's position, so every play computes the same walk without sharing anything. A play that starts mid-walk replays the unfinished glides before it, so it lands where a play that has been running all along is.
- Choices made without asking, noted here: (a) mode B's clock is elapsed real time, which keeps running in the editor and in a built game whether or not audio plays; this is what the Oscillate side already used, and is kept for consistency. (b) In mode B the phase is derived from the clock, so changing the Rate moves where the oscillator is, rather than continuing smoothly from where it was. (c) Two different oscillators wander independently; the same oscillator on the same sound always follows the same walk.
- Envelopes are untouched, as asked. The new control's hover text notes that an envelope always starts with the play, so it has no such choice.
- The analyser always draws an oscillator as if the play started at the top of its cycle. For an 'Always' oscillator its tooltip now says so, and that the playing sound's dot shows where a real play is.

VERIFICATION:
- By probe: the oscillate measurement above. Random + Always: a play started 300 ms after another started at -0.0717 where the earlier play was at -0.0747 (the step either side is 0.005 away, i.e. within the timing jitter of reading the clock) with partial glides; at a slower glide -0.0938 vs -0.0935; with no glide, exactly equal. The walk genuinely wanders (-0.60 to 0.57 over 2 s). Per play is unchanged.
- Kept check 9 now includes the Random/Always case and passes. A negative control (the same check with Per play) fails it as it should: -0.780 vs -0.081.
- By eye: the new 'Runs: Always | Per play' control in the real Klip Editor, laid out consistently with the neighbouring choices.
- NOT verified: (a) hearing it (T-0414 is the owner's by-ear gate); (b) the Random/Always change in a built player, where the audio code is compiled ahead of time. It is in the package assembly, the same place as the rest of the compiled audio code, but no player build was made for this change; (c) the new hover text on screen.
