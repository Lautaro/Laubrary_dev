**Request (Lautaro, 2026-09-07 00:15, live in `Assets/Demos/ProtoGuyDemo/ProtoGuyDemo.unity`):** "The muzzle flash effect should rotate so that its directional in the same direction the bullet fires. How do we configure that? The fire event should have a fire direction parameter and when an event spawns a pyre it should be possible to set its position (muzzle layer) and its rotation. This should be configurable in Zoe."

**Context you can build on (landed tonight, uncommitted):** T-0238 added `Runtime/Zoetrope/IPartLookup.cs` (declared body-part lookup, implemented in `Runtime/ZoetropeLaunimator/CompositeZonedPlayer.cs`) and a "Target Part" picker in `Editor/Zoetrope/ZoetropeWindows.cs`. ProtoGuy's parts are declared in `Assets/Demos/ProtoGuyDemo/ProtoGuy.asset` (Legs, Upper; the fire flash attaches to `Upper` via `attachToPartName`). The Pyre-spawning reaction path is `Runtime/ZoetropePyre/` + `Runtime/Zoetrope/EventContext.cs` / `NamedReaction.cs` / `CueBinding.cs` / `ReactionFxPlayer.cs`.

**What to build, in order:**
1. **Fire direction on the event.** The Fire event (raised by ProtoGuy's shooting code — find it: `ProtoGuy.states.cs`, `DemoWeaponSwitch.cs`, ZoeCombat / Combat2D / Lazor) must carry a `direction` (Vector2, normalised, the bullet's actual travel direction, aim included) in its `EventContext`, so every reaction can read it. Make it a general, named event parameter, not a ProtoGuy special case — other events (hit, death) will want a direction too.
2. **Event-spawned Pyre placement, configurable in Zoe.** Where a reaction spawns a Pyre (or any effect prefab), add per-reaction settings editable in the Zoetrope window: (a) **position**: anchor to a declared body part (reuse the Target Part / `IPartLookup` seam — the "muzzle" is a part or a named anchor on a part; if parts have no anchor points yet, add a minimal named-anchor concept with a local offset) plus a local offset; (b) **rotation**: `None` | `Face event direction` (rotate the spawned effect so its +X points along the event's direction, with an optional angle offset) | `Fixed angle`; (c) **flip** with the body's facing when applicable, so a left-facing shot mirrors correctly rather than rotating 180°.
3. **Wire it for ProtoGuy** in `ProtoGuy.asset` / `ProtoGuy Fire Flash.asset`: the muzzle flash anchored at the gun muzzle on `Upper`, rotated to the fire direction. Check what the Fire Flash Pyre's authored "forward" is and set the angle offset accordingly.
4. **Verify:** compile clean; edit-mode tests that (a) the Fire event context carries the direction, (b) the spawn rule produces the expected rotation for a few directions and the mirrored case; Play-mode in ProtoGuyDemo: fire right, fire left, and (if aiming exists) diagonally — capture frames and ATTACH them to the task (the previous task claimed a capture that never got attached; attach for real). Report verified-by-probe vs verified-by-eye separately.

**Constraints:** don't touch OutBurner, don't retouch art. Keep the API in line with the Laubrary skill's authoring rules; CHANGELOG entry. Pyre itself (`Runtime/Pyre`, `PyrePlus`) stays untouched unless a rotation hook is genuinely missing — say so if you add one. This is part of his ProtoGuy to-do list (`.agenthq/planning/ProtoGuy.json`); the same spawn-placement rule will be reused by the disc hit/death effects next.
