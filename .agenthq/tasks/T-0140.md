## Description

User feedback, direct: (1) a screenshot of ZuiGradientControl's 'Adjust' box showing Hue/Saturation/Brightness/Contrast/Phase/Quantise stacked one-per-row -- the same row-packing anti-pattern flagged earlier this session, but this time inside a SHARED ZUI control (Assets/Packages/Laubrary/Zui/Scripts -- ZuiGradientEditor), not mock-only code, so the fix benefits every consumer (Pyre's SpriteFx included). (2) User asked where the generator menu was -- answered (Shape section header caret, Composite kind only), no code issue found there. (3) User's own instinct that the Layers UI reads as empty turned out to be RIGHT and led to a real structural finding: the real ShaperLayer class (ShaperLightRig.cs) has response (ShaperLightResponse), zOffset (ZUIValue), and height (ShaperHeightDef, extrusion/bevel) as PER-LAYER fields. ShaperNode.cs has NONE of these -- confirmed by a direct grep returning zero matches. The mock currently builds 'Lighting response' and 'Extrusion' on EVERY node's own card (BuildShapeSection/BuildLightResponseBox, called per-node including bag members), which is structurally backwards: these are real per-LAYER authored data in the engine, not per-node, and repeating them on every node inside a bag misrepresents the real model. zOffset is also simply missing from the mock entirely.

Fix: (a) pack the shared ZuiGradientEditor 'Adjust' box's 6 fields into 2-3 per row. (b) Move 'Lighting response' and 'Extrusion' from per-node placement to a per-LAYER card, likely shown once per layer (in or near the Layers section, or when the layer ROOT node specifically is selected -- read the real ShaperLayer/ShaperNode classes fully before deciding exact UI placement) rather than repeated on every node in a bag. (c) Add the missing zOffset field to each layer's own row in the Layers section, as a Z.Value (it's already ZUIValue in the real engine).
