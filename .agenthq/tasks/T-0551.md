TRAP, cost real time: ZuiToolkit.uss has `.zui-root .unity-base-field { flex-grow: 0; flex-shrink: 0; }`. A one-class semantic rule cannot outrank it, so .zui-row__name applied its width and min-width but silently NOT its stretch, while every class was demonstrably present on the element. The rule is written `.zui-root .zui-row__name` for that reason. Check resolved values, never the class list.

TRAP 2: the Unity CLI's eval does not refresh the AssetDatabase, so an edited .uss is not reimported and a probe silently measures the old sheet. Call AssetDatabase.Refresh() first.

TRAP 3: opening, closing and resizing an editor window only completes when Unity pumps its loop, and Thread.Sleep blocks that very loop. The harness is therefore a stepped queue (D:/UNITY/Laubrary Dev/Assets/Editor/UISeparationPhase3/Phase3Run.cs) driven one external call per step; a single-call loop photographed every window one step stale. Also, an AssetKit window restores its last asset on open, so an 'empty' capture is not empty unless SetAsset(null) is forced.

Harness: D:/UNITY/Laubrary Dev/Assets/Editor/UISeparationPhase3/ (Phase3Capture, Phase3Run, Phase3SurfaceWindow - the last hosts a ScriptableObject's custom editor because Unity's own property editor would not build its contents for a scripted fixture).
