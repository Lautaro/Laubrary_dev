## Description

**Found by T-0276's cold walk, and half-fixed there.** Pressing **New** in any AssetKit window ran `AssetDatabase.SaveAssets()`, which writes EVERY dirty asset in the project - so creating a Shaper document also published whatever unsaved edits another window happened to be holding. That is not a theory: during T-0265 `Assets/Demos/ShaperDemo/ShaperDemoDoc.asset` was written to disk by a task that never edited it, and its handover already guessed the cause ("a probe which saves ANY asset can publish somebody else's unsaved edits"). The mechanism is this call, and it is in the SHIPPED window, not only in probes.

T-0276 narrowed the four on the path it walked - `ZuiAssetWindow`'s Create-confirm (Editor/AssetKit/ZuiAssetWindow.cs:271) and `AssetLibrary<T>.Create/Duplicate/Rename` (Editor/AssetKit/AssetLibrary.cs:45,56,67) - each to `AssetDatabase.SaveAssetIfDirty(<that asset>)`. Compiles clean; New/Duplicate/Rename still work.

**Left alone, and this card is for them:**
- `Editor/AssetKit/LaubraryAssetWindow.cs:199` - the IMGUI-era asset window's own save path.
- `Editor/AssetKit/LauTagPicker.cs:220, 239, 256` and `LauTagLibraryProvider.cs:32` - the tag side-table's create/rename/delete.
- `Editor/Shaper/ShaperBaker.cs:342` - Bake flushes the project after writing the sheet, the AnimationClip and the ShaperClip. This one carries real regression risk (T-0275 measured full bake parity with the call in place), so it needs the created assets flushed individually and then re-measured against T-0275's bake-parity table, not a blind substitution.

Each is one line; they are a separate card because they sit outside Shaper's own files, they reach ten tools, and the baker's needs re-verification rather than substitution. The measurement that proves the class: T-0276 drove the window's own **New** button through a real `NavigationSubmitEvent`, watched the two-step Create row appear, typed a name, pressed **Create**, and read the call chain - `AssetLibrary<T>.Create` -> `SaveAssets()` -> `InitializeNewAsset` -> `SetDirty` -> `SaveAssets()` again: twice over the whole project for one new asset.
