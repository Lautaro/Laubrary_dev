## Description

Measured live 2026-09-08 (changed pixels summed over frames 0/4/8/12, swarm on, count 8, spawner radius 24).

`spawnOrderChaos` is drawn as 'Appearance order' only inside the Window and FrameStep branches of BuildSwarmTimingBox (Editor/Shaper/ShaperWindow.Sections.cs:1669-1671). The Stagger branch returns before it. Measured against what the engine actually does:

                     shape = None        shape = Circle
  timing Stagger     0 px, not drawn OK  4224 px, NOT DRAWN  <-- live and unreachable
  timing Window      0 px, DRAWN LIVE    6774 px, drawn OK
  timing FrameStep   0 px, DRAWN LIVE    6354 px, drawn OK

So the rule is inverted on both sides: hidden where it works, drawn ungreyed where it is inert. With a spawn shape authored and the default Stagger timing - the state a new swarm starts in - a dial that moves 4224 pixels can only be reached through the raw Inspector, which is the exact failure the section's own Merge-carve comment calls out ('left editable from the Inspector and invisible here').

ROOT: the permutation it drives is built whenever a spawn shape exists (ShaperCompiler.cs:465, `placed || swarm.spawnOrderChaos > 0f`), so with a shape it re-assigns which instance sits at which position regardless of timing. The field's own doc comment (ShaperSwarmDef.cs:188-190, 'Observable only when timing gives instances distinct birth moments') understates that, and the card's branch placement follows the comment.

EVERYTHING ELSE IN THE SECTION CHECKS OUT: every other hidden dial measures 0 px in the state that hides it (spawnerRadius, distribution, spawnerOffsetX, orient, scaleByIndex under shape=None; pathSpread and pathProgress under Area; instanceLife, dieTogether, firstSpawnPhase under Stagger), the two genuinely inert controls (Merge carve, Instances mix) are greyed with their reason in their own tooltips in every state, and no swarm control is drawn without a tooltip in any state.

NOT MOVED HERE: which box a control belongs in is an authoring decision. The likely fix is one line - draw 'Appearance order' in the common part of the timing box rather than only in the two branches, greyed with a reason while shape = None. Full state table in workspace/T-0303/A25-SEVENTH-PASS.md section 2.

CHANGELOG: Shaper: the swarm's "Appearance order" is drawn under every timing and greyed with its reason when there is no spawn shape, instead of being hidden where it works and live where it does nothing.

The rule was inverted on both sides, and it followed the field's doc comment rather than the engine. spawnOrderChaos drives a permutation the compiler builds from the SHAPE, not the timing (ShaperCompiler.cs:465, `placed || swarm.spawnOrderChaos > 0f` with `placed = swarm.shape != ShaperSwarmShape.None`), so with a shape authored it re-assigns which instance sits at which position under every timing mode - Stagger included, where each instance still carries its own clock offset and its own index-driven size, so swapping them is visible.

The dial is now built once, before the timing branches, and added to all three; when shape = None it is declared inert through the section's existing Inert(...) helper, which disables it, puts the reason on it and prepends that reason onto its caption's tooltip (StampReason). Nothing was moved to another box, no control was added, no serialized field touched. ShaperSwarmDef.spawnOrderChaos's own doc comment - the source of the wrong rule - was corrected to state what the compiler does.
