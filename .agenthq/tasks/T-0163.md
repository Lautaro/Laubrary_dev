Shaper effects are authorable and they run. An effect entry now carries a real serialized modifier instance instead of a type name, so its dials are yours and not the class defaults every render used to rebuild; the dials are drawn per effect in a foldable card with a reorder grip, an enable toggle, a remove x and Undo on every edit, the same card Pyre's modifier stack uses.

There are two lists, and an entry's stage is which list holds it rather than a dropdown that can disagree with the renderer. A new per-layer 'Layer effects' section runs on that layer's own picture before it composites; the document's 'Effects' section runs on the finished picture after every layer has folded in. Each row says its stage in words.

26 of the 41 catalogued effects now run, at EITHER stage: the 10 whole-frame Post passes (bloom, outline, drop shadow, dissolve, chromatic aberration, ballistic shockwave, fuse, edge smooth, kaleidoscope, relight), the 9 buffer-only Pixel kernels (contrast, brightness, saturation, posterize, colour tint, colour replace, colour remap, ordered dither, wipe) and the 7 geometry warps (skew, scale, rotate, wobble, curl progress, smudge, pin warp). The other 15 are offered GREYED with the engine's own reason: 13 need per-pixel coverage/edge-distance sheets that a folded picture does not publish, Edge Warp is structurally stuck, and Pixel Fluid is a stateful simulation whose step hook only the Pyre assembly may call.

Before this, ZERO of the 41 ran. The known half was the stage mismatch; the half nobody had recorded is that the applier cast every effect to PixelModifier, which fails for all 10 Post entries, all 17 Geometry entries and the Edge and Simulation ones, so even a correctly-staged bloom was dropped by an `as` returning null. That path is gone: applying a list now calls SpriteFxStack.RunStack, the shared SpriteFx kernel that dispatches every family in authored order and resolves each modifier's ZUIValue dials against the Shaper phase. So an animated dial moves over the animation instead of freezing.

One cost is real and named rather than hidden: a layer carrying an enabled effect leaves the premultiplied-float composite for one 8-bit round trip (encode, run, decode), which cannot carry an additive glow whose premultiplied colour exceeds its alpha. A layer with no effect never enters that path, so every existing document renders bit-identically.

One thing to know before you look: the document 'Effects' section is currently OFF in this editor's saved toggle-bar arrangement (it was turned off when it was a useless read-only catalog). Turn 'Effects' back on in the Toggle Bar to see the document list. 'Layer effects' is a new label so it defaults on.

Per-layer list: ShaperLayer.effects (Runtime/Shaper/ShaperLightRig.cs:371).

Renderer (Runtime/Shaper/ShaperDocumentRenderer.cs): RenderPhaseInto gained an optional IShaperEffectApplier (added LAST in the parameter list, after T-0165's `pool`, so no existing call site moved). Execution (Runtime/PyreShaper/ShaperEffectApplier.cs): the private ApplyInPlace loop is DELETED. Apply collects enabled, resolvable, stage-legal instances and calls SpriteFxStack.RunStack once (managed, not Burst -- the Burst path copies the whole buffer into a NativeArray and back per batch, which is a real per-frame cost on a canvas this size and one more thing that could differ between preview and bake). `life` is the Shaper phase; `frame` is a phase-derived stamp (phase is a fixed function of the frame via ShaperClock, so it is deterministic and distinct per frame, which is all the hash-per-pixel Post effects need of it).

Availability (ShaperEffectRuntime.CanRun): three gates, each a real property of shipped code. (1) ShaperEffectCatalog.IsAvailable asked with the sheets a folded picture publishes -- none -- which greys the 13 NeedsSheets entries with the catalog's own wording and EdgeWarp as Stuck. (3) what RunStack dispatches: SimulationModifier.EnsureFrame is `internal` with InternalsVisibleTo(Pyre) only (Runtime/SpriteFx/AssemblyInfo.cs), so Shaper cannot step PixelFluid and says so instead of adding an inert row.

T-0114's ShaperEffectStageRunner.ApplyInPlace had the same static-only Prepare bug T-0167's handover flagged; it now Prepares with SpriteFxStack.LifeEval too, so the stage-comparison proxy and the production path read a dial identically.
