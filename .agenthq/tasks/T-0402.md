### 2026-09-22 — agent — root cause + fix + verification
**Root cause (measured, not inferred): `Assets/Pyre/Imported/Driectional Blast Plus.asset` was live in the editor with `anchorEnabled=false`, `anchorKind=Position`, `anchorOrigin=(0.4939, 0.5017)` — dirty and unsaved — while disk and HEAD both still held the correct `anchorEnabled: 1`, `anchorKind: 1` (Vector), `anchorOrigin: (0.5, 0.390625)`, `anchorDirection: (0, 1)`.** With the anchor off, `PyreAnchor.ForwardLocal` returns its documented `Vector2.right` default, so a blast whose art points UP was rotated as if it pointed RIGHT — the flash drew 90° counter-clockwise of the barrel on every shot, for BOTH characters (they share this blast asset).

**Ruled out first, with real numbers:**
- *Painted data* — live vectors are an exact 22.5° ring (f0 = 90°, f4 = 0°, f8 = 270°, f12 = 180°), matching `DirectionMode.Rotation`'s convention; a 16-cell contact sheet with each vector drawn over its own baked frame shows every arrow on the drawn barrel.
- *Frame mapping / zone structure* — both rigs' `UpperAim16` sets are byte-equivalent (`Rotation`, 1 member, `mirrorBuiltIn` false, `snapStepDeg` 0); aim → frame came out 0°→4, 90°→0, 180°→12, 270°→8, 45°→2, 225°→10.
- *Read path* — live in Play mode, `Upper` on frame 4, `flipX` false, no rotation, unit scale; `MuzzleVectorTracker.CurrentDirection` = (1.00, 0.00). Correct at every step.

**Fix:** the four anchor fields restored to their committed values and the asset saved. **No source file changed.** No sign-flip or offset was applied anywhere.

**Verified (ProtoGuy New, Play mode):** E/N/W/S/NE/SW — flash world forward (recomposed from the spawned blast's `transform.rotation.z` + `SpriteRenderer.flipX`) vs tracker direction, **err = 0.0° in all six**, plus screenshots of each.
**Old-rig regression (ProtoGuy.asset, spawned at runtime, same six):** **err = 0.0° in all six.** It had been equally broken while the anchor was off.

**Also saved + committed:** the owner's 16 hand-painted `Muzzle` vector frames existed only in editor memory (`ProtoGuy New_draft.asset` on disk had zero authored frames). Now persisted — closes T-0400's open "Muzzle layer still needs a repaint" caveat.
