**Details:**
How to use this: nothing changed about how you open or operate it -- Laubrary > Lazor > Lazor, same drawing canvas, same tools. The left-hand panel is now made of the standard controls, the zoom readout and Fit button moved out of the canvas into the window's own top bar, and the panel divider is draggable as before.

What got fixed while walking through it: the delete (X) button on a layer row was clipped off the panel's right edge and unclickable; the Pen instructions were cut off mid-word; a heading said the same thing twice; and a shape with no lines drawn yet showed as a plain black square in the library, which looked broken -- it now shows a faint empty-slot marker so you can tell 'nothing drawn yet' from 'failed to load'.

Two things the task asked about turned out not to be Lazor's fault, so I left them alone: there is no missing Save button (no tool in the whole toolkit has one -- shapes save the normal Unity way), and the Refresh button sitting far off to the right is how the shared library header is built for all 21 tools, not something Lazor does. Changing either would affect every tool, so that's your call rather than a silent side-effect here.

Not yet verified: I could not test the canvas with a real mouse. Drawing with the Pen, dragging points, middle-drag panning, scroll-zoom, the keyboard shortcuts and the panel divider drag are all unchanged code, but they now live inside a new host, so they deserve one hand pass before you trust them.

Left for you to decide: the old interface system's base file is now completely unused. It is safe to delete but I didn't, because it's shared by the whole toolkit and that's beyond what this task asked for.
**Technical details:**
Five files changed, all listed with full paths in the attached report.

LazorWindow now extends ZuiAssetWindow<LazorShape> instead of LaubraryAssetWindow<LazorShape>; per-frame DrawAsset replaced by retained-mode BuildAsset. The left panel (LazorWindow.Layers.cs) was rewritten from IMGUI into Z.Section/Z.Field/Z.MiniRadio/Z.SliderInt/Z.EnumDropdown/Z.Color/Z.TextInput/Z.Toggle builders. The bespoke canvas (LazorWindow.Canvas.cs, 610 lines) is deliberately untouched and hosted in a single IMGUIContainer -- the DotGenWindow pattern -- with the splitter reimplemented as DotGen's pointer-capture VisualElement. DrawCanvasHud was deleted; its zoom readout and Fit button are now real ZUI chrome above the canvas, kept in sync by SyncZoomLabel() called at the end of DrawCanvas. The 13 bare Repaint() calls became RepaintCanvas() (MarkDirtyRepaint + Repaint) because an IMGUIContainer does not necessarily redraw from EditorWindow.Repaint alone. LazorEditor.asmdef needed com.Lautaro-Arino.Laubrary.Zui.Editor added -- Lazor only referenced ZUI.Editor (the IMGUI assembly), and Z/ZuiWindow/ZuiSection live in Zui/Toolkit; without it the port cannot compile.

Note for whoever touches ZUI next: the 'known ZUI gaps' list in the project CLAUDE.md is stale again. Z.EnumDropdown<T>, Z.TextInput, Z.SliderInt, Z.MiniRadio and Z.Color all exist today, so this port needed zero raw-IMGUI fallbacks in the panel.

Gotcha worth keeping: making the layer-name TextField flexGrow=1 to stop the X clipping tripped ZuiAudit's 'stretch' rule (a stretching BaseField is globally forbidden by ZuiToolkit.uss). Correct pattern is a plain VisualElement wrapper doing the stretching with the field at width:100%, flexGrow:0.

LaubraryAssetWindow<T> now has zero subclasses (confirmed by walking every loaded type's base chain); all remaining repo mentions are doc comments. Safe to delete, left in place on purpose.

Also unaddressed by design: 'Laubrary/Lazor/Lazor' is the flat-menu anti-pattern the project rules name explicitly, but it can't be flattened while Laubrary/Lazor/Import SVG shares the submenu. Menus not changed unasked.

Repro scripts left in .agenthq/workspace/T-0329/: open_walk.cs (floating tagged window), shot.cs (PrintWindow capture), undo_probe.cs (drives the real control callbacks then PerformUndo).
