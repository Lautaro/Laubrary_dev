Note: items (1) and (2) were fixed by a sibling task (T-0367, commit c114ad53) that landed concurrently in the same working tree while I was investigating this task, before I made any change of my own there -- confirmed by diffing that commit and by a live message from that agent/PM. I did not re-implement or duplicate that work. My own commit (8e50090e) covers only items (3) and (4).
**Details:**
T-0359 check 6 (zoom stuck wide) and the draggingBlastCap serialization bug were both already resolved on dev by T-0367's commit c114ad53 before I touched ChunkWindow.Preview.cs/ChunkWindow.cs: pointerHeld and draggingBlastCap are now [NonSerialized], and Tick() runs a ReleaseStalePointerHold fallback that watches previewGeneration and self-clears pointerHeld ~0.35s after the last value change, covering controls whose PointerUp never reaches the window root. I verified this by reading c114ad53's diff directly rather than trusting the report.

My own work (commit 8e50090e) is scoped to Assets/Packages/Laubrary/Zui/Toolkit/ZuiMicroMinMax.cs and the two Chunks call sites that exposed the bug:
- ZuiMicroMinMax.OnDown's double-click handler: Fixed mode used to fall back to `_min` when no default was given (`_lowDefault ?? _highDefault ?? _min`), which is why Scale 3.06 double-clicked to 0.01 (VERIFY.md: 'The Pyre Blast card gives Scale and Alpha no defaults'). It now matches ZuiMicroSlider's own contract: reset to the given default (`_lowDefault ?? _highDefault`), or do nothing if neither was given. Range mode's fallback (reset to the full min/max span when unset) is unchanged -- VERIFY.md called that 'as before' / expected.
- Assets/Packages/Laubrary/Editor/Chunks/ChunkWindow.PyreBlastCard.cs: wired `lowDefault: 1f, highDefault: 1f` onto the Scale and Alpha MicroMinMax calls, since 1.0 is literally what each control's own tooltip already calls the authored default ('1 is the effect's own authored size' / 'Both ends at 1 leaves every blast fully solid'). Angle range (0-360) was left with no default -- there is no single sensible one, so a Fixed double-click there is now a documented no-op, same as an undefaulted MicroSlider.
- ZuiMicroMinMax.OnGenerate: a Range band with xHi-xLo <= 0.5px now draws a 2px tick at the shared value instead of nothing, so a genuinely zero-width band (two handles on the same value, by any path) never reads as an empty/broken track.
- ZuiMicroMinMax.SetMode: the Fixed->Range nudge that opens a fresh band clamped straight back to `low` when `low` was already at the top of the track (`Mathf.Min(_max, _low + nudge)` with `_low == _max`), which is exactly VERIFY.md's repro -- Alpha at 1.00, Fixed->Range gave '1.00 - 1.00'. Now nudges `low` DOWN instead whenever `high` has nowhere to go, so switching modes at the top of the track still opens a real, non-zero band (the render fix above is still there as a second line of defence for any other path to a zero-width band).
