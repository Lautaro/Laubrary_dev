## Description

Measured live 2026-09-08: `PyreWindow.minSize` reads **50x50** — Unity's default floor, i.e. the window never sets one. Setting `position` to that minimum produced a real 124.4x50 window in which 22 of 27 buttons were entirely outside the window's right edge.

ShaperWindow by contrast declares `minSize = (820, 520)` (confirmed live in the same session), which is what made T-0296's clamp testable against a documented floor.

This is separate from, and was found alongside, the Pyre splitter clamp T-0299 fixed: with the clamp in place the dial pane now tracks the window down correctly (verified at 900x700: pane clamped 1458 -> 640, 0 of 65 buttons off-screen; widened back to 1900 -> regrew to 1458, 0 of 27 off-screen), so Pyre degrades gracefully at any sane size. A minSize would simply stop the window reaching sizes where no layout can help.

OWNER DECISION: give PyreWindow a minSize in the spirit of Shaper's 820x520, or leave it. Not done here because picking the number is an authoring decision, not a defect fix.
