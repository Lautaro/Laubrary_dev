## Description

Follow-up from T-0026's converged design ("Legs and Torso become two ANIMATION SETS in the SAME Lauminary, not
two separate Lauminary assets") — explicitly deferred there, now done per direct user request: "make protoguys
legs and torso animations exist in the same asset just called ProtoGuy."

## What was done

- Created a single new `Lauminary` wrapper, **"ProtoGuy"**
  (`Assets/Launimator/Lauminaries/ProtoGuy_25cf2dfd/`), holding:
  - All 35 animations (19 from the old Legs Lauminary + 16 from the old Upper Lauminary — no name collisions,
    different prefixes).
  - All 3 `LauminationSet`s (`LegsIdle16`, `LegsWalk3`, `UpperAim16`) — cloned from the T-0026 re-trimmed
    drafts; sets embed independent `Laumination` copies (not references into `animations`), so combining sets
    from two different source versions into one new version needed no re-linking.
  - Recipes reconstructed from the TRUE original source PNGs (not from the already-baked packed atlases), same
    approach as T-0025/T-0026, auto-trimmed (`fixedFrame=false`) to match what the Rig's Edge anchors need.
- Verified byte-exact (non-transparent pixel count, per frame) against the true original source for all 35
  animations before trusting it.
- Repointed BOTH of `ProtoGuy.asset`'s `ZonedLauminaryView.version` references (the Legs body part AND the
  Upper body part) to this SAME new shared `LauminaryVersion` — each part still gets its own
  `ZonedAnimationPlayer` instance (per `CompositeZonedPlayer.Build`), just both reading from one shared asset;
  no runtime code changes needed, confirming T-0026's earlier claim that this needs zero schema/resolution
  changes.
- Live-verified in Play mode: idle pose and walking (W held, real queued Input System event) both
  screenshot-confirmed correct and properly aligned via the T-0026 Rig connection — no regression.
- The two old Lauminary wrappers (`ProtoGuyLegs_6a0fbd2c`, `ProtoGuyUpper_b1cceb82`) are now fully
  unreferenced (grepped — nothing in `Assets/Demos/` points at either GUID anymore). NOT deleted — left in
  place per this project's standing caution about not removing assets without being asked. Safe to delete
  whenever the user wants.
