The behavioural specification a Shaper user is entitled to expect, derived from Pyre's own window code rather than from docs: 109 rows across 13 surfaces, each one a user action, the visible result it must produce within N seconds, and how to check that result temporally (capture the preview at t=0/0.5/1.5/3s and diff pixels, read the frame readout at each) rather than by asking an API whether a field changed. Every row carries a Pyre file:line citation and a Shaper column reading the current code as Same / Differs / Missing / Unknown.

The owner's complaint reproduces from the code alone, and it is not one bug. A new ShaperDocument defaults to frameCount = 1 (ShaperDocument.cs:121) and the transport is only built when frameCount > 1 (ShaperWindow.cs:753), so a freshly created document has no Play button, no scrubber, no filmstrip and no cherry panel at all until the user discovers the Frames dial. Raise Frames and it still does not animate: every Shaper dial defaults to Static (ShaperPrimitives.cs:91-160), whereas Pyre's alpha and size default to CURVES (Pyre.cs:325-326, 980-1001) — which is precisely why a fresh Pyre layer moves with no authoring and a fresh Shaper layer cannot.

The stepping rule itself is sound: ShaperClock.AdvanceFrames/WrapFrame match Pyre's accumulator and modulo wrap, including the 0.1s delta clamp. What is missing around it is the chrome that makes a running transport legible — no frame N/M readout, no Strip toggle, no plain-loop blank Delay, no swarm overlay, no saved Views — plus one live risk: an edit drops the entire frame cache (ShaperPreviewFrameCache.cs:65) while playback refuses to step onto an uncached frame (ShaperWindow.cs:912), so dialling while playing can pin the picture in place.

Shaper is ahead of Pyre in three places, and those should not be regressed while closing the gaps: the transport status line that names a cherry gap instead of letting it read as a dead Play button, the Zound cue that actually fires on slot entry (Pyre records the choice and never fires it, PyreWindow.cs:281-284), and the per-frame cache tick strip.
