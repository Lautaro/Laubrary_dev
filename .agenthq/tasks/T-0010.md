### 2026-08-16T12:04:15Z — agent — in_progress -> done
Root cause found and fixed: Assets/Packages/Laubrary/Editor/AssetKit/ZuiAssetWindow.cs (the UI Toolkit asset-editor base every current Laubrary tool inherits -- Pyre, PyrePlus, Mirage, Zoetrope, Cartographer, Choreographer, Chunks, SpriteFx, BackSplash, TilesetBuilder, SpriteCatalog) had `OnProjectChanged()` hooked to `EditorApplication.projectChanged`, and on EVERY firing it called `Rebuild()` -- which is `rootVisualElement.Clear()` + `BuildUI()`, a full teardown-and-recreate of every VisualElement in the window, no matter what the user was doing at that moment. Any VisualElement being destroyed and recreated loses ALL of its retained-mode state: a focused TextField loses focus AND its caret/selection, a ScrollView's scroll offset resets to the top (the 'scrollbar snaps up' symptom), and an in-progress text-drag-select is simply gone once the backing element is replaced. This is exactly the SAME mechanism behind all three reported symptoms (scrollbar snap, input focus loss, text selection disappearing) because they are all just different flavors of 'a VisualElement got destroyed out from under you' -- one root cause, three visible symptoms, matching the task description. `EditorApplication.projectChanged` is a coarse, editor-wide event -- it fires for ANY asset changing anywhere in the project (not just the one being edited), so it can and does fire while the user is mid-interaction with a totally unrelated open editor window, with no correlation to anything they're doing.

FIX: OnProjectChanged now only invalidates the cached browser thumbnail list (ClearThumbs + _browse = null) unconditionally, but only calls Rebuild() -- the destructive full-window rebuild -- when the browser grid is actually what's on screen (asset == null || browsing). While a specific asset is open for editing (the state you're in when selecting/typing in a field), the window is left completely alone; the browser lazily re-enumerates the next time it's actually opened (BuildBrowser already does `if (_browse == null) RefreshBrowse()`). This preserves every other legitimate Rebuild() call site (Duplicate/Delete/Rename/Refresh-button, which are the user's OWN action on the currently visible browser and are supposed to rebuild).
