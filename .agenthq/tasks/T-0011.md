## Description

**This is the index task for the whole incident. Every other task under the
`IncidentRecovery-2026-08-16` node is a child of this one. Purpose of this whole
node, per explicit user instruction: track everything that was LOST so nothing is

delete or mark tasks done here just because compilation goes green; a task here is
only done when the actual feature/behavior it describes has been rebuilt and
verified.**

### What happened

1. An AgentHQ-duty agent (working the Vector MetaLayer / shooting-aiming feature,
   see the `VectorMetaLayer` sub-node) crashed mid-run and its crash deleted 1,087
   files from disk.
2. Independently, THREE simultaneous `Unity.exe` processes were found running
   against this same project (only one should ever exist) — this was actively
   causing file edits to revert themselves during recovery attempts, which is why
   fixes kept appearing to "un-fix" themselves. Two rogue processes were killed.
3. The 1,087 deleted files were restored via `git checkout HEAD
   --pathspec-from-file=<list-of-exactly-deleted-files>`.

### The actual damage (this is the part that matters)

**The project's last real commit is `4368af3`, dated 2026-08-05.** Every session
since then — 11 days of work spanning ProtoGuy/Zoe movement, the PyrePlus modifier
culling pass, CherryFraming (5+ iteration passes), the Zoe event-uniform-model
attempt, and this session's own Vector MetaLayer feature — was uncommitted.

`git checkout HEAD -- <path>` restores a TRACKED file to its last COMMITTED state.
For any tracked file that had uncommitted edits made after 2026-08-05, this
silently reverted it all the way back to the Aug-5 commit, discarding 11 days of
in-flight edits on that file. Brand-new files that were never committed (git
status `??`) were NOT touched by this restore (git checkout doesn't touch
untracked files) — those survived on disk intact. The net effect: **most
NEW files from the last 11 days survived; most EDITS to PRE-EXISTING (already
committed) files from the last 11 days were wiped**, often leaving the surviving
new files referencing APIs/fields on the reverted old files that no longer exist.

No other recovery path exists — checked and ruled out 2026-08-16: Recycle Bin (668
items, none matching), Windows File History (not configured), VS Code local-history
extension (not installed/no folder), Unity `Library/BackupAssets` (doesn't exist).
**The uncommitted deltas on tracked files are genuinely gone at the OS level.**
Session memory files (`C:\Users\Lauta\.claude\projects\D--UNITY-Laubrary-Dev\memory\`)
are the best surviving record of what several of these deltas actually contained,
in enough detail to rebuild from — see each sub-task for pointers.
