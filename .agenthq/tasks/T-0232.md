DECISIONS I MADE (owner away; recorded, not parked)

1. THE ENUM RULE IS "THREE OR FEWER", AND DOTGEN'S OWN HAND-BUILT CHOICES FOLLOW IT TOO. The brief offered a fallback (switch DotGen's shell enums to MiniRadio instead) if changing ZuiReflect proved risky. It did not: Pyre audits clean after the change, its widest segmented control is 179px inside its own pane, and its five-option Variant enum still wraps as a MiniRadio because five is more than three. So I took the systemic route AND removed the mirror-image inconsistency it would otherwise have left behind - DotGen's Placement Method and "Size relative to" were hand-built MiniRadios at 3 and 2 options, which would have been the only two short choices in the window still wearing the other look. Both now go through one Choice() helper carrying the identical rule. The Selector picker deliberately stays a MiniRadio at every length: it is a picker over a list that grows, and a control that changed shape as selectors were added would be worse than either look.

2. B-164 FAILED AND NEEDED A SHARED-ZUI ADDITION, NOT A DOTGEN WORKAROUND. Double-clicking the root generator's Grid Columns restored 4, the type's own initializer, where the checklist requires the role default 8. Hand-coding an exception inside DotGen's card would have hidden the rule from every other tool with the same shape.
