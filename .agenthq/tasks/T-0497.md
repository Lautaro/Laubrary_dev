### 2026-09-29T16:47:11Z — agent — in_progress -> in_progress
Commit da7aee37: replayable tokens, PlayToken (not-played / empty tokens), Track(n) / Track(id) with volume, pitch, speed, fade, mute, solo, enabled, stop, and selection that skips disabled tracks. Checks 22 and 23 pass.

**Decisions made while building:**
1. **Restart has no fade.** It ends the run at once (the engine's click-free stop). A faded restart would need the old run to keep sounding on a separate audio source while the new one starts. Logged as a possible follow-up.
2. **Track settings live on the top-level token, keyed by the authored track entry,** so they survive replays and apply at any depth.
3. **Disabling a track fades it over 30 ms.** A mid-run pick is not redone.

**Bug found and fixed by measurement:** ZPOC values sent before the audio graph made the voice were lost. This affected a replay, a value set before Play, project-wide values at start, and Zequence tracks.

**Open, pre-existing suspicion (NOT verified):** on the chain path a play's volume may be applied twice. The voice gets the volume as its output gain, AND the audio source carrying it has the same volume (measured: volume 0.5 gave voice gain 0.5 and source volume 0.5). If Unity applies an AudioSource's volume to a generator's output, a 0.5 play is heard at 0.25. It could not be measured in edit mode (no listener runs there). Needs a Play-mode or player measurement. Token and track volumes deliberately go through the one existing path (the source's volume) so this is not made worse.

**Todo 5** (token volume through the own Volume value) was superseded: token and track volume use the existing live/track volume on the audio source instead; see the suspicion above.
