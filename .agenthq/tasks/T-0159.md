Opening Shaper now works the way opening Pyre does. There is a library of every Shaper document in the project, each shown by its own picture rather than its name, and the picture is the real render — the middle frame of the document — which starts playing when you hover it. From that library you make a new document by typing a name (it lands in the tool's own folder, no file-explorer dialog), copy one, rename one, or delete one behind a confirm, and you can tag any of them. When nothing is selected the library IS the screen, with a line telling you to hit New, rather than an empty workbench waiting for someone to drag an asset into a field.

The raw object field and the save dialog you hit are gone. Everything the window already did is unchanged behind that: the same sections behind the same toggle bar (the Tags section now sits in it as the first entry), the same preview, transport, cherry panel and bake, and the same single undo wrapper behind every dial.

A document — and a baked clip — can also now draw itself for anyone who asks. Any picker, chip or browser elsewhere in Laubrary gets a real thumbnail instead of a blank square, and it comes from the one renderer the live preview and the bake already share, never a second drawing path invented for thumbnails.

One judgement call worth knowing about: a document drawing itself for an OUTSIDE consumer cannot run its own authored effects, because the piece that runs effects sits above the document in the assembly graph and the engine explicitly refuses a global hook for it. Shaper's own browser does supply that piece, so the library you see is effect-accurate; a thumbnail drawn somewhere else would show the document without its effects. Same renderer either way.

**Details:**
WHAT CHANGED
- ShaperWindow moved from the plain ZUI window base onto the AssetKit asset-window base, so all of the asset chrome above is inherited rather than hand-built.
- The document the window edits is now the base's own asset binding; every existing section keeps reading the same name and needed no other change.
- A new document is seeded with the same single quarter-canvas layer the old New path seeded, so the first render is still a shape sitting on a canvas rather than a grey block filling it.
- Switching document (by browser, by the assign field, or through the sibling task's OpenFor entry point) resets layer selection, frame and playback, so a stale selection can never land on a different shape or keep a dead clock running.
- The document type moved out of the light-rig file into its own file, and both it and the baked clip now implement the shared visual-preview contract.

DECISIONS I MADE
1. Effects and the outside preview: see the note in the summary. I did NOT add a static applier hook, because the engine file that defines the applier seam rejects exactly that by name (ShaperEffects.cs:91-92: "or reach for a mutable static hook, which is global state by another name"). Instead the window overrides the browser's thumbnail render and passes the applier itself, and the base prefers a window's own render over the asset's (ZuiAssetWindow.cs:355-356), so the Shaper library is effect-accurate today.
2. Animated thumbnails are ON, paired with the base's default hover-to-preview rather than animate-all, because a Shaper frame costs tens of milliseconds and a grid of them all animating would be a real cost.
3. I gave the window's document accessor a setter that routes to the base. The sibling W1.3 file ShaperWindow.OpenFor.cs assigns that name directly and would otherwise not compile; a setter is a smaller, better change than reaching into their file.
