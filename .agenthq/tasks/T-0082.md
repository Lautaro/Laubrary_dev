[[attach:20260826T053504Z_T-0082_walk_diagonal_NE.png]] [[attach:20260826T053504Z_T-0082_walk_diagonal_SE.png]] [[attach:20260826T053504Z_T-0082_walk_diagonal_SW.png]] [[attach:20260826T053504Z_T-0082_walk_diagonal_NW.png]]

Showing you these surfaced a real problem: on a diagonal, the gun/torso correctly aims at the exact diagonal, but the legs don't -- they snap to whichever straight-up/down or side-on walk cycle is closest, so the legs visibly don't match the direction the torso is aiming. You can see it clearest on NE and SW in the screenshots: the gun points crisply into the corner while the legs are doing a walk cycle that faces mostly forward or mostly sideways, not the corner.

Root cause: the walk legs were only ever drawn in 3 directions (facing up, facing sideways, facing down -- the sideways one gets mirrored for the 4th, left/right), while the torso/gun art was drawn as a full set covering every direction including the diagonals. So whenever the character walks toward a diagonal, the torso has an exact matching drawing to show, but the legs have to "round" to the nearest one of those 3 -- which is never actually the diagonal.

This is a different issue from the pixel-offset problem that was already fixed earlier in this task -- that was legs and torso not lining up in the SAME pose; this is legs and torso disagreeing about WHICH pose to be in.

Two ways to actually fix this, your call:
1. Ask the artist for diagonal walking-leg art (matching what was already done for the torso/gun, which does cover every direction) -- the clean fix, but needs new art.
2. Leave it as-is and accept that diagonal walking will always show straight/sideways legs under a diagonal-aiming torso -- no new art needed, but the mismatch stays visible during diagonal movement.

I have not changed anything in the project for this pass -- this was purely a "go look and show me" investigation, so there's nothing to review/undo. Let me know which way you want to go (or if you want it left alone for now, same as the earlier accepted seam) and I'll pick this back up.
