ProtoGuy's walk animation now always shows the character's legs walking in the direction his upper body (torso/gun) is facing, not the direction he's actually moving in -- so strafing or backing away no longer makes his legs point the wrong way.
**Details:**
How to check it: play the ProtoGuy demo scene, aim the mouse one way while moving a different way (e.g. aim left while walking right) -- the legs now animate to match where he's aiming, and if that means walking backwards, the walk-cycle plays in reverse so the feet still look right instead of moonwalking. Not yet re-verified: a live human playtest with a real mouse/gamepad (this was confirmed via scripted test values plus a screenshot, which is a good stand-in but not the same as someone actually playing it). The slight torso/legs seam mentioned in the task is a separate, known, accepted issue (waiting on updated art from the artist) and was not touched here.
**Technical details:**
Root cause: D:\UNITY\Laubrary Dev\Assets\Demos\ProtoGuyDemo\ProtoGuy.asset, the Legs body part's Moving MotionPoseRule (setName LegsWalk3) had overrideChannel: 0, so it fell back to the part's default channel: 0 (Heading/movement) instead of matching the Idle rule's overrideChannel: 1, channel: 1 (Aim/torso-facing). Fixed by setting the Moving rule's overrideChannel: 1 too, so both Idle and Moving read the Aim channel exactly like Upper does. Note: HEAD already had this rule at overrideChannel:1 -- the working tree had regressed it to 0 as part of other uncommitted WIP (unrelated anchor/idleClip changes in the same file, left untouched). The runtime backpedal-aware playback (MotionPoseAnimator.ShouldBackpedal() in Runtime/ZoetropeLaunimator/MotionPoseAnimator.cs) was already built anticipating exactly this change and required no code edits -- only the asset's rule needed flipping. Verified live in Play mode via MotionStateSource.PublishOverride with heading=East/aim=West: Legs resolved to LegsWalk_E mirrored (flipX=true, reversed=true, i.e. backpedal detected), matching torso facing West; same-direction case (heading=aim=North) played LegsWalk_N forward, reversed=false -- confirming no regression to the normal case. No new console errors/warnings introduced.
