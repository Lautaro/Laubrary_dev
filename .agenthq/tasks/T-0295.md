## Description

**Found by T-0293 (A22 fifth pass), measured live in the Shaper-worktree editor.**

`BuildViewsSection(VisualElement root)` is called as `BuildViewsSection(flow)` (`Editor/Shaper/ShaperWindow.cs:304`), where `flow` is the LEFT pane's `Z.ColumnFlow(360f)`. Its first line is `viewBar = BuildViewBar(root)` (`:400`), so the `paneRoot` that capture and apply both query through (`:418` and `:421`, `paneRoot.Query<ZuiBox>()`) is that column flow, not the window. Every `ZuiBox` in the RIGHT pane is invisible to a view.

**Measured round trip** (window 1500x1000, every section open so all ten boxes are in the tree):
- authored: the 8 left-pane boxes set to a known alternating pattern, `Preview backdrop` CLOSED, `Bake` CLOSED
- pressed `Save as` -> view `A22Panes`
- disturbed: every box opened, `Sweep` closed
- pressed `Apply` -> **all 8 left-pane boxes restored exactly** (Key=0, Mask=1, Lighting=0, Position=1, Sweep=1, Shell=1, Edge=0, Edge fill=1) and **`Preview backdrop` and `Bake` both stayed OPEN** — neither captured nor restored.

The same two boxes are also the only two built with a bare `Z.Box` instead of `Z.BoxKeyed`: read live, their `_key` is the title+tooltip fallback string (`"Preview backdropA colour and one optional image drawn BEHIND the preview..."`). Both facts hold at once, but the pane-root one alone explains the miss — a box outside `paneRoot` is never queried.

`ZuiViewBar`'s label tooltip promises "which CARDS are folded" without qualification, so the bar over-states what it stores.

**Suggested fix, deliberately NOT applied** (it changes what an already-committed saved view does — `Assets/Shaper/ShaperViews.asset` holds `A19View2`): pass the window root to `BuildViewBar`, and in the same change give the two right-pane boxes stable keys via `Z.BoxKeyed` (the layout guide's rule — an unkeyed `Z.Box` in a view-captured window orphans its state on any title reword). First check `ZuiBox.ApplyView`'s behaviour for a key the stored view does not contain, so older views leave the two newly-visible boxes alone rather than forcing them shut. Pyre's own bar (`Editor/Pyre/PyreWindow.cs:467`) should be checked for the same shape in the same pass.
