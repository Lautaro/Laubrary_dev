## Description

**Owner's spec, verbatim (2026-09-28):** "we have a new type of zound that I want you to build. This is not mutually exclusive with parallel, roundRobin etc.. those can also be chosen from. Looper: Meant for looping audio. When end is reached it starts over. It has a crossmix function. When enable = >0 then it will play a new instance some time before the end and fade out the old one as the new one fades in. Crossmix decides how long this will take. Some UI function shows in the start and end what parts will be used for this."

**Addition (owner, same day):** "The crossmix slider can be a static value or a random range." With a range, each crossfade picks its own length within it (deterministic hash draw, never managed randomness on the audio side).

**Coordinator's reading:** crossmix is a length; 0 = plain restart at the end; >0 = that long before the end a second read position starts from the loop start and the two cross-fade over exactly that length. Loop start/end = the sound's trim points unless there is a reason otherwise. The UI shows, at the start and end of the waveform, which parts the crossmix uses.

**Design points to decide and record here:** (1) inside one voice, sample-accurate, using the per-voice read cursors (not a second AudioSource from the main thread); (2) fade shape, checked flat on a steady tone; (3) crossmix limit vs loop length (applies to the top of a range) and how the UI shows it; (4) architecture rules in CLAUDE.md (original audio through the live chain, Decompress On Load, live edits resolved against the voice's own layout, decay added to length, no managed callback), and how a never-ending voice stops/tears down/passes the completion barrier (T-0419); (5) T-0449 (quit while looping segfaults) looked at alongside; (6) UI in the UI Toolkit windows, an honest minimal view in the old IMGUI ones, no new menu items.

**Verification buckets:** measured (seamless-loop seam check crossmix 0 and >0; block-slicing invariance; both kept in the Checks menu), seen by eye (waveform overlay and controls, side-by-side at real width), not verifiable by me (how it sounds: owner's listening test).
