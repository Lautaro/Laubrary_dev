The generator declares 141 dials whose stored names are the research program's own parameter keys (a1, turbOctShell, ripR, coreP, smearNorm), and those names cannot change without breaking contract loading, the parity dumps and the [MovedFrom] history every authored Orb depends on. **Technical details:**
ZuiReflect (Zui/Toolkit/ZuiReflect.cs)
  - LabelOf(FieldInfo) replaces ObjectNames.NicifyVariableName at the two sites that caption a control
    (BuildField's `nice`, and the Y half of a [ZUIPair2D]).
  - FlowFields takes a grouped path only when some field of the type carries [ZUIGroup] (HasGroups), so every
    card that has not adopted it draws through the identical code as before.
  - Grouped path walks declaration order: an ungrouped run flows inline; a grouped field lands in a Z.BoxKeyed
    created at its first member's position; Advanced groups are held to the end and start folded once per session
    (s_advancedFolded), never re-folding under a user who opened one.
  - BuildFields was split into BuildSubset(root, owner, opt, subset, all). This matters: [ZUIShowIf] gates and
    [ZUIPair2D] partners must resolve against the WHOLE field set, not the pass being drawn. Resolving against the
    pass would have shown all five Orb variant boxes at once, because `variant` and `emberdrift` land in different
    inline runs.
  - Group fold keys carry a _groupKeyPath (pushed/popped around the nested-class branch beside _nestDepth), so one
    settings class drawn three times (Plasma Bloom's chunks/embers/motes) gets three independent boxes. Keying on
    the type alone folded all three together, which is the same failure Z.BoxKeyed exists for.

New attributes (Zui/Scripts/Runtime/, global namespace like ZUIShowIf/ZUIWholeNumber)
  ZUILabelAttribute(string label); ZUIGroupAttribute(string group) { string Tooltip; bool Advanced; }
  Only the first member of a group needs to carry the tooltip.

OrbForm.RampHash (was OrbForm.cs:480, now a one-line delegation to PyreShade.RampHash)
  It folded stops + blend space only. PyreShade.RampHash also folds ZuiRampMath.Hash(h, r.adjust), which is what
  PyreOrb.BakeLut's ApplyAdjust actually consumes. Note the knob's unit when testing: hueShift is -1..1 where +/-1
  is +/-180 degrees, so a whole number is exactly identity. The first probe run used 120 and reported a false
  negative because of it.

ZuiMicroSlider / ZuiToolkit.uss
  .zui-microslider__caption gains right:6px + overflow:hidden + white-space:nowrap + text-overflow:ellipsis, and a
  --reserve modifier (right:46px) that ApplyDisplay toggles whenever the value label or the numeric field is shown.
  Hiding the value from the control's own menu gives the caption the whole track back.
