### 2026-09-02T18:30:45Z — agent — in_progress -> done
Cherry Framing in Shaper is Pyre's own panel now, not a partial copy of it.

What was wrong: Shaper had ported Pyre's cherry SLOT grid and left the SOURCE half behind. There was no grid of the document's own frames, no click / Shift-range / Ctrl-toggle selection over them, no double-click-to-add, no "+ Add selected" and no tile-size dial. The only way to author a slot was "+ Add slot", which appends whatever frame the preview happens to be showing. Ten of the panel's thirty-two functions were simply absent, which is what "massively underdeveloped" was.

Rather than port the missing half a second time, there is now ONE panel and two hosts — the same move the Shape cards made in T-0183. Editor/Pyre/PyreCherryPanel.cs owns the source grid, the slot grid, selection, block drag-reorder, the right-click slot editor and the keyboard shortcuts, driven by a small IPyreCherryHost. Pyre's window draws it through a host adapter and is unchanged, down to the pixel: every inline geometry value in the live panel (96px tiles from previewCherryStripSize, 2px margins and borders, the badge absolutely placed at 2,2, the 16x16 zero-margin remove button) matches the literals the old file set.

The two slot TYPES stay separate on purpose. Pyre's CherryFrame draws with UnityEngine.Random and System.Random, both banned from a Shaper generator path (BC-1.3), so ShaperCherryFrame hashes from the document seed instead. Unifying them would have dragged a banned draw into Shaper's runtime, so the panel exchanges the six authored scalars every slot has and leaves list surgery to each host — which also keeps each host's own extras entirely on its own side.

Shaper keeps everything it has that Pyre does not, drawn through the panel's host hooks: the loop gap (Pyre's lives in its transport row), the preview-only Zound cue and its slot badge, the MultiFrame candidate-frame list and its per-slot seed, "+ Add slot", and — untouched in the window itself — the cherry playhead and status line.

Three defects fell out of the work. The Tile px dial wrote its value and never repainted the grids it describes, so it was a dead control in BOTH windows; it now works in both. In Shaper every cherry thumbnail went blank after editing anything else, because the edit destroyed the cached textures the tiles were still displaying and nothing repainted them; invalidation now repaints both grids, deferred and coalesced so a dial drag costs one repaint rather than one per delta. And toggling MultiFrame in the slot editor did not reveal the candidate-frame list until the popover was closed and reopened, which made that list undiscoverable — the host's rows now follow the value they depend on.

Shaper's tile size is stored in EditorPrefs rather than on the document: how big a thumbnail is drawn is view state and does not belong in a document's undo history.
