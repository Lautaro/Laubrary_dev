**Technical details:**
Root cause was NOT in D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Editor/Zoetrope/ZoetropeWindows.cs -- the Hit/Death headers there (RoleHeaderRow) are plain rows with no fold logic of their own. The real bug lives in the shared D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Zui/Toolkit/ZuiSectionLabel.cs, which gives every Z.Text(.., ZuiText.Section, ..) heading its click-to-fold behaviour. When a heading sits inside a ROW (RoleHeaderRow's title + role chip + preview button), ZuiSectionLabel.Apply()'s fold loop walks the row's PARENT's children looking for the next boundary, but it only compared each candidate child against `is ZuiSectionLabel` -- for a row-heading, the candidate child IS the row (a plain VisualElement), with the actual ZuiSectionLabel nested one level inside it, so the check always missed it. Collapsing Hit therefore treated Death's whole row (header + body) as ordinary content to hide, along with everything after it, instead of stopping there. Fix: added a static IsSectionStart(VisualElement el) helper that also returns true when el's direct children include a ZuiSectionLabel, and used it as the loop's break condition. This only narrows what gets hidden (never widens it), so it cannot regress any of the other ~15 files in the package that use ZuiText.Section headings.
