## Description

The user's request, verbatim intent: "There are a lot of parameters that seem to work animated. I would like them all to be vetted and changed to allow them to be envelopes — but only the ones that make sense and where the algorithm allows it."

Scope: the six finished Kiln forms — `PlasmaBloomForm`, `ArcBurstForm`, `OrbForm`, `TorchForm`, `JetForm`, `RadialJetForm` (+ `JetFormBase`). Skip `ExplosiveJetForm` (WIP, T-0049) and `InfernoForm` (already envelope-driven, the precedent). Per form, per dial: classify **animatable** (the algorithm reads it as a per-frame scalar → `[Range] public ZUIValue x = new ZUIValue(def)`, snapshot in `Prepare` via `ctx.Eval(x, slot)` with a unique slot), **structural** (counts, seeds, integer periods, enums, per-element random ranges — stays plain; a dial read only inside population setup is structural even if it looks like a scalar, since animating it would silently do nothing), or **pre-pass input** (feeds a `PlusPrepassCache` / clip-statistics solve — stays plain unless the solve is trivially per-frame). Ramps / colours are untouched (bands are T-0064). No algorithm changes — only where a dial is read from. Defaults identical, so Static renders the same bytes; `FromContract` keeps setting every key (a ZUIValue target takes the scalar as its Static value).

Verify per form: compile clean; `FromContract` mapped counts equal the form's log; parity on every contract draw unchanged; a test in `Assets/Tests/PyrePlus/` that a Curve on a converted dial changes frame N-1 vs frame 0 while a Static ZUIValue renders byte-identically to the plain-float build; `ZuiAudit` 0 findings with the form selected and the card looked at; cold-vs-warm 0 px; parallel-fill identity; per-layer cache re-keys on an envelope edit; suite green. Commit per form.

Standing rules: autonomous, never stall, log decisions here. Never touch the user's assets (the uncommitted `New Pyre Plus§.asset` / deleted `New Pyre Plus.asset` / untracked `Inferno Deluxe.asset` are never added, reverted or committed). No MenuItems, no Pyre1 edits, no port started, no T-0064 work.
