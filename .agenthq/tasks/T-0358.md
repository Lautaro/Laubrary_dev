T-0366 verify FAIL (check T-0358/2): dragging a blast disc or a not-yet-fired ring on the stage moves the offset and the card's X/Y live, but leaves NO Undo record. Undo.RecordObject runs only on MouseDown, a frame in which nothing changes, so Unity drops it; the MouseDrag frames mutate with no record. Measured with the Undo stack (GetRecords) before/after each event in separate frames: the stack stays unchanged, and one Ctrl+Z after the drag undid the PREVIOUS unrelated edit (a Timing band drag), leaving the offset where it was dragged. Fix: RecordObject on each MouseDrag (inside one group: IncrementCurrentGroup at down, CollapseUndoOperations at up), as ZuiUndoGesture does. BackSplashWindow.HandleDrag has the same shape and likely the same bug. Also: draggingBlastCap is a serialized [Serializable] field, so after a domain reload it comes back as a default PyreBlast (empty id), not null; a press-drag on empty stage then 'drags' that phantom and dirties the asset.
