## Description

Found 2026-09-29 by the ZPOC player-build proof (T-0499), with the check build's new -zoundsQuitWhilePlaying mode (commit 1980e32e). Pre-existing; not caused by ZPOC.

**Measured on standalone Windows development builds of the check scene:**
- **This branch:** quitting while a voice plays exits with an access violation (-1073741819) after every subsystem has shut down; 61 native allocations leak.
- **The commit before the ZPOC work (599767be):** the same crash, with 41 leaked allocations. That is exactly the signature T-0449 recorded before its fix. The extra 20 on this branch are the per-voice arrays ZPOC added.
- **Stopping the voice 0.3 s before quitting (-stopFirst):** exits cleanly (0) on both.
- **No sound playing (-zoundsCheckReport):** exits cleanly.

**Ruled out (experiments in a throwaway worktree, all still crashed):**
1. Freeing nothing at quit.
2. Skipping the quit teardown entirely.
3. Waiting at quit until the audio system reports the voice's instance destroyed. It already was, after 0.2 ms.

So the voice itself is torn down correctly at quit, and something else still faults later in shutdown. The one difference from the clean exit is that the audio source was stopped while the application was quitting, rather than with frames still running after it.

**Why it matters:** a real game almost always quits with something playing, and a Looper never ends by itself.

**Next step:** run the player with `-native-leak-detection EnabledWithStackTrace` and read the crash dump in %TEMP%/<company>/ZoundsSapCheck/Crashes. The clean worktree at D:/UNITY/LaubraryDev-BuildCheck builds the check in about 30 s (ZoundsSapBuildCheck.BuildFromCommandLine in batch mode).
