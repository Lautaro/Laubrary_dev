## Description

**Important distinction from the rest of this node: this is NOT data lost by
tonight's crash.** `MuzzleTracker.cs` and `MuzzleVectorTracker.cs` are both
untracked (never committed) files, so the crash+restore didn't touch them. The bug
is that they were built (by the AgentHQ-duty agent working T-0001–T-0006, then by
me for T-0007/T-0008) calling `IAnimatedView.TryGetMetaPointNearest` /
`.TryGetMetaVectorNearest` — methods that were **never actually implemented
anywhere in the codebase**, on the interface OR on the concrete
`ZonedAnimationPlayer` class (grepped, zero matches for either name project-wide).
Only `TryGetMetaPoint(string, out Vector3, out float)` (3-arg, different name)
exists.

This means the T-0001–T-0008 "done" tasks for the shooting/aiming feature (see
`vector-metalayer-shooting-aiming-2026-08-16.md` memory) had a real compile-blocking
gap in them that wasn't caught before those tasks were marked done — worth noting
as a verification-process gap for future HQ-duty runs, separate from fixing the gap
itself.

**Current state**: both files were quarantined to
`D:\UNITY\Laubrary Dev\_Quarantine\VectorMuzzleTrackers\` (moved out of `Assets/`,
NOT deleted) tonight to unblock compilation elsewhere. They need either:
- A real `TryGetMetaPointNearest`/`TryGetMetaVectorNearest` implementation added to
  `ZonedAnimationPlayer` (and exposed via `IAnimatedView` if the trackers should
  stay interface-typed rather than switching to the concrete class), or
- The trackers rewritten to use the existing `TryGetMetaPoint`/`TryGetMetaVector`
  signatures if "nearest" semantics weren't actually needed.

## Handover Log

### 2026-08-16T13:34:54Z — agent — in_progress -> done
Implemented the missing TryGetMetaPointNearest/TryGetMetaVectorNearest methods and everything they depend on, then un-quarantined MuzzleTracker.cs and MuzzleVectorTracker.cs back into Assets/Packages/Laubrary/Runtime/Zoetrope/. Vector-mode meta-layers (MetaLayerMode.Vector, VectorMetaFrame) did not exist at all in the current codebase either - that was also part of the incident-wiped work - so this rebuilds the runtime data model + sampling API, not just the two Nearest method names.

How this works now: a MetaLayer can be mode=Vector with a per-frame VectorMetaFrame (origin/direction/optional length). ZonedAnimationPlayer.TryGetMetaPoint/TryGetMetaVector sample the current frame; the new *Nearest variants fall back to the nearest frame (either direction) with authored data instead of failing outright, matching the fallback behavior both tracker components' own doc comments already assumed. Both are exposed on IAnimatedView and implemented in AnimatedViewRelay (with the lazy _player re-fetch guard the original build added).

Not done (out of scope for this gap-fix): there is still no authoring UI for Vector-mode layers in the Laumination Builder window, and no weapon-side consumer (TryFireFromVector, WeaponDef fields, ZoeSpawner wiring) - those were also wiped by the incident and would need to be rebuilt separately if the full shooting/aiming feature from T-0001-T-0008 is wanted back. Right now Vector layers can only be authored by setting VectorMetaFrame fields directly (script/asset), same limitation T-0007 already had before painting UI existed.

Not yet verified: no live in-scene weapon actually calls these trackers today (the consumer side is gone), so this is verified at the API layer, not via a real fired shot.
