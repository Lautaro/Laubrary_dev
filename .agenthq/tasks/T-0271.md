CHANGELOG: Shaper - a bag's own Fill card works again on a SAVED document: a node's fill and edge now say whether a person asked for them, so the empty fill and empty edge Unity conjures on every save stop painting and stop claiming to exist.

**Unity never writes null for a plain [Serializable] class field - it writes a DEFAULT-CONSTRUCTED one, with the C# initialiser values.** Measured directly rather than inferred: a document whose every fill and border was null in memory came back from disk with a fill block carrying veil static 1 and white, and a border block carrying width 2 and alignment 1. That is why the border's default-off flag closed the border hole and why nothing could close the fill hole the same way - a fill has no "off", and a phantom fill is bit-identical to a legitimately authored white Solid.

**The bug, sized.** ShaperFillResolver.Walk read node.fill, and a node that owns a fill wins inside its own coverage - so on a saved bag each member was painted by its own conjured white Solid and the bag's authored fill painted nothing. On a saved two-member bag, editing the bag's own fill colour changed **0 pixels before this task and 6144 after** - the whole 96x64 canvas. The card was lying in the same breath: on every saved document it offered "Remove fill" and "Remove edge" on every node, including the ones nobody had given either.

**The fix keeps every authored value.** ShaperFillDef.authored and ShaperBorderDef.authored, false by default (load-bearing: a phantom carries the constructed defaults, so false is what a phantom has), set true by every place that creates one because a person asked - DefaultRootFill, the window's "Add fill", "Add edge" and its seeded border fill. A document authored BEFORE the flag is migrated on first read: a deserialized fill whose serialized state differs from a default-constructed one is real authored data and is promoted in place, so nothing is lost, nothing needs re-saving, and no field was renamed, removed or re-defaulted. The comparison is JsonUtility against a cached default rather than a hand-written field list, deliberately - this class has 60-odd authorable fields and gains more, and a hand-written list silently stops migrating the day someone adds one.
