## Description

**Owner (2026-09-29, while answering the ZPOC plan questions on T-0485):** he explicitly asked for this as its own to-do. Add a warnings/diagnostics tab somewhere in the Zounds editor that collects a running list of runtime lookup problems, instead of leaving them only as console lines. Examples he gave: "Zound name called but not found", "Zound X has no track index 2".

Context: the engine already keeps a Missing list for Zounds requested by name that do not exist, and the sound browser shows it. It warns once per name and never throws. The ZPOC plan (T-0485, D:/Claude@GDrive/Zounds Programmatic Control Research 2026-09-29.md, section on graceful failure) adds more cases of the same kind:
- ZPOC id not found anywhere in a play's tree
- track index out of range
- snapshot name not found
- global ZPOC id declared by no Zound

This tab should be the one place all of them land: one row per distinct problem (not per occurrence), with a count, first and last seen time, and the Zound involved. It should be clearable, and follow the Missing list's lifetime rules.

Design is to be settled together with T-0485 before building (the owner's rule: nothing is built until the ZPOC design is settled). It could start from the existing Missing view.

### 2026-09-29T17:32:02Z — agent — in_progress -> in_progress
**Built (commits 9923aa0f and the one after):**
- The Zounds window has a sixth tab, **Problems**. It holds one row per distinct problem: what kind, the sound, what was asked for (in the caller's first spelling), how many times, and when last seen.
- **Open** goes to the sound's editor; **Forget** drops the row; **Clear** empties the list.
- The tab turns amber (the ZPOC colour) whenever the list is not empty.
- A missing sound that has been created since reads "Sound added since", and Open goes to it.

**Lifetime:** the same as the browser's Missing list. It lasts the editor session, survives leaving Play mode, and is not saved.

**Decisions:**
- It is a main tab rather than a ⋮ item, because it needs to be visible (it tints amber).
- Spellings of the same id are merged into one row, using the matching key; the first spelling is kept for display.
- There is no "first seen" column. It is in the row tooltip data but was left off the table to keep it wide-not-tall.

**Verified:**
- **Measured:** kept check 25 passes (every kind of miss makes a row; three spellings make one row; 3000 repeated misses allocate 0 bytes; nothing throws). Checks 20 to 23 still pass.
- **Seen by eye:** screenshots of the tab with five real misses from game-code calls, of the amber tint while another tab is selected, and of the "added since" row.
- **Not verified:** Open and Forget have not been clicked by a hand.
