The Chunks window has a body again, and what is in it is the recipe rather than a fixed set of panels.

A recipe is now an ordered stack of capabilities, so the window is a stack of cards: one per capability, each with a fold, an on/off switch, a move up, a move down and a remove, and one button under the stack that adds another. That button's menu lists the nine kinds and greys the ones that cannot do anything yet, saying which producer they are waiting for - so a trail with nothing to trail is never authored in the first place, rather than authored and then discovered to be silent.

What is on screen follows what the recipe holds. A recipe with one timed capability shows no clock and no delay, because it owns the whole clock and has nothing to be timed against; adding a second makes the clock appear and a delay appear on both cards. A recipe with no layer plan offers no layer slots anywhere. An empty recipe is one button, and a brand-new recipe now really is empty - it used to arrive carrying a debris capability nobody asked for, because a fresh recipe and an old one were indistinguishable at the moment they were read, and there is now a creation-time hook that can tell them apart.

Time actually runs. Play advances the recipe's clock at real speed, Loop wraps it, Replay restarts it, and the scrub handle, the readout and the timing playhead are one instant rather than three that have to be kept agreeing. Each capability's band is drawn at its own start and end, so two things that overlap are drawn overlapping; a switched-off capability keeps its band, drawn faint, so switching one off to look at the rest cannot rescale the ruler or move the picture. I watched it run and captured it a second apart: 0.89 s then 0.92 s of 1.10 s, handle and playhead both moved.

The Pyre Blast card is complete and is the shape the other eight are written against: which blast, a pool to pick between, one or a line or a ring of them with their own count, size, angle, wander, stagger and order, an offset pad, how each one is turned and scaled, a seed, and which named layer slot it draws in. The other eight cards carry their shared rows and say plainly that their own dials are still to come; the preview stage is still a placeholder - it paints the backdrop, the origin and the moving playhead, not yet the schematic of what the recipe throws.

One more thing worth knowing: the preview backdrop is now remembered on the recipe rather than on the window, so the backdrop a burst was tuned against comes back with the burst.

DEVIATIONS FROM THE BRIEF, AND WHY:
1. The splitter is `Z.Split("Chunks.dials", 460, left, right)`, not a hand-rolled 6px divider like Pyre's. The brief asked for a splitter WITH a double-click reset; T-0209 built exactly that into Z.Split, and Pyre's own splitter has no reset to copy. Hand-rolling a second one would be routing around ZUI to reimplement what ZUI just gained. Min width is `leftPane.style.minWidth = 460`.
2. The right pane is a ScrollView. Forced by the measured 820x480 overlap described in the details bucket. Pyre's right pane is a plain column and would have the same defect.
3. Delay is `Z.Float` in a `Z.Field`, not a slider. Its only honest ceiling is the clock's own length, which this dial is one of the things that decides - any range would clamp exactly the edit meant to extend it. Per ui-layout-rules: "slider if the range is real and stable; input if you'd only be guessing the cap." The field is still scrub-draggable.
4. The Timing entry is OMITTED from the section toggle bar when there is no timing surface, rather than passed as null. Verified in ZuiSectionToggleBar's constructor that a null section still draws a labelled (inert) segment - a button promising a section that does not exist. Timing is last, so dropping it leaves every other segment's saved state on its own index.
5. A SECOND Layer Plan is greyed in the Add menu with a tooltip, by the same argument decision 13 makes for Cues: ChunkSpec.ResolveLayers reads FirstEnabled<LayerPlan>, so a second one is authored and never read. The design doc names only Cues; this is my extension of its reasoning, flag it if unwanted.
6. The three MODIFIER placeholder cards carry their TargetRow (Fragment Fracture and Palette Splash carry their LayerSlotRow), slightly more than "a one-line placeholder". A modifier that does not say what it acts on is unreadable, and it exercises the shared helper the next tasks depend on.
7. The preview placeholder paints backdrop + origin cross + a moving playhead as well as the recipe name. Without something that moves there is no way to see that the transport works, which is the one thing this task most needed to prove.
8. Two additions outside the brief: `ChunkSpec.previewBackSplash` (a [HideInInspector] BackSplashSettings, mirroring Pyre.previewBackSplash) so the backdrop belongs to the recipe, and `ChunkSpec.Reset()` for decision 12. Both asmdefs gained a BackSplash reference (Chunks -> BackSplash; Chunks.Editor -> BackSplash + BackSplash.Editor). No cycle: BackSplash references only PreviewKit.
9. Nothing to delete: the old ChunkWindow partials (Formation/Layers/Modifiers/PyreMotion/PyreSpawn/Slicer/Splash/Timeline/Preview) were already gone before this task started - ChunkWindow.cs was a 39-line stub.
