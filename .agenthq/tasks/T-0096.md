## Description

Step 7 of the build plan from `D:\UNITY\Laubrary Dev\ZOE_PALETTE_BUILD_PLAN.md` (task 7 — read that file and `D:\UNITY\Laubrary Dev\ZOE_PALETTE_TAKE.md`, especially the "bypass question" section, before starting). Depends on T-0095.

Plain-language: a small set of visibility tools so nobody — including an AI writing game code — quietly starts making a character show something without going through its declared list of named states. Build:

- Each row/state shows whether anything in the project actually requests it (an existing sibling tool already ships this exact pattern for a different purpose — reuse its approach rather than reinventing it).
- A project-wide check that flags a name something requests that no character declares (this direction likely already has partial coverage — verify).
- The reverse check: a character showing something that did NOT come from its declared palette. This is the one that actually detects a bypass, and per round 3's analysis it's the one direction nothing currently checks — do not skip it as "the same as the first check."
- Deleting a row warns if anything still depends on it.
- A play/preview button on each row so a state can be previewed without the game running.
- A copy-name button for pasting a state's name into code.
- Each character can print its own list of declared states on demand, for someone writing code without Unity open.

Also add a short, explicit rule to this project's own instructions (`D:\UNITY\Laubrary Dev\CLAUDE.md` or the appropriate skill/guide file — follow existing conventions for where such rules live): a character shows things only through its declared palette; if the state needed isn't there, add a row — never spawn the visual directly. This is flagged in the design docs as the single highest-value, lowest-cost item in this whole task — do not treat it as an afterthought.
