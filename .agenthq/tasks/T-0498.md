## Handover Log

### 2026-09-29T15:51:58Z — agent — open -> open
Owner confirmed (2026-09-29): 'a play remembers its own draws so gliding back to Default lands exactly where it started' - 'YES! That's a great idea.' He added: 'Perhaps there is a return object when doing a glide that lets you glide back.'

Decisions (made without asking, per the owner's standing instruction):
1. **The handle.** Starting a glide returns a small, allocation-free handle: the token, a glide serial, and the token's run number.
2. **What glide-back does.** It glides back to the per-parameter state recorded when that glide began, including the run's remembered range draws, so it is exact rather than a re-roll.
3. **Only the latest glide on a play can be reversed.** If another glide has started since, the handle is stale: GlideBack does nothing and returns false. This is silent and not a diagnostics entry, because racing a newer glide is normal game behaviour, not a typo. Reason: the older origin would mix with the later glide's changes and land somewhere nobody authored.
4. **One-shot per handle.** A glide-back is itself a glide and returns its own handle, so toggling A/B means chaining handles. Calling GlideBack twice on the same handle does nothing the second time (it is no longer the latest).
5. **Tied to the run.** A handle is stale once its run has ended or the token has been replayed or restarted, because its origin was that run's state and draws. A replayed token still starts at the last glide target (the target is a setting), but it has no origin to go back to.
6. **Duration.** GlideBack(ms) defaults to the original glide's duration.
