## Description

Step 2 of the build plan from `D:\UNITY\Laubrary Dev\ZOE_PALETTE_BUILD_PLAN.md` (task 2 — read that file and `D:\UNITY\Laubrary Dev\ZOE_PALETTE_TAKE.md` for full context before starting; this is prerequisite work for T-0095).

Plain-language: when a character dies, its ability to be hit again is switched off — correct, you don't want to keep shooting a corpse. But nothing currently switches it back on if that same character is brought back to life and reused, which is exactly what happens on every respawn. The practical effect is a revived character that can never be hit again — this is confirmed to break Mirage's own target-practice respawn feature in a shipped tool today, not just a theoretical case.

Root cause (verified by an adversarial-verify subagent during T-0089 round 4, not yet re-confirmed by whoever picks this up — re-verify before changing anything): `ZoeState.cs` around line 79 disables all child `Collider2D` components on death. None of the three `Health.Revive()` call sites found (`ZoeSpawner.cs` ~line 61, `TargetPracticeController.cs` ~line 94, `MirageSubject.cs` ~line 467), nor `Health.Revive()` itself (`Health.cs` ~lines 99-105), re-enable them.

Fix so `Health.Revive()` (or the appropriate revival path) restores hit-detection colliders. Verify in a running editor with Mirage's target-practice respawn specifically, since that's the shipped tool this currently breaks.
