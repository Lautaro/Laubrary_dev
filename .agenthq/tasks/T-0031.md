### Added 2026-08-24 — user's three concrete use cases, gap-checked against the child tasks above

The user described three specific things they want to build (spawn several pyres in a formation
with stagger; fracture a sprite and layer different pyres around the pieces; a debris source that
follows a moving Transform and repeats). Checking each against the child tasks above:

- Use case "fracture a sprite, layer different pyres behind/front/between the pieces" is already
  fully covered by T-0036 (Fragment Slicer) + T-0037 (Layer Stack) + T-0034 (Pyre Spawner) — no new
  task needed, this one just needs those three built.
- Use case "spawn N pyres in a line/shape, staggered, one fixed OR randomly-per-spawn from a group"
  was NOT covered by any existing child task — T-0034 only ever places one pyre (or one
  random-pick) at a single point, nothing about multiple placement points or timing stagger. New
  child task **T-0079** (Spawn Formation module) covers this; depends on T-0034.
- Use case "a Chunk follows a moving Transform, throws particles backward, spawns a pyre every X
  seconds" was NOT covered by any existing child task — every module here is designed around a
  one-shot burst, none of them attach to and continuously track an external Transform or re-fire on
  a timer. New child task **T-0080** (Follow Emitter module) covers this; depends on T-0033 +
  T-0034.

Both T-0079 and T-0080 have been added to `CHUNKS_OVERHAUL_DESIGN.md` as Standalone modules #8 and
#9. Full manual walkthrough of what's possible today vs. not:
`Assets/Packages/Laubrary/Runtime/Chunks/CHUNKS_USER_MANUAL.md`.

The whole Chunks 2.0 overhaul is built. Chunks is no longer just a debris thrower -- it now composes several effects into one authored explosion: big recognisable fragments, colour splashes, real explosions placed in shapes and thrown around, all in a draw order you decide, on a timeline that can also fire sounds and game signals, previewable in one click.
