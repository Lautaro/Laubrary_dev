## Description

**Filed by T-0313 (A27, ninth structural pass). Measured live at HEAD ae66d31c; write-up in `workspace/T-0313/A27-NINTH-PASS.md` sec 2.4, dumps `out/audit-LauminaryBrowserWindow-w820.txt`, `out/audit-laumination-real-w900.txt`, `out/audit-chunks-w820.txt`.**

Shaper and Pyre hold the standard this programme has been checking them against - a greyed control's tooltip says WHY it is greyed ("No Shaper is open, so there is nothing to save", "Position and range only apply to a Point light..."). Chunks and Launimator do not:

- **Lauminary Browser, 4 of 4.** `Duplicate` -> "Create a copy of the selected lauminary (draft only)."; the name field -> "New name for the selected lauminary."; `Rename` -> "Rename the selected lauminary."; `Delete...` -> "Delete the selected lauminary and every one of its versions (asks first)." All four are greyed because nothing is selected. None says so.
- **Laumination Builder, 14 of 14** (opened on Hero/Idle through `OpenForEdit`, its real door): `Restore`, `Clear`, `Download`, the transparent-colour and tolerance fields, the four marquee fields, `Clear Box`, `Add Region (0)`, `Edit in Aseprite`, `Sync edits`, `Reverse`. Greyed because no sheet is loaded / no marquee is drawn / nothing is selected. None says so.
- **Chunks, 3 of 4**: the two `Sprites` pickers and their count. Chunks' `Save` is the one that does it right - "This Chunk matches what is on disk - nothing to save."

**This also corrects a claim the shared probe library makes, which matters beyond these 21 tooltips.** `ZAudit`'s inert rule counts a disabled control as explained if it has ANY effective tooltip, so all 21 score as `inertWithReason` and 0 as `inertNoReason`. Every "0 disabled without a reason" in this programme - T-0312's included - therefore means "every greyed control has a tooltip", not "every greyed control says why". On Shaper and Pyre the two coincide because their tooltips were written that way; on these windows they come apart. Either the rule tightens (a reason is a tooltip that changes when the control is enabled, or one written in the "X, so Y" shape) or the claim is reworded wherever it appears.

Scope: `Editor/Launimator/LauminaryBrowserWindow.cs`, `Editor/Launimator/LauminationBuilderWindow.cs`, `Editor/Chunks/ChunkWindow*.cs` (tooltip wording only), plus optionally `Zui/Toolkit/ZuiAudit.cs` / the programme's probe library rule. No serialized data changes.
