## Description

Build a new, standalone, reusable ZUI control that edits a **vector** (origin + direction + optional length). No MetaLayer/Launimator integration in this task — this is the raw control, mirroring how `Zui/Toolkit/ZuiEnvelope.cs` is built, so it can be demoed and iterated on by itself before anything depends on it.

**Behavior wanted (from the user, verbatim intent):**
- Click inside the control's frame to position the vector's origin.
- The vector renders as an arrow from that origin.
- Dragging adjusts direction (and length, if length editing is enabled — see below).
- Default length is normalized (1.0) unless the caller configures otherwise.
- The **caller** decides whether length is user-adjustable or fixed via the factory call (e.g. `Z.VectorEditor(..., allowLength: true/false)` — name it however fits `Zui.cs`'s existing factory-method conventions, just follow the `Z.Envelope(...)` pattern for parameter shape).

**Technical approach (from research this session):**
- `Zui/Toolkit/ZuiEnvelope.cs` is the direct model: a UITK `VisualElement`, drawn with `Painter2D`, using pointer-capture-based `PointerDownEvent`/`PointerMoveEvent`/`PointerUpEvent` handling (not IMGUI). Build the new control the same way, own file (e.g. `ZuiVectorEditor.cs` or `ZuiDial.cs` — your call), NOT nested inside ZuiEnvelope.
- **No dial/knob control exists anywhere in `Assets/ZUI` today** — this is genuinely new, not an extension of something existing.
- For quantized angle math (see the follow-up context-card task, T-0002, for the actual quantize UI) the underlying math already exists and matches the project's angle convention exactly: `Runtime/Cookbook/Cookbook2D.cs` — `Dir8`/`Dir16` enums, `ToDir8()`/`ToDir16()`, `AngleDeg()`, `ToVector()`, all using **"0° = up, increasing clockwise"** — the SAME convention `LauminationSetResolver` uses project-wide. Reuse this rather than inventing new angle math. A `Dir4` enum (N/S/E/W only) does not exist yet and would need adding alongside `Dir8`/`Dir16` for the 4-way quantize case — small, same pattern.
- Add a `Z.VectorEditor(...)` (or whatever final name) factory method to `Zui.cs` alongside the existing `Z.Envelope(...)` etc., following that file's established calling convention.

**Explicitly OUT of scope for this task** (separate tasks): the right-click context card with toggles/quantize (T-0002), any MetaLayer/Launimator wiring (T-0003 onward).
