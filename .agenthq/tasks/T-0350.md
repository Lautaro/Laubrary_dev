Every ZuiAssetWindow<T> tool (Chunks, Pyre, and ~16 others: BackSplash, Cartographer, PropWindow, TilesetBuilder, Choreographer, DotGen, Larder, LatheMold, LatheWindow, SpriteCatalog, Mirage, SpriteFxStack, Tapestry, TextSplash, Zoetrope) now reopens onto the asset it was editing instead of the browser. Fixed once in the shared base. Falls back silently to the browser if that asset was deleted/moved meanwhile, and never overrides an explicit open (double-click asset, Mirage handoff).
**Details:**
Editor/AssetKit/ZuiAssetWindow.cs: SetAsset now mirrors the current non-sub-asset's GUID into EditorPrefs (key includes concrete window type + this project's Application.dataPath, so two projects/types never collide). OnEnable restores it (GUID -> AssetDatabase path -> LoadAssetAtPath<T>) but only when the window comes up with asset==null and browsing==false -- both true for a genuine cold reopen. This deliberately never runs when a caller calls SetAsset explicitly right after GetWindow (that happens after OnEnable and simply overwrites), and never runs when Unity's own [SerializeField] serialization already restored the asset across a plain recompile of a window that stayed open (asset would already be non-null by the time OnEnable's check runs). Sub-assets (e.g. a Zoe's embedded private Chunks) are excluded from being remembered -- they're only ever reached via an external explicit 'Edit' entry point anyway.
