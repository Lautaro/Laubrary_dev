Section toggle buttons now have a Solo mode: right-clicking a section's button in the toggle bar hides every other section and puts a green outline around the soloed button, so you can focus on just the parts you're working on.
**Details:**
How to use it: switch a tool's section bar to 'Toggle Bar' mode, then right-click any section's button to solo it (left-click still does the old show/hide). You can solo more than one section at once -- they all stay visible together while everything else hides. Right-click a soloed button again to un-solo it; once every solo is removed, all the sections go back to exactly how they were before you started soloing.

This only works in the Toggle Bar mode (not the classic per-header-click mode), since that's the only place these buttons exist. Verified in the Pyre Plus editor window; any other Laubrary tool that adopts the same section-toggle-bar control gets this for free.

Not yet verified: a real mouse right-click through the actual UI (this was proven via direct calls to the same code path plus a real on-screen screenshot of the resulting look, not a literal mouse click).
**Technical details:**
Files: Assets/Packages/Laubrary/Zui/Toolkit/ZuiSectionToggleBar.cs (solo logic), ZuiSegmented.cs (added SegmentAt(int) so the bar can reach individual buttons), ZuiToolkit.uss (.zui-segmented__solo green-border rule). Model: HashSet<int> _solo + bool[] _preSolo snapshot taken on 0->1 solo transition; ToggleSolo(idx) recomputes each ZuiSection.IsOpen from the solo mask (or restores _preSolo when the set empties) and re-lights the ZuiSegmented via SetOn. Left-click while solo is active is a no-op (guarded in the onToggled callback, since ZuiSegmented's Clickable already flips the visual class before the callback runs -- re-call SetOn to correct it). Right-click is safe to own outright since UI Toolkit's Clickable manipulator only engages for the left mouse button. Leaving Toggle Bar mode clears any active solo (ClearSolo, called from Apply()). Verified functionally via reflection-driven calls to the private ToggleSolo method against PyreWindow's live ZuiSectionToggleBar (8 Pyre sections): single solo, multi-solo, partial un-solo, and full clear-restore all produced the exact expected IsOpen/class-list state. Verified visually via a PrintWindow screenshot of the same window mid-solo (Views + Shape soloed) -- only those two sections rendered, both with the green ring, everything else gone. Gotcha for future agents: creating/editing a new scratch .cs file under Assets triggers a Unity domain reload, which wipes ZuiSection's static IsOpen dictionary AND any live ZuiSectionToggleBar instance (fresh _solo/_preSolo) -- do the state-mutation and the screenshot/verification in the SAME execute_script call if you need them to reflect each other; splitting across two coplay calls that each touch new files will silently reset state in between.
