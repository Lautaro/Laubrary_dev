## Description

Lautaro's own words (2026-09-07): "In floating disc zoe: i see that there are chunks configured with floating disc debris. It should be possible to have an inline Chunks, or private chunk. That is a debris spray that is bespoke to this zoe and there is no point in cluttering the browser window. Change it so that its possible to choose a public or create an private asset. If its private it needs an edit button cause its the only place where the asset can be edited from."

Context: Floating Disc's Zoe has a Chunks debris effect ("floating disc debris") authored as a normal shared/public Chunks library asset -- visible and pickable in the Chunks asset browser -- even though it's bespoke to this one character and nobody else should ever need to pick it from the library. Lautaro wants the option, when authoring a Chunks (or any similarly-scoped) reference on a Zoe, to choose between:
- Public: today's behavior, a shared library asset picked via the normal browser/picker.
- Private: an asset embedded/owned by this specific Zoe (or this specific reaction row), not listed in the shared browser, that only this Zoe can see or reference.

If Private is chosen, the Zoe editor's effect row is the ONLY place that private asset can be edited from (it isn't in the browser to open separately), so that row needs its own Edit button to open/edit the embedded asset in place.

Likely needs: read the LauAsset / AssetKit conventions (~/.claude/skills/laubrary/, Assets/Packages/Laubrary/Editor/ AssetKit base, LauAssetField/Picker) to see whether there's already a public/private or embedded-vs-referenced asset pattern elsewhere in Laubrary to extend, rather than inventing a new one. This is likely a reusable pattern (any LauAsset-style reference could conceivably want private/embedded mode), but scope THIS task to the Chunks reference specifically (Floating Disc's debris) -- generalizing further is a judgment call for whoever picks this up, not a requirement.

**Details:**
How to use it: open a Zoe in the Zoetrope window, find a Chunks effect row (Hit or Death reaction) — it now has a Public/Private toggle next to the picker. Public works exactly as before. Click Private: if nothing was assigned yet, or something public was, it makes its own private copy embedded in the Zoe's file and switches to it. A Private row shows the asset's name plus an Edit button — click that to open it in the normal Chunks window, since it's not in the shared browser anymore (that's the point). Switching back to Public never deletes anything — it just changes what the row shows; the private copy stays embedded and safe if you want to go back to it.

Floating Disc's 'Floating Disc Blowup' death debris is now Private on its own Zoe (verified this was safe: the original shared asset is untouched and the ChunksDemo scene still uses it fine). Scope note: this only applies to Chunks references on a Zoe reaction row, per the task's own scope — not rolled out to every LauAsset type in the codebase.
**Technical details:**
Public/Private needs no new serialized flag: 'Private' just means the referenced ChunkSpec is a SUB-ASSET embedded in the Zoe's own .asset file (AssetDatabase.AddObjectToAsset), and the mode is read straight off whether the current reference lives at the Zoe's own asset path (AssetDatabase.IsSubAsset + GetAssetPath match). New/changed code:
- D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Editor/Zoetrope/ZoetropeWindows.cs — BuildChunksRefRow/MakeChunksPrivate/IsPrivateChunks, wired into the existing generic TryBuildAssetRefField for field.FieldType == typeof(ChunkSpec). Edit button goes through the existing LauAssetEditors.Open registry (ChunkWindow.OpenFor), same entry point the old right-click 'Edit' menu already used.
- Two real bugs caught and fixed live via play-mode probing before landing: (1) EditorUtility.CopySerialized also copies the source's own name, so it must run BEFORE setting the private asset's intended name, not after (a copy of 'Sparks' briefly came out named 'Sparks'). (2) the click closure must capture prop.Copy(), not the live SerializedProperty iterator the caller's property-walk keeps advancing after the row is built, or a click fires against whatever field the iterator drifted onto afterward (a click created a sub-asset assigned to the WRONG field, named after an unrelated sibling property).
- D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Editor/AssetKit/AssetLibrary.cs and AssetLibraryUntyped.cs — Enumerate() now excludes AssetDatabase.IsSubAsset() results. Root cause: AssetDatabase.LoadAssetAtPath<T> falls back to a matching SUB-asset when a path's main asset is a different type (confirmed live) — without this fix, an embedded ChunkSpec inside a Zoe (main type Zoe, not ChunkSpec) still surfaced in every LauAsset browser/picker built on this shared enumeration, defeating the whole feature. This fix is general (any future 'private' LauAsset embedded this way benefits), not Chunks-specific.
- D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Editor/AssetKit/ZuiAssetWindow.cs — Duplicate/Rename/Delete toolbar buttons and the Tags section are now hidden when AssetDatabase.IsSubAsset(asset) is true. Root cause: those actions operate on the asset's FILE PATH (AssetDatabase.CopyAsset/RenameAsset/DeleteAsset), which a sub-asset shares with its owner — without this guard, opening a private Chunks sub-asset via Edit and clicking 'Delete' would have deleted the owning Zoe's entire file.
