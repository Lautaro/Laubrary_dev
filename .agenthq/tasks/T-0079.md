## Description

Chunks/Pyre today have no way to place several instances of something (e.g. several PyrePlus blasts) at multiple points in a line or shape with staggered timing -- confirmed absent from both Chunks (ChunkSpec/ChunkEmitter) and Pyre itself (no reusable spawn-shape/formation utility exists anywhere in Runtime/Pyre, checked via a full grep for Shape/Formation/SpawnPattern -- the only "Shape" hits found are Pyre's own blast-FORM enum, which is unrelated visual shape, not a spawn-position pattern). Needed for two of the user's requested use cases: (1) "spawn N pyres in a line/shape with life stagger, the pyre chosen via a LauAsset picker" and (1b) the same, but each spawn point randomly picks one pyre from a user-defined group instead of always the same one.

New standalone module: given a shape spec (start with line + circle/ring, the two implied by the request) and a count, computes N world offsets from an origin, then calls the Pyre Spawner module (T-0034) once per offset with a per-instance time delay -- "life stagger" means spawn point N fires staggerSeconds * N after the burst starts, not all simultaneously. Each spawn point independently draws from either one fixed PyrePlus blast (use case 1) or randomly from a user-configured pool of blasts (use case 1b) -- the pool-random behaviour piggybacks directly on T-0034's own "pick randomly from a configured pool" feature, so this module's own job is purely placement + stagger, not picking.

One correction worth carrying into the build: Chunks does not bake a new effect here -- it plays already-authored PyrePlus assets. "Formation" is about WHERE and WHEN each existing pyre fires, not about generating new pyre content.

**Depends on T-0034** (Pyre Spawner must exist first to have something to place in formation). Must work standalone otherwise (no layering/timeline/Fragment Slicer required) per the design doc's standalone-first principle. Gets its own collapsible ZUI section, ZUI-only, no raw IMGUI. See CHUNKS_OVERHAUL_DESIGN.md (updated with this module as "Standalone modules" #8).
