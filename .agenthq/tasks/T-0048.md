**Design decisions (logged, not asked):**
- **One program, five presets → variant enum + one settings box per variant.** `heat_field` is ONE program for all five draws; the draws differ only in values (components switch on by value: pulse > 0, lash > 0, curl > 0, glow > 0, tongues > 0, embers > 0). PyrePlus has no preset-apply mechanism for a reflected form (and adding one is editor surface this task must not grow), so the five looks are reachable the Orb way: `variant` + `[ZUIShowIf]` boxes — but unlike Orb the box class is ONE `TorchSettings` with five factory constructors (`Emberbed()`, `Surge()` …), so the dial set is written once and each box's defaults are that draw's contract values.
- **Canonical / default variant = `barbs`** (#003), not #001 `emberbed`. MANIFEST names no canonical; #001 is merely first in the calm→violent order and is a 124 × 80 BRAZIER (a wide coal bed) that cannot fit PyrePlus's 64 px square at the 0.55 canvas-fraction heights the family uses. `barbs` is the 0115 TORCH — the near-parallel licking column the form is named for, 64 px wide at source, the one the brief's "torch" means. Logged here and in the file header; the shared placement dials default to barbs' own contract frame (axis 0.5, ground 0.085, height 0.627 on the 118 px letterbox square).
- **Units:** the program runs in the draw's SOURCE px frame (as Orb does): u = (height × canvas H) / hFlame; every px-unit dial inside the box (w0, wmin, xsc, ysc, sway, lean, lash, glow, tongue / ember ranges, curl) is in source px, so the picture is the source's magnified to the dialled height. Shared dials are canvas fractions: `axisX`, `ground` (fuel bed, fraction of the canvas height from the BOTTOM), `height`. The flame is evaluated only inside the draw's own FRAME rect (its source W × H around cx / base_y, mapped through u) — that is what the source renders (outside it is the canvas edge, transparent) and it is what bounds the cost of the swarm.
- **Curl RMS:** the source normalises the curl displacement by the RMS over the WHOLE SUPERSAMPLED FRAME, per frame (`curl_warp`, inside `heat_field`). It is a frame statistic but NOT a cross-frame fit — each frame is standalone, so it needs no `PlusClipStats` and stays exactly as the source does it (PlusClipStats would change the picture: every frame's scale would become one pooled number, which is not what the contract planes hold). The statistic's region is the frame rect above (at the contract canvas = the contract's own sample set, `np.gradient` one-sided at the rect edge exactly as the source).
- **Loop:** t = frameIndex / frameCount (the source's `i / frames`, NOT life = i/(N−1)): one period = the clip, seamless by construction; `pulseN`, `lashK` stay `int`.
- **Pairs** (`tongue_x` … `ember_size`): `Vector2` fields with `[Range]`; `ZuiReflect` gained a tiny additive rule — a `[Range]`-bounded Vector2 draws as ONE `Z.MinMax` range slider (the UI Guide's pair rule, fixed in the wrapper so every reflected pair benefits); an unbounded Vector2 draws as before.
- **Ramp:** the banded palette ships as `PlusRampPresets.TorchHot / TorchEmber / TorchWhite / TorchRim / TorchGold` + `Torch(name)` exactly as the contract's ramp.json writes it (stepped stops at threshold / top, sRGB, alpha 1) with `rampTop` (the top threshold in field units) as a dial; the form reads the ramp as hard bands (`PlusShade.Banded(t, thresholds, colours)` after collapsing repeated positions), never a LUT — the source interpolates nothing.
- **Supersample:** the field at 3×, premultiplied planes box-filtered ONCE through `PlusSupersample.Downsample(float[] …)` (the Plasma overload; the byte-first overload would round each supersample first).
- **Swarm:** one flame per instance rooted at the particle (base anchor = the particle's position, y-up → the fuel bed), scaled by Swarm Size × sizeMul, heat × brightMul, tongue / ember / noise streams salted by the instance index; heats and colour fields SUM (fire over fire burns hotter), cost ∝ instances × frame rect.
