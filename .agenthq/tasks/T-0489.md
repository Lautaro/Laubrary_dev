## Description

Owner: "How does Keep Length, Time and Live Speed toggle synergise? It seems to be they overlap and its unclear which one does what at a given time. I think we should be stricter to be clearer. Perhaps different modes that governs pitch and time possibilities?"

STATUS: PROPOSAL ONLY, nothing built. Waiting for the coordinator/owner to agree the mode set.

WHAT HAPPENS TODAY (traced through the code by a read-only research pass; not probed in the editor):
- Pitch and time are really two separate axes that multiply: what you hear as pitch, and how fast the source is used up. The confusion comes from three facts:
  1. FOUR different switches can each silently turn on the time-stretcher (Live speed, Keep length with a pitch curve, a Time curve, an old stretch setting). Anything bound to Speed is only heard while the stretcher happens to run.
  2. Game code's speed (bullet time) follows 'is the stretcher running', not the Live speed toggle, although the toggle's tooltip says otherwise. So bullet time slows a sound that has a Time curve or Keep length, but not a plain one.
  3. Keep length only does anything when a pitch curve exists; on its own it is shown 'on' and does nothing.
- The Klip's random pitch range is ALWAYS tape-style (changes pitch and length together), even with Keep length on.
- Nothing 'wins' when everything is on: pitch curve, pitch range, Live speed, Time curve, old stretch and game speed all multiply; each piece is clamped separately and the total speed is clamped to x0.05..x8.
- Combinations that are silently ignored: Keep length without a pitch curve; a stored Live speed while the toggle is off; a non-curve modifier (LFO, random) on Speed while no other switch runs the stretcher. Double-applied: an old Region/Curve stretch plus a new Time curve (the old one is not drawn on the waveform). Also: stretcher settings are fixed when a play starts, so toggling Keep length/Time/Live speed on a playing sound is only heard from the next play.

PROPOSED MODEL: one per-Klip choice, 'Pitch & time', a two-way segmented control on the waveform toolbar where Keep length sits today:
- TAPE (like a record or tape): pitch and speed are one thing. The pitch range and the pitch curve change pitch AND length together. No stretcher. Shown: Pitch curve, pitch range. Hidden: Time curve, Speed, stretcher settings (Window, Keep hits, algorithm). Game speed: not applied (exactly as a plain sound today). A Looper keeps its crossmix.
- INDEPENDENT (pitch and time are separate): the pitch curve (and, see question 1, the pitch range) changes pitch only; length is governed only by the Time curve x Speed (x game speed). Always uses the stretcher. Shown: Pitch curve, Time curve, Speed (always visible, 1 = unchanged; no separate Live speed toggle), stretcher settings. A Looper loops without the crossmix (the stretcher's existing limit), said on hover.
- Removed: the Keep length toggle and the Live speed toggle (both become the mode). A third 'Pitch only' mode was considered and left out: it is Independent with the Time curve off and Speed 1, so it would add a choice without adding a behaviour.

OLD SOUNDS SOUND EXACTLY AS NOW (worked out when the sound is loaded, written on the first edit, as with the pitch-curve and old-stretch conversions):
- No stretcher running today -> Tape (identical; this includes Keep length on without a pitch curve, which does nothing today, and a stored Live speed with the toggle off).
- Stretcher running today -> Independent (identical for: pitch curve + Keep length; Time curve; Live speed; old stretch -- game speed also applies today in all of these).
- The one case that needs real conversion: stretcher running AND a pitch curve WITHOUT Keep length (today that curve still changes length, tape-style, on top of the Time curve). Converted exactly by moving the curve's length effect into time: a copy of the pitch curve is added on Speed next to the Time curve. Exact for ordinary curves; for a pitch curve with random points the copy would draw its own random positions, so those few sounds would differ slightly -- to be listed by a check before converting.
- A stored Live speed that was inert (toggle off) is reset to 1 on conversion, so it cannot suddenly become audible.

QUESTIONS FOR THE OWNER:
1. In Independent, should the Klip's random pitch RANGE also keep length (consistent: 'pitch never changes length in this mode') or stay tape-style as today? Consistent is clearer, but it would change existing Independent sounds that have a pitch range other than a single value.
2. In Tape, should game code's speed (bullet time) slow the sound tape-style (pitch drops with it) instead of being ignored? Today it is ignored; changing it is a behaviour change for every plain sound.

SUSPECTED BUGS found on the way (read from code, NOT measured): switching Pitch on for a sound with no pitch modifier may create a flat +2-octave curve instead of x1 (it seeds from the unused old pitch field); dragging Speed on a playing sound drops an old Uniform stretch factor until the next play; an enabled but flat old Curve stretch still counts as 'effective' and runs the stretcher; at extreme settings the speed clamp breaks Keep length and the 'Plays X s' readout is wrong; an old stretch Convert can store a Speed outside the slider's range.
