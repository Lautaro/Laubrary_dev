## Description

**Read first:** `D:\Unity\UNITY_DEV_GUIDE.md` and the Laubrary skill (`~/.claude/skills/laubrary/`). This is a Laubrary tool (shared library), consumed per project.

**Problem (Lautaro, 2026-09-06 23:15, live in ProtoGuyDemo):** "Everything is too large. I suspect the camera is wrong. So we need some function that can set the camera and everything else correct as per the project settings. Like if it was a 320x200 screen." He does NOT want a hardcoded value: "I want the settings to be per project and I want the gameplay to reflect that per default (it should be possible to override with explicit settings in a scene)."

**What to build:**

1. **A per-project settings asset** (ScriptableObject in Laubrary, one instance per project, found via a single static accessor with a sensible fallback if the project has none) holding:
   - `pixelsPerUnit` = 16 (the tile unit; OutBurner already enforces this in `Assets/OutBurner/Editor/PixelArtImportPolicy.cs` — leave that policy alone in this task, just make the number live in the asset)
   - `targetResolution` = 320x200 (internal world-layer resolution)
   - `referenceHumanHeightPx` = 32 (proportion reference; ProtoGuy is ~22-34 px at PPU 16)
   - Reference target display: Steam Deck 1280x800 = exact 4x.

2. **One shared helper** (static, in Laubrary) that derives everything from the asset, so no tool computes it itself:
   - orthographic camera size for the target resolution: `targetResolution.y / (2 * pixelsPerUnit)` = 6.25 for the defaults
   - integer upscale for a given display: `floor(displayHeight / targetResolution.y)` (4x on the Deck, 5x on 1080p; letterbox the remainder; wider screens simply see more width, nothing cropped)
   - "preview zoom 1" multiplier for editor previews = that same upscale for the monitor the editor is on

3. **A runtime component that applies the camera fit by default**, e.g. `PixelScaleCamera` on a Camera: on enable it sets the camera orthographic and its size from the helper, and keeps the world-layer pixel-perfect look (integer upscale + letterbox, or the Pixel Perfect Camera package if it is already in the project — check before adding a dependency). **Per-scene override:** the component has an explicit "Override project settings" toggle with its own values; when off it follows the project asset. That toggle is the override mechanism he asked for. UI/text canvases are NOT affected — they render at native resolution (his rule from 19:10: "no point making it harder to read just for retro purpose").

4. **Wire it into the two scenes he actually runs:** `Assets/Demos/ProtoGuyDemo/ProtoGuyDemo.unity` (the scene he is in right now) and Mirage's preview camera (`Runtime/Mirage/`). Both should show a 320x200 world at the correct upscale with ProtoGuy at his true size (~2 world units tall) as soon as Play is pressed, with nothing set by hand in the scene.

**Constraints:** PPU stays 16; do not retouch any art, import settings or the import policy. Keep it small — a foundation, not a tool with a window. Follow the UI guide for any inspector UI. Do not touch `D:\Unity\OutBurner` in this task (a follow-up will point OutBurner's own asset + racer at this).

**Done looks like:** (a) the asset type exists and Laubrary Dev has one instance with the defaults above; (b) the helper returns 6.25 / 4x / 5x for the numbers above (assert it in a small edit-mode test); (c) pressing Play in ProtoGuyDemo shows the 320x200 view at an integer upscale with the camera size coming from the asset, and flipping the scene override toggle changes it; (d) Mirage's camera uses the same helper; (e) CHANGELOG entry. Report verified-by-probe vs verified-by-eye separately — you cannot see the Game view, say so.

**Context:** this is the first step of his to-do list in the ProtoGuy Planning tab (`.agenthq/planning/ProtoGuy.json`): camera fit -> disc hit effects -> ProtoGuy muzzle light -> disc death.
