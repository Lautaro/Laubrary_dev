## Description

**Owner report (2026-09-21), live-testing UC5 (Fragment Fracture) via a real kill in ProtoGuyDemo:** the disc fractures into 3-4 pieces with the right colours, but the fragments render sub-pixel tiny — visibly wrong next to UC4's correctly-sized debris.

**Root cause, already found and fixed by this PM session (not by a subagent yet — code changes are done, need compiler + live verification):**

`FragmentFracture.cs` computed its cut pieces' pixels-per-unit straight from `src.pixelsPerUnit` — the live sprite's own baked import value — while `DebrisScatter` (what UC4 uses) was deliberately given a project-setting-first rule back in T-0383: `useProjectPixelScale`/`EffectivePixelsPerUnit`, defaulting to `PixelScaleProjectSettings.Instance.pixelsPerUnit` (the project's global 16) with an explicit per-recipe override only when turned off. `FragmentFracture` never got that treatment, so it inherited whatever PPU happened to be baked onto the live Zoe sprite at import time — the same class of drift T-0383 through T-0386 hunted down everywhere else this session (Pyre, Mirage, BackSplash).

**Already changed, by hand, this session (verify these compile and behave correctly, do not re-derive them):**
1. `Runtime/Chunks/Capabilities/FragmentFracture.cs` — added `useProjectPixelScale` (bool, default true) + `pixelsPerUnitOverride` (float, default 32) + `EffectivePixelsPerUnit` property, exact mirror of `DebrisScatter`'s own fields. `Fire()` now reads `ppu = EffectivePixelsPerUnit` instead of `src.pixelsPerUnit`, and passes it into `FragmentCutter.Cut(...)`.
2. `Runtime/Chunks/Slicer/FragmentCutter.cs` — `Cut`/`CutUncached`/`BuildPieces` now take an explicit `pixelsPerUnit` parameter instead of reading `source.pixelsPerUnit` internally (this affects BOTH the built sprite's PPU and the `offsetUnits` piece-placement math, which also used the wrong PPU before). The seeded-cut cache key (`CutKey`) now includes the ppu (as its raw bits) so a stale cached cut from before this fix — or a future author toggling the setting — can never silently return pieces sized/placed for the wrong PPU.
3. `Editor/Chunks/ChunkPreviewSim.cs` — the standalone editor preview's own cut call updated to pass `f.EffectivePixelsPerUnit` too (was also reading `src.pixelsPerUnit` directly, same bug, would otherwise have shown a preview that lied about the runtime fix). `CutLook.ppu` added so the preview's own re-cut cache invalidates when the toggle changes.
4. `Editor/Chunks/ChunkWindow.FragmentFractureCard.cs` — added the same "Use project pixel scale" toggle + override field UI as `DebrisScatterCard`, inserted right after the Pieces/Min area/Seed row.
