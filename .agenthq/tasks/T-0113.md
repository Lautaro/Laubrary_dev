## Description

Swarm becomes a modifier available on every generator. Two implementations behind one control: a generic wrapper that instantiates any generator N times with per-instance clocks, seeds, positions and parameter jitter, and a native path for generators that can do it more efficiently or want their instances to interact. Which one is in use must be shown, not hidden, because it changes what the controls mean. Two things needing real work rather than wrapping: the simulation-based generators, where N independent instances is an asymptotic blow-up rather than a linear cost (measured at roughly 200x cell updates for a realistic swarm), and the generators whose per-instance parameters do not exist yet. Also fix, during the port, that most big effects start every instance on the shared clock so instances pop in mid-animation instead of having their own lifetimes.

The authoritative design is the "Shaper - the design" tab of this group's planning document (also at D:\UNITY\Laubrary Dev\.agenthq\workspace\T-0098\SHAPER_THE_DESIGN.md). Read it before starting. Background: the three earlier reports are tabs of the PyrePlus group's planning document, and a condensed digest of them (incl. every withdrawn claim and every known live bug) is at D:\UNITY\Laubrary Dev\.agenthq\workspace\T-0098\P1-digest.md.

Swarm now works as an on/off group option for any Shaper shape: turn it on, tell it how many copies you want, and it scatters that many staggered-lifetime copies of the shape instead of one, without you writing any new code for that shape.

[[attach:20260831T210105Z_SWARM-SPEC.md]] [[attach:20260831T210105Z_VERIFICATION.md]] [[attach:20260831T210105Z_swarm-contact-sheet.png]]
**Details:**
Two ways of making a swarm are built. The everyday one (Generic) works on any shape already in Shaper with zero extra work. A second, faster way (Native) is available for shapes that can share one simulation instead of running many separate ones -- this was built and proven for one representative simulation-style shape (a toy glowing-ember effect), not yet for every shape kind. Whichever way is actually running is always reported honestly, never hidden, since a couple of the controls only do something under the fast path.

A real bug in how these copies used to start (all of them beginning their animation at the exact same moment, so they'd all look identical instead of looking like independently spawned effects) is fixed by default, and the old broken behaviour is kept as an option so it can still be shown for comparison.

Not yet verified by a human: nobody has looked at this running live inside the Unity editor UI -- there is no on-screen swarm control panel yet for Shaper at all (none of this rebuild's tools have one yet), so everything below was checked through automated numeric tests and a rendered picture, not by clicking around in the editor.

How to use this: there is nothing to click yet -- this is backend/engine work for whoever builds the next Shaper tool feature (a full authoring window) to build on top of.
