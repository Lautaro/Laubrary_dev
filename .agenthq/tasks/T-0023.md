## Description

User request: "add a function for metaLayer editor where I can copy/paste a frame. in case same position is
used for most frames." — motivated directly by T-0021's alignment workflow, which needs a "Waist" point painted
on ~40 Legs frames plus 16 Upper frames; many of those points will land in roughly the same place across
several consecutive frames.

## What was built

`Assets/Packages/Laubrary/Editor/Launimator/LauminationBuilderWindow.cs`, the meta-layers panel (Shape/Point
mode — the pixel-mask `MetaFrame` data, not Vector mode's separate `VectorMetaFrame` data, which isn't wired
into this window's UI yet):

- **`_metaFrameClipboard`** — a single static clipboard (last-copied wins), same pattern
  `PyreWindow.Modifiers.cs`'s modifier clipboard already uses, so it survives closing/reopening the window.
- **"Copy frame"** button — clones the active layer's current frame (mask + free-text param) into the
  clipboard.
- **"Paste"** button — pastes the clipboard onto the current frame only. Disabled until something's copied.
- **"Paste all"** button — pastes the clipboard onto EVERY frame of the active layer in one click. Disabled
  until something's copied. This is the one that directly answers "same position used for most frames": copy
  once, Paste-all, then repaint just the handful of frames that actually differ.
- New helper `PasteMetaFrameInto(MetaLayer, int frameIndex)` resamples the pasted frame to the TARGET frame's
  own baked size (nearest-neighbor, via `MetaFrame.EnsureSize` — already-existing, already-used-elsewhere
  logic) before assigning, so copying between frames of different baked dimensions degrades gracefully instead
  of corrupting the grid, rather than assuming every frame is the same size.
- Both paste buttons and their disabled-until-copied SetEnabled wiring mirror the modifier-clipboard pattern
  already established elsewhere in the codebase — no new UI idiom introduced.

## Verified

- Compiles clean.
- Logic-level test: created a real `LauminationBuilderWindow` instance via `EditorWindow.CreateInstance`,
  populated fake baked-sprite/sequence state via reflection, painted a test cell on frame 0 of a Point-mode
  layer, invoked the ACTUAL private `PasteMetaFrameInto` method (not a hand-rolled equivalent) to paste onto
  frame 1, confirmed the painted cell round-tripped correctly and frame 1 is a genuinely separate `MetaFrame`
  instance (not aliased to frame 0's). Scratch test script deleted after passing.
- **NOT done**: a real mouse-driven Handover Walk (open a Lauminary with a Point layer, actually click Copy on
  one frame, scrub to another, click Paste/Paste-all, see the point appear) — the logic path is proven, but
  nobody has clicked the actual buttons in the running editor yet. Worth doing before/while using this for the
  T-0021 "Waist" point authoring pass, since that's the first real use.
