## Description

### Why

The UI rulebook requires every hoverable control to explain its actual effect. These did not: the hover text was the
parameter's own name read back with its units appended, which is useful only to somebody who already knew. A name is a
handle for a thing you understand, not an explanation of it.

This surfaced through a real question rather than an audit — the owner asked what an oscillator's curve was for, having
reasonably taken it for a waveform option. That one was fixed with a caption, but the same gap ran through every setting
in the chain editor.

### What changed

Every effect and modulator setting can now carry a description of its effect on the sound, and sixty-nine of the
seventy-six settings have one. Lists of choices explain each option separately, since that is exactly where the words are
jargon — telling somebody a waveform is a "saw" explains nothing about why they would pick it.

Written for a reader who knows what a filter is but not what this particular control will do: what happens when it goes
up, what happens when it goes down, and what it is normally used for. Anything not yet described falls back to the old
wording, so the change can only improve and never regress.

### Remaining

The seven without a description are the source-stage settings and a few choice lists that carry per-option text instead.
