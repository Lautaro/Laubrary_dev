## Description

A "Preview in Mirage" button on the Chunks window that builds a throwaway `MirageView` (never saved as an asset)
holding the current recipe and opens Mirage, exposing the Timeline (T-0038) for scrubbing — the exact pattern
`ZoetropeWindows.cs` already uses for a Zoe's rig (`PreviewInMirage(zoe)` → `MirageWindow.OpenFor(view)`).

**Open risk to resolve first:** Mirage previews are built for continuous/looping assets; a Chunks burst is a
one-shot. Needs a re-trigger/replay affordance (a HUD button) — confirm how cheap that is in Mirage today before
committing to the final shape. See `CHUNKS_OVERHAUL_DESIGN.md` §"Standalone modules" #7 and §"Open questions".

Best done last / near-last — needs at least one real module (T-0033..T-0036) and ideally the Layer Stack (T-0037)
to have something worth previewing.

There is now a "Preview in Mirage" button on the Chunks window that opens your recipe in the preview stage without saving anything, and because an explosion happens once rather than looping, the preview carries a Replay button so you can watch it as many times as you like.
**Details:**
How to use this: at the bottom of the Laubrary -> Chunks window press "Preview in Mirage". It is greyed out with an explanation when there is nothing worth previewing yet. Once open, press "Replay burst" to fire it again; there is also an opt-in auto-replay on a timer, off by default because an explosion going off continuously is impossible to look at. A Chunk recipe can also now be ADDED to an existing preview alongside a character or another effect, so you can see how they read together. Note: bursts only fire in Play mode -- outside it the preview says so instead of showing a dead button.
**Technical details:**
D:\UNITY\Laubrary Dev\Assets\Packages\Laubrary\Runtime\Mirage\MirageChunkBurst.cs (new driver), \Mirage\MirageRig.cs (a case ChunkSpec in SpawnEntry, before the default warning), \Mirage\MirageHud.cs (the replay controls), \Mirage\com.Lautaro-Arino.Laubrary.Mirage.asmdef (+ Chunks reference), D:\UNITY\Laubrary Dev\Assets\Packages\Laubrary\Editor\Chunks\ChunkWindow.MiragePreview.cs, \Editor\Chunks\ChunksEditor.asmdef (+ Mirage and Mirage.Editor). No cycles: Chunks never references Mirage. MirageRig deliberately does NOT call ApplyScale for a ChunkSpec -- the other cases normalize source-sprite PPU, but a ChunkSpec is authored in world units and Chunk writes transform.position in world space, so a parent scale would resize the sprites without resizing their trajectories and the burst would visibly come apart. MirageChunkBurst.Fire calls ChunkEmitter.SpawnBurst so the composed 2.0 modules run inside it and a layered recipe previews as a layered recipe; it clears the previous container first (destroying rather than hand-releasing, because SpawnBurst subscribes a one-shot Finished release per chunk and an early manual release would double-release into the free list). Auto-fire happens on the first Update tick, not Start/OnEnable, mirroring the trap MirageSubject documents. The replay control is deliberately NOT gated behind entry.manualControls the way Zoe controls are: a Zoe keeps playing on its own so its controls are a decline-able convenience, whereas a burst without a re-fire is a preview you can watch exactly once. PM FIX ON TOP: MirageAssetPicker.SupportedTypes and FindAll were Zoe+Pyre only, so a ChunkSpec could never be ADDED to an existing view -- the subagent flagged it and could not fix it in scope; ChunkSpec is now in both.
