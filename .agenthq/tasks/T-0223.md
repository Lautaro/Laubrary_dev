Beside a gradient the star and the Adjust box sit exactly where they did before T-0221.

The eight keys are a PICTURE, not a limit. Showing a fourteen-stop palette subsamples to eight for the bar, with the real end colours kept, and writes nothing — so a Pyre preset, or a big palette applied from the star library, keeps every stop it has and renders with all of them. Only actually changing something in the popup writes back, and that necessarily collapses the ramp to the eight the field held. The bar's tooltip says so before you touch it, naming the count that would go. Measured, not asserted: all 31 shipped Pyre ramp presets are untouched by being displayed, ramps within eight keys survive a full trip through the popup, and the Shaper demo document plus three authored Pyre assets render to an identical hash — including after every ramp in them is edited through the field, since none of the three exceeds eight stops.

**Technical details:**
THE CONTROL. ZuiRampControl is now a GradientField (UnityEditor.UIElements) + the star Button + the ramp's BlendModeNames as a Z.Segmented, in a wrapping row. The bespoke Strip class, its Painter2D per-texel paint, the marker lane, the drag/double-click-insert/right-click-remove/click-popover gestures, the per-stop Z.Popover and the "+" button are all deleted, as is the public const MinStripWidth (no external caller; grep-verified). The constructor signature is unchanged (IZuiRamp, tooltip, showLibrary), so ZuiReflect, Z.Ramp and ZuiGradientEditor needed no call-site edits. ZuiReflect.IsWideControl still keys on the type, so a ramp still gets its own line in a card flow.

WHERE THE 8-KEY CAP IS PAID. Display goes through ZuiRampGradientBridge.ToGradient -> ZuiGradient.BuildGradient, which is exact at or below 8 stops and evenly subsamples above it with stops[0] and stops[n-1] always kept. It is pushed in with SetValueWithoutNotify, so nothing writes. Write-back happens only from the field's own ChangeEvent<Gradient>, guarded by an _applying flag so the value is never pushed back mid-gesture (that would fight Unity's open popup and re-enter the callback). The tooltip is rebuilt on every sync and names the live stop count, so "simplified from 14" appears before the edit that would cost those stops. An empty ramp (Pyre's soot ramp) is shown as a fully transparent 2-key bar and is never auto-seeded — editing the field is the way in, which is what the deleted "+" existed for.

BLEND SPACE. ZuiRampGradientBridge.ApplyGradient now snapshots ramp.BlendMode and restores it after ApplyZuiGradient. Without that it took the throwaway ZuiGradient's default (Srgb), because a UnityEngine.Gradient carries no space at all — so every colour edit on a Linear-Light PyreRamp silently re-blended it. Pre-existing since T-0221; it only became reachable now that a Gradient is the editing surface.

LAYOUT. The control sets flexWrap = Wrap on itself and minWidth 120 on the field (a gradient bar reads narrower than the painted strip did). The field carries the zui-audit-allow-stretch class alongside its inline flexGrow, because the shared sheet pins .unity-base-field to flex-grow 0 and ZuiAudit would otherwise report an intended full-width ramp as accidental stretch.

THE PREVIEW-STRIP FIX. ZuiGradientEditor registered DetachFromPanelEvent -> DisposeLut (DestroyImmediate) with no counterpart. Any detach — a folded section, a toggle-bar hide, a reparent — destroyed the LUT and left Output.image pointing at a destroyed texture, permanently blank. Measured live: the Image reported unityNull true while the gradient below it still edited fine. It now also registers AttachToPanelEvent -> Refresh, one 256x1 texture per re-attach.
