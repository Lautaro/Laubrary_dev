Pyre has been run for real for the first time: every one of its 29 picture-making techniques was rendered to an actual image, and the results are saved as one labelled sheet that is now the reference the rebuild gets judged against. Looking at the pictures immediately settled three things that four rounds of reading had got wrong or missed - and it also caught two genuine faults nobody knew about.

**Details:**
**What you can look at.** The main sheet shows one frame from each of the 29 techniques, side by side, at the same size and settings, with the two retired slots included at the bottom as a control. A second sheet shows the same techniques across seven moments of their life, so you can see what each one actually does rather than guessing from a single still.

**The headline results.**

- 28 of the 29 draw something. One - "Playback 3D" - draws nothing at all, at any moment. It is offered in the picker but cannot currently produce a picture.
- The two retired slots really do come out as a plain circle, identical down to the last pixel.
- The colour-ramp question: editing the ramp on Fire and on Fireball **does** work. The earlier reading that it does nothing is wrong, and the pictures prove it. Text is the real problem case - its ordinary Colour row changes literally nothing, and the colour you actually see on a Text layer comes almost entirely from its outline setting instead.
- The protrusion check on the old browser app confirms the design document: a hand-painted strip really does carve genuine lit relief with a cast shadow. Two things the document did not know: the slider stops making any visual difference above roughly a third of its range, and a sunken value only reads as engraving when the layer is on its own - with anything underneath, the sunken part is simply replaced by what is below rather than looking carved.

**Two faults found by looking, that reading had never surfaced.**

- A Text layer draws the wrong letters out of the box. Asked for "PYRE" it produces gibberish. The cause is that Pyre picks a font for you and picks a bad one - a demo font with an incomplete character set. Given a normal font it spells correctly.
- If the chosen font cannot be read, a Text layer silently draws a plain circle instead, with no warning of any kind. The same silent swap exists for image layers.

**Not verified:** this shows each technique at its stock settings only, so it is what each one *is*, not what it can be tuned into. Six of the effects have five to ten alternative looks each that were not rendered - roughly fifty more variations exist behind those cards. And nothing here was seen inside the Pyre editor window itself; these come from the renderer directly, so the window's own appearance and controls are still unchecked by eye.
**Technical details:**
**Method.** Unity 6000.3.10f1 in `-batchmode -executeMethod` against `D:\UNITY\Laubrary Dev`. A temporary probe script built each spec in memory (`ScriptableObject.CreateInstance<Laubrary.Pyre.Pyre>()`, `canvasSize 96`, `frameCount 16`, `seed 1234`, one `new PyreLayer()` with stock defaults) and called the public one-shot entry point `PyreRenderer.RenderFrame(spec, frameIndex)`. Nothing touched `PyreWindow`, the frame cache, or the incremental `PlanFrame`/`ComposeFrame` API. Plug-in forms were constructed the same way the picker constructs them (`Activator.CreateInstance`, no post-configuration), discovered by reflection rather than by an asmdef reference. Frames 2/4/6/7/9/11/13 were rendered per technique; the sheet shows the highest-coverage one, and `manifest.txt` records coverage at every sampled frame.

The probe script is archived at `D:\UNITY\Laubrary Dev\.agenthq\workspace\T-0101\T0101PyreBaseline.cs.txt` and was REMOVED from `Assets\Editor\` after the run (`Assets/Editor.meta` is tracked in git and the folder pre-existed empty; both were restored exactly as found). The re-run command is in the report.

**The 29, confirmed against source:** 17 live `ShapeForm` entries + 9 concrete `PyreForm` plug-ins (`Laubrary.Pyre.Forms.Kiln.*`) + 3 field-pass modes. The 3 field-pass modes are reached by `layer.coalesce = Fuse` / `= Ramp` (both require `swarmEnabled = true`, since `RenderSwarm` is the only caller) and by the height consumer, which needs TWO layers - a `matteRole = WriteMatte, matteWriteLuma = true` writer below and a `heightFromChannel = 0` consumer above. Dispatch priority is NOT all inside `RenderLayer`: `plan.isHeightConsumer` is checked one level up in `PyreRenderer.Layers.cs:168`, and `coalesce` one level down inside `RenderSwarm` (`PyreRenderer.cs:1497`).

**Check A numbers** (share of the generator`s own visible pixels repainted when the gradient is swapped): Fire 102.8%, Fireball 100.8%, Text via `shapeFill` 0.0%, Text via `textFill` 6.5%, Text via `textBorder` 93.5%. Controls: Disc 103.5%, Gem 47.8%, InfernoForm 100.2%, TorchForm 0.0% (`UsesFill => false`). Values at/above 100% mean "entirely repainted" - the denominator excludes sub-threshold edge pixels that still register a delta. The earlier "the ramp does nothing on Fire" claim came from a canvas-wide metric applied to a generator covering under 1% of the canvas.

**Text glyph fault.** `PyreRenderer.FindReadableTextFont()` takes the FIRST TMP font asset in the project whose atlas is readable. Here that is `Assets/Demos/TextSplashDemo/Border Fonts/Splash Demo (LiberationSans SDF) Border Font.asset`, whose character table is partial - "PYRE" renders as garbage while "ABCDEFGH" renders correctly. `Inconsolata-SemiBold SDF` and `LiberationSans SDF - Fallback` both render "PYRE" correctly. Separately, `LiberationSans SDF` (atlas not readable) produced exactly the Disc coverage (16.02%) and the Disc image - the documented-but-silent fallback at `RenderLayer:276-279`.

**Side effect, reverted.** `EnsureTextGlyphs` calls `font.TryAddCharacters(...)`, which regenerated the atlas on three font assets. Only the Border Font is git-tracked; it was backed up to `D:\UNITY\Laubrary Dev\.agenthq\workspace\T-0101\Splash Demo Border Font.asset.probe-modified.bak` and then reverted with a file-scoped `git checkout --`. `Assets/Demos/TextSplashDemo/` is clean again. No other project file was written; all output went to `.agenthq/workspace/T-0101/`.
