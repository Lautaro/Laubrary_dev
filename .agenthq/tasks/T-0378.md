## Description

Found by T-0374 while building the UC1-3 real Play-mode rig (not fixed there, flagged as out of scope). `ChunkEmitter.Burst()` parents its `ChunkBurst` container under the emitter, and `SpawnBurst` only schedules a `Destroy` when `parent == null`. A component-driven emitter (i.e. exactly the kind T-0374 just built, and presumably how a real game would fire one) therefore accumulates one empty `ChunkBurst` GameObject per press for the rest of a play session — nothing survives Play mode itself, but a game that fires an emitter repeatedly during a real session will pile these up. Find the exact spawn/parent/destroy logic (`ChunkEmitter.cs`/`ChunkBurst`-related code under `Assets/Packages/Laubrary/Runtime/Chunks/`) and fix the destroy condition so a parented burst container still gets cleaned up once its contents are done playing.
