## Description

User observation (2026-08-21): "Having several layers doesn't mean each layer is cached — every time I change a layer or hide/show a layer it has to re-cache everything." True after T-0059/T-0060: the frame cache holds whole composited frames, so any edit throws every frame away. Cache per LAYER per frame instead — each layer's isolated rendered buffer keyed by its own content (plus the few things it reads from elsewhere), then composite the cached layer buffers into frames. Hide/show/reorder = recomposite only; a dial on one layer re-renders that layer only; spec-level post modifiers apply live after compositing. Renderer factored so the full `RenderFrame` and the cached composite share ONE per-layer code path; `RenderFrame` output stays byte-identical (bake/export untouched). Identity tests, live measurements, audit, handover walk.

Standing rules: autonomous, never stall, commit after each verified milestone, log handovers here. Never touch the user's assets (temp probe assets only; the uncommitted `New Pyre Plus§.asset` / deleted `New Pyre Plus.asset` are never added, reverted or committed).
