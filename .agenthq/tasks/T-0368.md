### 2026-09-16T21:27:30Z — agent — in_progress -> done
Fixed all three T-0357 regressions the merge-1 verification found on the Fling card, code-only (no Unity/Coplay session). Commit 858d45ba on worktree-agent-abd65237713eb61cc, branch dev at 3e0859f7 before this commit.

1) Burst-direction mirror now live. The read-only mirror was built once from the recipe's directionDeg at card-build time; dragging the Preview pane's own Burst-direction dial Dials the whole window but never rebuilt this one card, so the mirror went stale. It now registers into the same per-card `cardStates` refresh dictionary the source-state line already uses (RefreshCardStates() runs it on every Dial()), so it re-reads the live value every edit without a card rebuild.

2) Migration/data-loss fixed. The rule: a NEW Fling (added from the Add menu) has no legacy inheritBurstDirection choice to convert, so it must be born already migrated — MarkBornMigrated() sets directionModeMigrated=true right after construction, called ONLY from the Add-menu factory in ChunkWindow.Recipe.cs's Kinds table. MigrateLegacyCurves() then no-ops for it forever, so whatever mode the user later picks (Fixed/Outward) survives every domain reload instead of being silently overwritten back to Burst. An asset saved BEFORE this flag existed never goes through that factory (it comes from AssetDatabase deserialization instead) — it still deserializes with directionModeMigrated at the C# default (false), so MigrateLegacyCurves() still runs exactly once for it and still folds its real old inheritBurstDirection choice into directionMode, unchanged from T-0357. Duplicate (ChunkCapabilityCopy.Of) was checked and needs no change: it deep-copies every serialized field including directionModeMigrated, so a duplicated Fling keeps whichever migration state the original had.

3) Orientation tick no longer hidden. The tick used to run from a guide's exact centre to its rim; the firing-number chip (T-0354) is centred on that same point and is drawn in a separate pass AFTER every disc, so it covered the tick's origin. The tick now starts just outside the chip's worst-case footprint (a new ChipHalfDiagonal constant, 9.6px, matching the chip's own 14x13 floor) whenever the guide carries a label at all — so the two never compete for the same pixels regardless of draw order. A guide with no label is unaffected (tick still runs full centre-to-rim, as before). Discs too small for a visible stroke past the chip (r - startDist < 2px) simply skip the tick rather than drawing a backwards/zero-length segment.

Scope respected: only Preview.cs's disc/tick drawing was touched, nothing in the stage-drag handler, PadRow or BackSplash (that's T-0367's area).
**Details:**
Files changed (all under Assets/Packages/Laubrary/):
- Runtime/Chunks/Capabilities/Trajectory.cs — added public MarkBornMigrated() (sets the private directionModeMigrated field true).
- Editor/Chunks/ChunkWindow.Recipe.cs — the Fling entry in the Kinds factory table now calls MarkBornMigrated() right after `new Trajectory()`.
- Editor/Chunks/ChunkWindow.TrajectoryCard.cs — the Burst-direction mirror registers/deregisters itself into the cardStates refresh dictionary depending on directionMode; restructured the if/else-if chain into if/else so the cardStates.Remove(id) runs for both Fixed and Outward.
- Editor/Chunks/ChunkWindow.Preview.cs — DrawGuide's orientation-tick block now starts the line at ChipHalfDiagonal (new const, 9.6f) from centre when the guide has a label, instead of at the centre.
- CHANGELOG.md — new T-0368 entry under [Unreleased].
**Technical details:**
MarkBornMigrated() is a thin public setter (`directionModeMigrated = true`) added to Trajectory.cs because the field is private and Editor/Chunks is a separate asmdef from Runtime/Chunks with no InternalsVisibleTo — a public method was the minimal-surface option, matching how every other capability's migration flag stays private with MigrateLegacyCurves() as the only entry point (this adds a second, narrower one for the born-migrated case only). Considered and rejected: flipping directionModeMigrated's field-initializer default to true — that would make truly-old deserialized assets (predating the flag) also start migrated, since Unity's serializer runs C# field initializers before patching in whatever the YAML actually contains, and a pre-flag asset's YAML has nothing to patch that field with — which would silently skip their real migration. The chosen fix only marks migrated at the one code path (the Add-menu factory) that constructs a capability with no legacy data at all.

The mirror's live-follow reuses ChunkWindow.CardState.cs's existing `cardStates` Dictionary<string,Action> (keyed by capability id) rather than inventing a second notification channel — it's the same mechanism SourceStateLine already uses for Fragment Fracture/Palette Splash source warnings, called from RefreshCardStates() inside InvalidatePreview() on every Dial(). ZuiMicroSlider.value has a `set` that calls SetValue(value, notify:false), so writing mirror.value never fires the slider's onChanged and can't create a feedback loop back into the recipe.

The tick fix is placement, not draw-order: I considered moving DrawGuideLabels to run before the tick pass instead, but that only trades which one occludes the other and the task said 'keep both readable', so offsetting the tick's start point to fully clear the chip's footprint (rather than merely re-stacking two overlapping draws) was the more robust fix — it holds regardless of any future change to which pass runs first. ChipHalfDiagonal (9.6f) is computed from the chip's own floors in DrawGuideLabels (Mathf.Max(14f, textWidth+6f) wide, 13f tall): half-diagonal of a 14x13 rect is sqrt(7^2+6.5^2) ≈ 9.55, rounded up slightly for margin.
