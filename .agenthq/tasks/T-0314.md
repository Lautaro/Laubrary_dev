## Description

**Filed by T-0313 (A27, ninth structural pass). Every number measured live in the Shaper-worktree editor at HEAD ae66d31c; full write-up + probes in `workspace/T-0313/` (A27-NINTH-PASS.md sec 2.1, dumps `out/compactrow-ejet-c1.txt`, `out/spill-ejet-c1.txt`, `out/compact-scan.txt`).**

`ZuiReflect.BuildList`'s **compact** branch (`Zui/Toolkit/ZuiReflect.cs:706-763`) draws a list element made only of bounded scalars as ONE `NoWrap` row: `#n` + its dials + a flexible gap + the remove `x`. Its own comment says "the dials shrink instead". They do not - every child resolves `flex-shrink: 0` - and `ZuiMicroSlider`'s `min-width` is 60, so shrinking alone could not save five of them either.

Measured in Pyre on a one-layer scratch spec with `ExplosiveJetForm`, dial pane 360 (the width `PyreWindow.leftPaneWidth` defaults to, i.e. the width the window opens at), card body **293.8px**:

```
[0] Label '#1'                w= 26.2  x= 30.7.. 56.9
[1] ZuiMicroSlider 'Blast at' w=100.0  x= 63.1..163.1
[2] ZuiMicroSlider 'Violence' w=100.0  x=169.3..269.3
[3] ZuiMicroSlider 'Share'    w=100.0  x=275.6..375.6   << past the box
[4] ZuiMicroSlider 'Seat X'   w=100.0  x=381.8..481.8   << past the box
[5] ZuiMicroSlider 'Seat Y'   w=100.0  x=488.0..588.0   << past the box
[7] Button 'x'                w= 21.8  x=603.6..625.3   << 300.9px past the box
```

The dial pane's clipping viewport ends at **351.1**, so at one column `Share`, `Seat X`, `Seat Y` and the remove `x` are OUTSIDE it: not drawn, not clickable. **An authored blast cannot be removed and three of its five dials cannot be touched at the width Pyre opens at.** At 2 columns the spill is 277.3px and at 4 columns 291.1px - drawn there (the pane is wider) but still overhanging the card; they overlap no other leaf control, so the effect is a row sprawling across the column gap.

**The arithmetic, so no number has to be invented.** A 360px column gives a card body 293.8px; `26 + N x 100 + 6.2px gaps + 22` fits **N = 2** (258.6px) and does not fit N = 3 (364.8px). `IsCompactRowElement` (`ZuiReflect.cs:815-837`) admits **N = 2..5**. A reflection scan replaying that rule over every `List<T>` field of every Laubrary runtime type finds **exactly one** admitted type in the whole package - `ExplosiveJetSettings.blasts` -> `ExplosiveBlast`, with 5 dials - so the compact branch has never yet produced a row that fits.

Riding along in the same row: the `Violence` caption is **1.8px short** (needs 44.9, has 43.1) because `CompactOptions` sets `ControlWidth = 100` while a MicroSlider's caption reserve is sized for 150. It disappears with whatever fixes the row, so it was deliberately not patched on its own.

**Not prescribing the fix** (programme rule 6 - this pass files, it does not build). The measured facts a fix has to satisfy: two 100px dials are the most a 360px column holds; the non-compact card path (which flows an element's fields) already handles narrow columns; and the `x` must stay reachable at the pane width the window opens at.

Blocked on nothing. Scope: `Zui/Toolkit/ZuiReflect.cs` (+ whatever ExplosiveJet's card is meant to look like); no serialized data changes.
