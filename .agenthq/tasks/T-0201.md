### 2026-09-02T22:16:55Z — agent — in_progress -> done
Every control the Shaper window shows now reaches the picture the moment you move it.

**What was wrong, and it was one thing in four places.** The preview reads through a frame cache. An edit that repaints without first dropping that cache repaints the frame that was rendered *before* the edit — the dial moves, the picture does not. `Change()` and `Val()` dropped it; the four hooks that carry every reflection-drawn control did not: the hosted generator's own dials (Orb, Plasma Bloom, all nine forms), the hosted Pyre layer's dials (which is what Reach, Spread and Auto Exposure report through), each effect modifier's dials, and the gradient control. That is exactly why an unrelated edit that *did* invalidate released every held-back edit at once. Invalidation is not a per-control decision, so it now has one home — `ShaperWindow.AfterEdit()` — and every writer calls it.

**Two more faults the sweep found on its own.** Turning a shape off left it on screen and kept it there: a layer that resolves to no owners returns out of the painter before the painter clears its buffer, and the preview's buffer pool hands back the slot still holding that layer's previous pixels, which were then composited *and* cached under the new key. And a Curve, Steps or Oscillation dial's envelope was not part of its cache identity, so reshaping a curve changed what the dial evaluates to and left the key unchanged (latent — that key is not on the live render path today).

**The sweep.** 29,023 controls, across documents covering every primitive, every solid, a bag with fill/border/height/mask/swarm, document effects and lights, all nine hosted PyreForms, both simulations and all sixteen hosted Pyre legacy shapes. Each control is moved, the caches are invalidated exactly as the window does it, and the frame is rendered twice — once through the preview's cache, once cold. **Zero disagreements, zero exceptions, zero failures to restore.** Undo restores a plain field, a nested dial and a string, and the SerializeReference graph survives it.

**One finding is not mine and needs T-0202.** With invalidation proven clean, the nine PyreForms, both simulations and all sixteen hosted Pyre layers still show *zero* of their own dials moving Shaper's picture, while the same documents' transform, shell, swarm and canvas dials all move it. Asking the layer below (`generator-source-check.md`): every form's own raster paints 45,000–573,000 covered pixels and *does* move when a dial moves. So the picture is lost between the generator's raster and Shaper's composite paint — not in the generator, not in the cache. The tell is `TestDiscForm`, whose one radius dial changes *coverage* and does come through: what survives the bridge is coverage, and what is dropped is everything the generator says about colour and energy.
