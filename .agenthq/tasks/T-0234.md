The box sits under a new objective preview strip showing the ramp AS IT RENDERS. That strip is not decoration — Unity's gradient field shows the SOURCE stops it edits and structurally cannot picture a hue shift, so without it the knobs would look inert while the render moved.

One gap, stated plainly: a form that caches its baked ramp only re-bakes when its cache key changes. **Details:**
Storage. `ZuiRampAdjust` (Zui/Scripts/Runtime/ZuiRampAdjust.cs, global-namespace [Serializable], new): reverse, phase (0..2, mirrored so an animated scroll loops seamlessly), quantiseSteps, hueShift, saturation, brightness, contrast, cycle, cycleSpeed. Every default is the identity and `IsIdentity` is what a baker tests to skip the pass entirely — that is what makes adding it to an already-serialized type safe. cycle/cycleSpeed are deliberately outside IsIdentity: they instruct a runtime driver and change no still sample. `PyreRamp` (Runtime/Pyre/PyreShade.cs:52) holds one; Clone deep-copies it.

Shared maths, not a copy. `ZuiRampMath.Position(t, reverse, phase, steps)` and `ZuiRampMath.Adjust(colour, hue, sat, bri, con)` are the one implementation. `ZuiGradient.Evaluate` (ZuiGradient.cs:241) now calls both over its own animatable ZUIValue knobs instead of its inlined arithmetic — same order of operations, so a gradient still evaluates identically; `PyreRamp.Evaluate` calls them through `adjust.Sample(EvalRaw, t)`. A hue shift therefore cannot come to mean two different things on the two sides.

UI. `IZuiRamp` gained `ZuiRampAdjust RampAdjust { get; }`. PyreRamp returns its own; ZuiGradient returns null on purpose — ZuiGradientEditor already draws the richer animatable set, and two Adjust boxes on one gradient would be two places to say the same thing. `ZuiRampControl` became a column: preview strip, the existing ramp row (GradientField + ★ + blend space), then Z.Box("Adjust") with Hue/Saturation/Brightness, Contrast/Phase, Quantise/Cycle/Reverse — MicroSliders and Toggles, because these are plain floats rather than ZuiGradient's per-life ZUIValues. Every edit goes through the control's existing Mutate() gesture, so the host's OnBeforeMutate Undo hook records them exactly as it records a moved stop. Refresh() rebuilds the box rather than writing values back into the controls, because pushing a value in would fire the change callback and turn an Undo into a new Undo record.

Where the knobs reach the picture. `PyreShade.BakeLut(PyreRamp)` samples through Evaluate when the knobs are non-identity and takes the original stop-list path when they are. The two forms with bespoke LUT bakers post-process their own table at LUT resolution and return immediately on IsIdentity: PyreOrb.BakeLut (Orb's 256x3 double table) and PyreJetEngine.Bake (the Jet Lut, sRGB bytes re-derived from the adjusted colour and the linear channels from those bytes, alpha carried through the position transform but never colour-adjusted — opacity is the ramp's authored ceiling, not a colour).

Cache identity. `PyreShade.RampHash(ramp)` folds stops + blend space + ZuiRampMath.Hash(knobs). JetFormBase's private RampHash now delegates to it. OrbForm.cs:480 keeps its own stop-only copy and was NOT touched: T-0235 holds that file this wave. PyreForm.ContentHash reflects over fields generically and its plain-serializable-class branch walks the new `adjust` object, so Shaper's own node cache already invalidates on a knob turn with no edit needed.

Pyre files edited, all additive: PyreShade.cs (the field, Evaluate, EvalRaw, BakeLut, RampHash), PyreOrb.cs (+ApplyAdjust at the end of BakeLut), PyreJetEngine.cs (+ApplyAdjust at the end of Bake), JetFormBase.cs (RampHash now one line delegating to the shared one).
