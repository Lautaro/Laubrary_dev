### 2026-09-02T11:41:04Z — agent — in_progress -> done
Text is a shape source in Shaper, not a form with its own private fill/border/extrusion. A new ShaperPrimitiveKind.Text (=8) turns a string's TMP glyphs into a signed distance field; from there the fill, border, height and light stages apply to it unchanged, and not one of them was edited to make "BOOM" carry an outline and a Dome.

Authoring lives in the Shape section's Text case: font (Z.Object<TMP_FontAsset>, empty = the project's TMP default), the string (Z.TextInput, the one place a typed field is right because it DECLARES content), Left/Centre/Right alignment as radios, and four animatable dials - Size (character height in canvas px, the same meaning Pyre's own size has), Letter spacing, Line spacing, Weight. Weight is the cut through the glyph SDF: TMP writes 0.5 at the outline, so below 0.5 fattens the letters and above thins them - a free bold/light on any font. The text sizes itself from the font's metrics rather than being handed a box, and centres its own origin on the string so rotating the node turns the word rather than swinging it around the first pen position.

Like Sprite, Text has no analytic SDF, so it forks around ShaperPrimitives.Bake at the same point (ShaperCompiler.EmitLeafFrom) into EmitTextLeaf, which resolves the dials once per compile, fetches a cached raster from the new ShaperTextPrepassCache, and emits a ShaperOpKind.TextSample op. The raster is built by laying the string out from the glyph metrics, taking the MAX of every glyph's atlas SDF (a union, so tight spacing merges letters instead of notching one along its neighbour's cell edge), cutting at the weight, then running an exact Euclidean distance transform. That last step is the load-bearing choice: TMP's own atlas SDF saturates a few texels past its padding band - exactly where a border lives - whereas the transform is Lipschitz-1 across the whole raster, which is what lets Text declare bound 1 honestly rather than by convention. A half-character blank margin is baked around the string so a border/shell has somewhere to reach.

Each raster also publishes a per-glyph index channel (ShaperCompiledTextField.glyphIndex, plus GlyphIndexAt) so a per-character fill can address one letter at a time. Judgment call, stated plainly: no fill kind CONSUMES that channel today, because the fill stage's per-sample inputs are the nine declared quantities of ShaperQuantitySet and character index is not one of them; adding a tenth would have meant editing ShaperFillContract/Ops/Compiler/Resolver while two other agents are in the tree, which is not a trade worth making for this task. Publishing is what the task asked for and what shipped. A per-character GRADIENT needs nothing new at all - Pyre's PerCharGradient is a gradient swept in SPACE across the line, which an ordinary Linear Gradient fill over the node's box already is, and the probe renders that variant.
