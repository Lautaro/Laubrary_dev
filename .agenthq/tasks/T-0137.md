## Description

User feedback: the composite-generator picker used nine INVENTED names (Blob/Sparkle/Mesh/Wisp/Halo/Bolt/Cloud/Ripple/Shard) with no per-generator authored UI at all -- just a name + a free-text reason note, regardless of which of the 9 was selected. Asked directly: 'have you considered UI for them, or is that something you think will happen by itself?' It had not been considered.

Fixed by reading the REAL catalog directly from the Shaper engine worktree (`D:\UNITY\Laubrary Dev - Shaper\Assets\Packages\Laubrary\Runtime\PyreShaper\PyreCompositeCatalog.cs`, T-0112) instead of inventing names:
1. Real 9 names: Inferno, Fork Blast, Orb, Torch, Arc Burst, Plasma Bloom, Jet, Radial Jet, Explosive Jet.
2. Real palette classification carried into the mock (a sourced fact, not invented): Orb/Torch/Arc Burst/Plasma Bloom are palette-indifferent; Inferno/Fork Blast/Jet/Radial Jet/Explosive Jet are veil-multiplied -- shown as a read-only badge in the Composite card, and used to replace the old `index % 2 == 0` PublishesSheets placeholder with a real, sourced relationship.
3. Moved the picker from an in-body MiniRadio grid into the Shape section's HEADER via ZuiSection.SetHeaderMenu, mirroring PyreWindow.ShowShapeMenu exactly (a caret button + right-click, two side-by-side columns) -- the user's own direction: 'look at how Pyre does it, choosing generators will be the same.' The two columns are the real Palette-indifferent/Veil-multiplied split, not an arbitrary grouping invented to mimic Pyre's 3D/2D/Special shape.
4. Gave each of the 9 (7 distinct classes, since Jet/Radial Jet/Explosive Jet share the real engine's JetFormBase family) a representative 2-3 field parameter set, reflected via the same ZuiReflect pattern the effect catalog already proves -- picking a generator now visibly changes what you can author, instead of every generator showing an identical, empty-feeling card.

Verified live via Coplay: selecting Orb (index 2) shows PaletteIndifferent=True (matches the real classification) and generatorParams resolves to MockOrbParams; screenshot confirms the header caret button and the 'Orb parameters' foldout with real reflected fields.
