The Public/Private switch on a Zoe's Chunks row can now be undone and redone any number of times without breaking anything. The row always ends up on a recipe that loads and keeps its tuning, and no file is left that Unity can't load.

How it works: making the library asset (Public) or the hidden copy inside the Zoe (Private) is now permanent asset work that Undo never touches. The switch also no longer deletes the recipe the row is leaving: the hidden copy stays inside the Zoe's file, and the library asset stays in the library. The only step Undo records is which recipe the row points at, as one step named "Make Chunks Public" or "Make Chunks Private". Undo and redo only move that pointer between two recipes that both still exist, so they can't leave the row broken or a file unloadable.

Clicking Public or Private again no longer piles up copies. Each direction first looks for a copy it made earlier with exactly the same tuning and reuses it: a library "<Zoe> — Chunks", "… Chunks 1" and so on in Assets/Chunks, or an unused hidden copy with the same name in the Zoe. It makes a new copy only when the tuning has changed.

Saving now covers only the Zoe and the new library asset, not every unsaved asset in the project.

Trade-off: a hidden copy the row switched away from stays inside the Zoe's file, where no browser shows it, so that Undo can switch back to it. Editing between switches can leave one such copy per distinct recipe.

Code-only. Nothing was compiled or tried in the editor.
