## Description

**Structural audit programme.** Read `D:\UNITY\Laubrary Dev\.agenthq\workspace\ShaperHarmony\RULES.md` first (do not commit; PM commits; UI Guide is a hard gate). Measured by T-0307, whose report is `workspace/T-0307/A26-EIGHTH-PASS.md` and whose probes are `workspace/T-0307/probes/`. `ZuiAssetWindow.BuildToolbar` gives the asset `ObjectField` a fixed 200 px. Measured live: the label `AuditT0307 (Shaper Document)` needs **180.4 px** and the field's label box gives it **161.8 px**, so any asset whose name runs past ~14 characters is drawn cut off — in every Laubrary asset window, not just Shaper. **It cannot simply be widened where it sits.** At the declared 820x520 minimum window the toolbar row is `flexWrap: NoWrap`, its children total 812 px, and its rightmost child ends **10.2 px** from the window edge (`probes/c3-toolbar-read.cs`: ObjectField 200, dot 12, Save 52, New 40, Browse 56.4, Duplicate 68, Rename 60.4, Delete 51.1, tag strip 197.3). Buying 60 px for the field pushes `Delete` off the edge at the minimum size. The UI Guide's own rule applies ('A fixed width is a starting point, not a check that content fits ... measure and size to fit rather than guessing', and 'a full-asset-name field legitimately uses the space it needs'), so this wants a real shape: let the row wrap at narrow widths, or show the asset NAME instead of Unity's 'Name (Type)', or let the field grow and clamp the rest. Not a bigger number picked by an agent. T-0307 fixed the dirty dot in the same row (padding, not width, precisely because of the 10.2 px) and left this one.
