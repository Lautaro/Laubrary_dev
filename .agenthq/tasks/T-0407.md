## Description

Sub-task of T-0406. An interrupted session removed the native C++ plugin audio path from the package but stopped partway, leaving the package unable to compile. **Unity confirms 57 compile errors**, all of three kinds: the removed namespace, and two removed types (the per-voice native handle and the bus wrapper).

The audit found the breakage is in **six** files, not the three first suspected:

**Native-only, delete outright:**
- The main-thread half of the native audio graph — it owned pools of native voice and group handles, decided which voice to allocate or steal, drained events out of the plugin, and read stall and collection statistics straight from the plugin's shared memory. Nothing in it is shared.
- The native debug reporter — it formats numbers that all originate in the file above, and reads the plugin's per-bus control block.

**Shared, needs surgery (delete only the native half):**
- The playback helper. Its native half exists purely to hand a native voice its starting state. Its other half is engine-agnostic and must survive: deciding which effect chain a sound plays with, turning a chain into the flat parameter and state layout any engine consumes, working out a sound's duration when pitch is being modulated, rolling random/oscillator/step values at trigger time, and migrating a clip's older named-field effects into a modern chain. **Caution recorded in the brief:** the layout cache may be shared by the parts that must survive, so it must be read rather than assumed.

**Shared, strip the native branch (three playback handlers):**
Each held a native handle and called native-only operations on it, and each already contains a complete working non-native branch selected by a boolean. Removing the native branch is a deletion inside an existing either/or, not a rewrite. The now-dead setting that chose between them is then removed too.

**No editor code is affected at all** — every editor window, the monitor tab and the waveform/spectrum view read playback state through an engine-agnostic layer, so none of them reference the removed code. The six files above are the complete set; there is no further breakage lurking.

## Handover Log

### 2026-09-26T19:35:00Z — agent — open

Audit complete, fix in progress. Two things worth recording:

**The native C# source is not lost.** All 18 of its files remain intact in the mainline development branch, which this branch was cut from and has not diverged from except by the one checkpoint commit. Only the two compiled plugin binaries were relocated into a project-level experimental folder. So the research plan's instruction to keep the old path available as a working reference is satisfied by the mainline branch retaining it — removing it from this branch burns nothing. That was the reasoning used to proceed rather than restoring it here.

**The important discovery, which changes what the remaining work is.** The surviving "managed" path is not a live audio engine. A sound plays through an ordinary Unity audio source, using a clip that was rendered ahead of time in the editor with its effects already baked into the audio data. There is a complete, real per-sample effect-chain engine in the package — resampling, the full effect chain, modifiers, repeats, stop and release, pause and resume, all in plain arrays with no native calls — but it is currently wired only to offline rendering and editor previews, not to anything that plays during a game.

So removing the native path removes real capability with no replacement yet: live effect chains that react while a sound is playing, retriggered repeat trains, and real-time retriggerable time-stretch all existed **only** in the native branch. Basic one-shot and looping playback, offline rendering, and every editor view are unaffected. Those three named gaps are precisely what the new Burst-generator path has to fill, and the existing per-sample engine is the specification to port — the new per-voice state container already mirrors its fields exactly.

### 2026-09-26T19:55:00Z — agent — open — review of the fix, and one correction to the audit

Reviewed the change rather than taking it on trust. Verified directly: zero references to any removed native type remain in any source file, every member that had to survive in the shared playback helper is still present, every member that had to go is gone, and all four edited files are brace-balanced.

**The audit's keep-list was wrong on one item, and the implementer was right to ignore it.** The helper that rolls random, oscillator and step values at the moment a sound is triggered was on the "must survive" list, but checking the original shows it took a native voice handle as a parameter and was only ever called from the two native-only start methods. It was therefore native-only by both signature and call graph, and could not have compiled once its parameter type ceased to exist. Deleting it was correct.

**But that has a consequence worth carrying forward:** the *behaviour* it implemented — choosing a fresh random, oscillator or stepped value for a parameter each time a sound starts, so repeated plays vary — is real functionality that the new Burst path will need, and it is now absent from the working tree. It is not lost: it remains in full on the mainline branch and can be read back from there when the new path needs it. Treat it as a named item to re-implement, not as dead weight.

**Scale of what the removal took with it**, as a rough measure of the gap now to be filled: the shared playback helper lost about 45% of its lines, one handler about 70%, and another about two thirds. Those proportions are consistent with the finding above that the live engine lived almost entirely on the native side, and are a reminder that this branch currently has *less* audio capability than the mainline, not more. That is expected and acceptable mid-port, but it must not be mistaken for progress on its own.

### 2026-09-26T20:10:00Z — agent — open — two MORE files were broken, by our own deletion

The original audit declared the engine's main class "not broken" because it held no reference to the native types. That was true and still misleading: it held references to the **native graph class**, which the fix then deleted — so removing that class broke the engine class as a second-order effect. A second file, the trigger-watchdog diagnostic, broke the same way by calling the deleted native debug reporter.

This is worth remembering as a pattern: an audit that asks "what references the thing being deleted?" misses "what references the things I am about to delete because they referenced it." The implementer caught both and correctly refused to fix them because they were outside its permitted file list — the right call, and the reason the scope guard was worth setting.

Both are now fixed:
- The engine class lost its whole per-voice-graph section: the field, the two accessors, the lazy create and teardown, the two flush-all-voices calls, the per-frame event drain, and the pre-domain-reload teardown hook. One behaviour went with it deliberately — a handler that killed all playing sounds when the audio device or buffer size changed. That handler was only ever subscribed when the native graph was created, so it never ran on the surviving path; removing it therefore changes nothing that happens today. **It does leave a real pre-existing gap worth fixing later:** after an audio device change, sounds are stopped by the engine but their tokens are not told, so they believe they are still playing. Worth handling properly when the new path lands, rather than restoring a hook that never fired.
- The diagnostic lost the block that dumped per-voice and per-group state out of the native plugin. Everything else it reports — play history, origins, timing, the main-thread timeline, live token state — is untouched.

Three comments that pointed at now-deleted classes were rewritten to describe the behaviour instead of naming a class that no longer exists. One of those is worth noting for the port: the authored per-voice effect-chain data on each sound is deliberately **kept**, because it is pipeline-agnostic — it is currently unread at play time, and it is exactly the authored input the new Burst path will consume. Nobody should "clean up" that unused data.

Verified after the edits: zero compile-affecting references to any deleted type or member anywhere in the project, and every edited file brace-balanced. The shared constants file was checked and correctly retained — the layout builder still uses it.
