## Description

**Found by T-0276 while re-running every earlier probe unchanged, which is this programme's own closing criterion.** `D:\UNITY\Laubrary Dev\.agenthq\workspace\T-0277\fill-state-probe.cs` creates `hfield0277.png` (an RGBA PNG) at its line 39, then at line 61 loads **`rfield0277.asset`** - a file it never creates anywhere. `hfield` is therefore always null, and every row that depends on it prints 0.

Re-run at HEAD deb9db03 the archived probe reports `heightFieldScale / HeightField on a SOLID (Pyramid), one layer / 0`, where T-0277's own handover states **671** and, on the strength of that 671, deliberately left the dial LIVE on a Solid while greying it everywhere else. A later pass re-running the probe would read that 0 as a regression in the shipped engine and "fix" a carve-out that is correct.

It is not a regression: T-0276 rebuilt the fixture with a real in-memory `TextureFormat.RFloat` height field (the format `ShaperFillCompiler.BakeHeightField` requires - it reads `GetPixelData<float>`) and measured **310 changed pixels** on a Pyramid solid at scale 1 -> 6 across two frames, against **0** on a primitive ellipse with one layer. Same verdict as T-0277, different fixture, so the shipped greying rule stands. Every other row of the archived probe reproduces T-0277's numbers exactly (Fit 968/0/0, Posterise 1032/1032/214, Tiles 819/398, Columns 873, Rows 446, Frames 784, strip Offset 1048, Plain colour 596, slot Height 242, Height change 484, the four tints 1032/0).

The work: repair the archived probe so it creates the RFloat asset it loads (or builds one in memory), re-run it, and confirm the eight heightField rows print T-0277's values. Small, but it belongs to the programme's own record - an archived probe that cannot reproduce its own handover's numbers is worse than no probe, because the next pass trusts it.
