### 2026-09-02T12:02:21Z — agent — in_progress -> done
Layers are stacked by DEPTH now, not just by their place in the list. Every layer already sat on a base plane — its index times the document's layer spacing, plus its own signed Z offset — and that plane drove how the layer was shaded and how tall its height field stood, but nothing ever compared one layer's surface against another's. Pushing a layer back changed how it looked and still painted it in front of everything below it. A layer whose surface sits behind what is already painted now goes under it, so two raised shapes at different depths intersect along a curve instead of one hiding the other.

The ordering is deliberately biased toward the document's own authored answer. A tie, or anything in front, composites exactly as it did before — that covers every document whose layers do not contradict their list order, every flat document, and every document at zero layer spacing. A surface a full canvas pixel or more behind goes fully under. The pixel in between blends, and blending is safe rather than a fudge because the two orderings of the same pair of samples produce identical coverage: only colour moves, so a soft intersection can neither punch a hole in an edge nor double it up. How much a barely-covered sample is allowed to assert about depth is weighted by how much of it is actually covered — which is what stops an antialiased rim from claiming an occluding plane and leaving a stair along every silhouette. A masked-away region contributes no depth at all, however tall its height field says it is.

One thing had to be fixed for any of it to mean anything, and it is the more consequential half of this change. The layer walk never handed the height stage the layer's own compiled shape program or the canvas sample spacing — both optional arguments the stage falls back on. So the height span was ONE canvas pixel for every layer in every document: every extrusion profile flattened to a full-depth plateau one pixel in from the silhouette, and the one technique that reads the node-local frame became a constant slab. Measured: a dome of depth 26 over a 34-pixel disc was 26 everywhere inside and 0 outside. A plateau can only re-order whole layers; it can never let two surfaces cross, so the feature this task asked for was unreachable without the fix. Height profiles are real curves now — in the picture, and in the lighting, which reads the same sheet and had been shading every layer against a flattened one.

Nothing new was added to the window. The two dials that now mean more than they did — a layer's Z and the document's layer spacing — say what they do in their tooltips.

THE COMPOSITE:
- New public ShaperDocumentRenderer.CompositeDepth(acc, accZ, accZw, src, srcHeight, baseZ, n) and const DepthBlendBand = 1f. CompositeOver is kept as the plain primitive it always was (and is what CompositeDepth degenerates to); it is no longer called by the walk.
- t = 1 for srcZ >= accZ; smoothstep(-band, 0) below that, reaching exactly 1 at the crossing so the ramp is continuous; then t = lerp(1, t, accZw) so an uncovered or barely-covered accumulator cannot assert depth.
- over and under produce the same alpha (a + b - ab either way), so only the three colour channels are lerped and alpha is written once, unconditionally.
- accZ/accZw are separate from dst's alpha on purpose: the document background (T-0166) fills alpha everywhere while occupying no depth, so reusing alpha as the depth weight would put every negative-Z layer behind the backdrop.
- No authored field added, so no cache key changes (ShaperNodeIdentity untouched).
