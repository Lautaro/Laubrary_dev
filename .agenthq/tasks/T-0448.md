The project's last OnAudioFilterRead was removed 2026-09-26 21:07 (e68d8a6c); this editor started 2026-09-27 14:55 and no branch was checked out since, so nothing in this session could have attached the thread earlier either.
- This session's work (analyser display voices T-0434/T-0443/T-0446 etc.): they render offline on the main thread through the same render code; none adds an audio callback. Confirmed by the guard below: 0 managed blocks.
- Burst in this editor: enabled, compiles asynchronously; the voice struct is marked compile-synchronously.
GUARD BUILT (T-0406's T7, which did not exist): every real-time block counts itself and counts again only if running as managed code (a call Burst deletes when it compiles). Proven to detect: called from managed code it counted 1. A load-time scan warns on any OnAudioFilterRead and is silent otherwise.
MEASURED, editor edit mode: one voice renders ~47 blocks/s; across a ~700 ms forced full collection only 1-6 blocks (of ~33 due): the audio stalls, while 0 blocks ran as managed code.
MEASURED, editor Play mode (check scene, same button): 5 of 5 collections STALLED (0-4 of 25-60 blocks rendered, 527-1271 ms), 0 of 940 blocks managed.
MEASURED, standalone build (same scene, unattended mode, quiet): 10 of 10 collections AUDIO KEPT RUNNING (96-100% of due blocks rendered during collections of 242-1432 ms), 0 of 605 blocks managed; its compile check also reports the chain genuinely compiled.
So: in the editor the audio stalls during a collection even though our render is compiled (the editor drives it differently); in a build it does not. This matches T-0406/T-0414 ('the editor is not a valid venue').
