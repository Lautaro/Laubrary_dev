**Technical details:**
1) Z.PadRow (Zui.cs): ZuiPad.Value's setter already clamps to `range` (Clamp() in ZuiPad.cs), but the xField/yField FloatField callbacks built `nv` from the RAW typed/scrubbed value and passed that same unclamped `nv` to `onChanged`, never reading `pad.Value` back after assigning it. Fix: assign `pad.Value = new Vector2(...)`, then read `var clamped = pad.Value` (now clamped by the setter), `SetValueWithoutNotify` BOTH fields to `clamped`, and invoke `onChanged?.Invoke(clamped)`. Hand-traced against the exact repro: type X=20 (range -8..8) -> pad clamps to 8, xField now shows 8 via SetValueWithoutNotify (no infinite loop, since it's WithoutNotify), onChanged fires with x=8. Then type Y=-30 -> pad.Value.x is already 8 (correct), new Vector2(8,-30) clamps to (8,-8), both fields resync to (8,-8) -- the described 'later Y edit silently sets X to 8' bug is now the CORRECT behaviour (X was already 8), and the field never disagrees with the pad. Scrubbing goes through the same FloatField value-changed callback, so it's covered by the same fix.
2) ChunkWindow.HandleBlastDrag (ChunkWindow.Preview.cs): replaced `Undo.RecordObject(c, ...)` at MouseDown with `Undo.IncrementCurrentGroup()` + `dragUndoGroup = Undo.GetCurrentGroup()` + `Undo.RegisterCompleteObjectUndo(c, "Drag Blast Offset")` at MouseDown, and `Undo.CollapseUndoOperations(dragUndoGroup)` at MouseUp (and in OnAnyPointerUp as a fallback for a release outside the stage). This is the exact pattern ZoundsWindow.BeginDragUndo/EndDragUndo already uses for the identical bug (its own header comment names the same root cause: 'RecordObject's frame-end diff would find no change on the MouseDown frame and silently discard the entry'). RegisterCompleteObjectUndo stores the pre-drag snapshot immediately rather than deferring to an end-of-frame diff, so it survives to be compared against the MouseDrag frames' direct mutation of draggingBlastCap.offset.
3) draggingBlastCap marked [NonSerialized] (also dragUndoGroup, for consistency, though its -1 default is harmless either way) and both explicitly reset to null/-1 in OnEnable as a second line of defence.
4) SeedField (ChunkWindow.CardState.cs) gained an optional `string label = "Seed"` parameter; had to rename its internal `var label = field.Q<Label>(...)` to `labelEl` to avoid a parameter/local name collision that would not have compiled. PyreBlastCard.cs's two Z.Field("Seed"/"Pattern seed", ..., Z.Int(...)) call sites replaced with SeedField(...) calls carrying the same pins/undo-label text as before.
