## Description

Depends on T-0003 (the vector MetaLayer data type must exist). Independent of the ZUI control tasks (T-0001/T-0002) and the authoring UI (T-0006) — this is pure runtime read-side plumbing, unit-testable without any UI at all.

Add the runtime accessor(s) a game-code consumer (the muzzle/weapon system in T-0005, or anything else later) uses to read a vector MetaLayer's current value during playback.

**Pattern to mirror exactly** (confirmed by reading `ZonedAnimationPlayer.cs` this session): the existing point-reading API —
- `TryGetMetaPoint(layerId, out worldPos, out ...)` — exact-frame read.
- `TryGetMetaPointNearest(layerId, out worldPos, out ...)` — nearest-authored-frame fallback (used by the muzzle system today specifically because not every frame necessarily has a painted point).

Build the vector equivalents with the same two-tier shape:
- `TryGetMetaVector(layerId, out origin, out direction, out length)` — exact frame.
- `TryGetMetaVectorNearest(layerId, out origin, out direction, out length)` — nearest-authored-frame fallback, same fallback semantics as the point version.

Both should convert the MetaLayer's authored frame-pixel-space data into WORLD space the same way the point APIs already do (reuse whatever transform math `TryGetMetaPoint` uses — don't re-derive it).
