## Description

Three pieces of direct user feedback on screenshots from T-0134/T-0135, all fixed:

1. User annotated a screenshot showing Seed, Pitch and Specular each stranded alone on their own row with a large empty gap beside them -- the exact anti-pattern the T-0134 packing fix was supposed to remove, just relocated. Root cause: Canvas's 4 packed fields needed 553px against a measured 547px section width (6px short) so the 4th always wrapped alone; the Light Rig's 8 dials were split into two independent 4-item HGroups, so whichever dial didn't fit on a group's own first line became the LAST item in that group with nothing after it to share the line. Fixed: Canvas's three sliders trimmed 140->125px (clears with real margin, measured); merged the two 4-item light-dial groups into one continuous 8-item group so overflow lands beside the FOLLOWING dial instead of alone (now wraps 3+3+2, verified by measuring each child's layout.y).
2. User asked to see the full add-effect menu with all items -- doing so exposed a real bug: the effect catalog's declaration order interleaves buckets (the 7 hand-authored effects mix Padded/Free/NeedsSheets in sequence), and the menu opens a new Section header every time the bucket changes while walking the list in order -- so before this fix the menu showed 6 tiny one-item sections before settling into real per-bucket runs. Fixed: ShaperMockEffectCatalog.BuildAddable() now stable-sorts by bucket before returning, so the menu shows one clean section per bucket.
3. User feedback: the Swarm section spent a whole body row on a '+ Enable swarm' button when Pyre puts this exact kind of toggle in the SECTION HEADER instead (ZuiSection.SetHeaderToggle, used by PyreWindow.RebuildSwarm). Fixed Swarm to match Pyre exactly, and proactively applied the same treatment to Border (identical null-vs-present pattern) for consistency -- both now use a header checkbox, removing the redundant '+Add'/'Remove'/'Disable' body buttons entirely.

All three verified live via Coplay: structural measurement of wrap-line groupings (not just screenshots, which have had repeated rendering-timing artifacts this session under rapid programmatic resize) for #1, a fresh menu screenshot showing one clean per-bucket section for #2, and direct reflection into the section header's Toggle element (bypassing ZuiSection's Children() override, which hides header chrome from the public API) confirming both Swarm's and Border's header checkboxes exist and bind correctly for #3.
