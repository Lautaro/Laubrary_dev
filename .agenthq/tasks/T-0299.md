1. OPENING A WINDOW MUST NOT WRITE AN ASSET - root-caused and fixed. PyreWindow.OnAssetChanged wrote `layerSel = int.MaxValue` into the asset on EVERY load (previewLayerSel is a serialized field, and the setter calls SetDirty); BuildAsset then clamped it back with a second SetDirty. Net authored change on a healthy asset: zero - the asset was dirtied only to arrive at the value it started with, and the next domain reload wrote the whole file. Measured: binding a byte-identical duplicate of New Pyre Plus.asset flipped previewLayerSel 2147483647 -> 0 and set dirty=True; an ordinary recompile then rewrote the file from 216435 to 211993 bytes with a full ZuiGradient re-serialisation, with no user action at all. That is T-0288's and T-0293's "opening Pyre republishes the asset", explained. Isolated to the load-time write alone by using an asset whose index was already valid (0), where the clamp is a no-op: bind -> dirty=True; clear and rebuild -> dirty=False. The stomp also DESTROYED the persisted selection the field's own doc comment promises to keep, and when a flush landed between the two writes it persisted the raw sentinel - which is how the shipped asset came to carry 2147483647. Fixed by the rule "the dirty flag belongs to a user's choice of layer, never to housekeeping": a new ClampLayerSel() repairs an out-of-range index without dirtying, SelLayer's getter is read-only, the rebuild clamp is silent, and the layer-delete button (a real user action) still dirties. Verified after the fix on the real corrupt asset: bind -> repaired to 0 in memory, SelLayer returns a valid layer, asset stays CLEAN. Shaper does NOT have this defect - its OnAssetChanged writes only window [SerializeField]s.

2. PYRE'S BESPOKE SPLITTER - the T-0296 class of bug, confirmed and fixed. The DRAG clamped against the window (position.width - 260) but the BUILD clamped only against the four-column cap [360, 1458]. One ClampedLeftPaneWidth() now owns the cap for build, drag and a new GeometryChangedEvent re-clamp. Verified: 900x700 -> pane 640, 0 of 65 buttons off-screen; widened to 1900 with NO rebuild -> regrew to 1458, 0 of 27 off-screen; the persisted intent stayed 1458 throughout.
