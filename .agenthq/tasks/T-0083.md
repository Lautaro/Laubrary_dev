## Description

Protoguys bullets are drawn for the north direction. Zoe and combat system needs a way to rotate the bullets to the aim angle referencing north as the default.

### 2026-08-25T07:05:47Z — agent — in_progress -> done
ProtoGuy's gun bullets now turn to face whichever way you're aiming, instead of always pointing the one direction they were drawn in.
**Details:**
Bullet art was drawn facing north (up), so a bullet always looked like it was flying north even when it was actually flying sideways or down. Bullets fired from ProtoGuy's gun now rotate to visually match the real flight direction, using north/up as the reference "unrotated" pose that matches the art.

How to use this: no action needed to see it working in the ProtoGuy demo scene -- just fire the gun in different directions and the bullet sprite will turn to match. Other weapons/ammo in the project can opt into the same rotation by enabling their ammo's existing "Face Travel" checkbox; a new tunable on the bullet itself lets an artist correct for art drawn facing a different way than north, if that's ever needed for some other bullet.

Not yet verified: only checked via a runtime code probe that the rotation math is correct for the four cardinal directions, and confirmed no compile errors -- did not visually eyeball the sprite turning in the Game view during Play.
**Technical details:**
Root cause: D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Runtime/Combat2D/Projectile.cs LaunchCommon() rotated via plain Atan2(dir.y,dir.x) with no offset, which is Combat2D's general 'art drawn facing +X/right' convention (see LazorShape.cs comment) -- but projectile art baked via Launimator/Pyre (ZoeSpawner.BuildProjectileTemplate) is drawn facing +Y/north, same convention AimIndicator.cs already compensates for on its own marker (-90 offset).

Fix: added `public float rotationOffsetDeg = -90f` to Projectile (D:/UNITY/Laubrary Dev/Assets/Packages/Laubrary/Runtime/Combat2D/Projectile.cs), added into the rotation formula in LaunchCommon. Default -90 matches north-facing art (the common case going forward); an artist can set it to 0 for right-facing art on a specific prefab/template. No AmmoDef field added -- Zoe-driven projectile templates (ZoeSpawner.BuildProjectileTemplate) get the Projectile component's class default automatically, so no extra plumbing was needed; only add an AmmoDef-level override later if a real asset actually needs a non-default offset.

Also flipped `faceTravel: 0` -> `faceTravel: 1` on D:/UNITY/Laubrary Dev/Assets/Zoetrope/Hero Gun Ammo.asset (ProtoGuy's actual live bullet, referenced by ProtoGuy Gun.asset's ammoTypes) so the new rotation path is actually engaged for ProtoGuy; PreviewAmmo.asset was left untouched since it has no visual assigned (fileID: 0) and isn't the asset the task described.

Verified via a scratch execute_script (Assets/Editor/_Scratch_VerifyBulletRotation.cs, deleted after use) that instantiated the live weapon's projectilePrefab and called Launch() for the four cardinal directions: up -> rotZ=0 (unrotated, matches art), right -> rotZ=270 (-90), left -> rotZ=90, down -> rotZ=180 -- all correct. check_compile_errors clean before and after.
