### 2026-09-27T18:11:41Z — agent — in_progress -> in_progress
MEASURED on the owner's chain (Low pass at 194 Hz; Envelope curve 0 -> 0.88 -> 0.31 -> 0.15 -> 0; depth 1):
- Shift: cutoff moves 195 Hz .. 11,075 Hz.
- Set:   cutoff moves 633 Hz .. 12,873 Hz.
So not identical, but nearly: both peak around 11-13 kHz, and they differ only in where they rest (the set value vs 633 Hz).
For comparison, an LFO under either mode covers the full 20 Hz .. 20 kHz.
CAUSE: Set assumes a modifier outputs -1 to +1 (as an oscillator or a step list does) and maps -1 to the bottom of the parameter, 0 to the middle and +1 to the top. An Envelope outputs 0 to 1. So under Set it can only ever drive the parameter from the MIDDLE to the top; half of Set's range is unreachable, and what is left looks like Shift from a low value.

### 2026-09-27T18:18:37Z — agent — in_progress -> done
Done. Set now takes an Envelope's 0 to the bottom of the parameter and its 1 to the top, so it spans the whole range. It is chosen when the chain is laid out, from the kind of modifier bound, so stored bindings do not change and the interface still just says Set. Oscillators and step lists keep their both-ways mapping.
MEASURED on the owner's Envelope, after the fix:
- Set: 20 Hz .. 8,286 Hz, following the envelope's own shape (its 0.88 peak = 0.87 of the slider).
- Shift: unchanged, 195 Hz .. 11,075 Hz, pushing up from where he set it.
The two are now clearly different. An LFO under either mode is unchanged (full range).
Both engine paths that read a binding use the same fix: the per-block render, and the play-length calculation used when pitch is modulated.
