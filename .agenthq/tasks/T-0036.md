## Description

Splits a source sprite into a small number (2-6, not dozens) of large, recognizable pieces, each with its own
physical movement (reuse T-0035's physics where it makes sense). Distinct from the existing `SampledChunkSprites`
(which is tuned for many small, non-recognizable debris bits) — this is a NEW slicing mode aimed at "the pieces
still read as parts of the original thing," e.g. a spaceship Zoe's idle frame splitting into 3 recognizable hull
fragments.

Must work fully standalone (no layering/timeline/Mirage required). See `CHUNKS_OVERHAUL_DESIGN.md`
§"Standalone modules" #4.

**Details:**
How to use this: in Laubrary -> Chunks, switch on "Fragment Slicer" and drop in the sprite you want broken. The section shows a live picture of the cut, each piece in its own colour over a ghost of the original, so you can see the break lines before pressing Play; Reshuffle rerolls them. The source image needs "Read/Write Enabled" ticked in its import settings, otherwise there is nothing to cut and it quietly does nothing. Not yet verified: nobody has watched the pieces actually fly.
**Technical details:**
D:\UNITY\Laubrary Dev\Assets\Packages\Laubrary\Runtime\Chunks\Slicer\FragmentSlicerModule.cs, D:\UNITY\Laubrary Dev\Assets\Packages\Laubrary\Runtime\Chunks\Slicer\FragmentCutter.cs, D:\UNITY\Laubrary Dev\Assets\Packages\Laubrary\Editor\Chunks\ChunkWindow.Slicer.cs (stateKey "chunks.slicer"). ALGORITHM: seeded Voronoi cell partition over the sprite's own opaque pixels, chosen over a recursive chord split because every opaque pixel lands in exactly one cell, so the pieces tile the original with no gaps or overlap -- that exact tiling is what makes three fragments read as one hull that broke. Seeds spread by farthest-of-K sampling (K=16); a uniform pick clumps into one huge piece plus slivers. Cells under minPieceAreaPx MERGE into their nearest surviving neighbour rather than being dropped, preserving the tiling. Each piece carries offsetUnits = (bbox centre - sprite pivot) / PPU and spawns at ctx.Origin + offsetUnits, pivoted at its own centre -- a fragment spawning at the origin would destroy the effect. Launch angle = LerpAngle(aim, radialOutward, spread/180). CACHE: stores the PIXEL DATA of a cut, never built sprites (a fragment destroys its own sprite+texture on death, so cached sprites would be dead on the second burst), keyed on (sprite, pieceCount, minPieceAreaPx, seed), MRU of 8, used ONLY when seed != 0 since seed 0 means reroll and its key would never repeat. Generated Texture2D and Sprite are both HideAndDontSave and released together. TWO REQUESTS RAISED, NOT ACTED ON (deliberate, recorded for whoever picks this up): (1) ChunkWindow.Preview.cs is wired end to end to SampledChunkSprites and exposes no seam a second cutter could render into, so the slicer draws its own 200px canvas instead of sharing the existing stage -- a small registration seam there would let them share. (2) ChunkModuleRunner has no angular velocity and no fade, so the slicer drives spin and alpha from its own coroutine; adding those to the runner would be the shared fix, but it is deferred because two already-working modules depend on the runner as it stands. Known leak path documented in code: if the burst container is destroyed early the teardown coroutine dies with it, leaving those textures to Unity's finalizer.
