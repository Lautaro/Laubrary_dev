## Description

**Read first:** `D:\Unity\UNITY_DEV_GUIDE.md` and the Laubrary skill (`~/.claude/skills/laubrary/`, Zoetrope + SpriteFx references).

**Bug (Lautaro, 2026-09-06 23:45, live in `Assets/Demos/ProtoGuyDemo/ProtoGuyDemo.unity`):** "When protoguy fires a spriteFX stack is triggered with 'Fake Light' effect. It only seems to affect the leg sprites. We need the composite sprites to be treated as one visual entity. How do we handle that in the zoe system?"

The cue is the ProtoGuy fire reaction (`Assets/Demos/ProtoGuyDemo/ProtoGuy Fire Flash.asset` / `ProtoGuy.asset`), applied through Zoetrope's `Runtime/Zoetrope/BodySpriteFxEffect.cs` using `Runtime/SpriteFx/SpriteFxRelight.cs` (the "Fake Light" relight). ProtoGuy is a composite ZOE body (several SpriteRenderers / body parts — legs, torso, head, weapon…), and only the legs get the effect.

**What to do, in order:**
1. **Root-cause** why only the legs are affected: does `BodySpriteFxEffect` resolve one renderer (first child / a named part) instead of the whole body? Is the stack applied per-part and only the legs' part is bound? Does the relight need a shared material/property block that the other parts don't get? Write the finding into the task's Handover Log in plain words.
2. **Answer his design question** — how the ZOE system should treat a composite body as one visual entity for SpriteFx: the right seam is probably a body-level renderer set (Zoetrope already knows all body-part renderers) that every SpriteFx effect targets by default, with an opt-in to restrict to named parts. Prefer the smallest change that makes 'the body' the default target and keeps per-part targeting possible; do NOT introduce a render-texture composite unless nothing else works, and say why if you do.
3. **Implement it** so ProtoGuy's fire flash lights the whole figure (all parts, including the weapon if it is a body part) in ProtoGuyDemo. Keep the API in line with the Laubrary skill's authoring rules; CHANGELOG entry.
4. **Verify:** compile clean; an edit-mode test that a composite body's SpriteFx effect targets every part renderer; a Play-mode capture of ProtoGuyDemo mid-flash. Report verified-by-probe vs verified-by-eye separately.

**Constraints:** do not touch OutBurner, do not retouch art. This task is the "ProtoGuy lights up when firing" step of his to-do list in the ProtoGuy Planning tab (`.agenthq/planning/ProtoGuy.json`); the same body-as-one-entity rule will matter for the Chunks hit/death effects that follow (T-0008 in the Life Manager project), so design the seam with those in mind but don't build them here.
