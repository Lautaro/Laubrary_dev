## Description

Step 1 of the build plan from `D:\UNITY\Laubrary Dev\ZOE_PALETTE_BUILD_PLAN.md` (task 1 — read that file and `D:\UNITY\Laubrary Dev\ZOE_PALETTE_TAKE.md` for full context before starting; this is prerequisite work for T-0095).

Plain-language: every character is supposed to have a short pause before its body is cleaned up when it dies — long enough for a death effect to play and for it to read as a death rather than a disappearance. That pause only actually runs today if a death animation has been authored, and no character in the project currently has one, so in practice every death is instant and the pause never happens.

Root cause (verified by an adversarial-verify subagent during T-0089 round 4, not yet re-confirmed by whoever picks this up — re-verify before changing anything): `ZoeState.cs` around lines 75-93 schedules an `Invoke(Dispose, deathLinger)` call on death as the intended fallback. But `ReactionFxPlayer.cs` around lines 103-116 fires `DeathFinished` **synchronously, same frame**, whenever `def.death` is null or has no clip — and `ZoeState.OnDeathClipFinished` unconditionally disposes on `DeathFinished`. Both handlers subscribe to the same `Health.Died` multicast event, so the synchronous path races ahead of and defeats the scheduled `deathLinger` invoke. The fallback is effectively dead code today.

Fix so the linger duration is honored whether or not a death animation/clip exists. Verify by giving a test character a `deathLinger` value with no death clip authored and confirming the body actually persists for that duration before disposal, in a running editor — not just by reading the code.
