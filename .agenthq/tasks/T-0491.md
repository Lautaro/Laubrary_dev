**Final decisions:**
1. **Names and matching.** ZPOC is both the system and one exposed channel. Game code reaches everything through the existing play handle (ZoundToken). ZPOC ids are matched with the same rule as Zound names (ignore case, spaces, underscores and hyphens). Dots are NOT added to that rule, because that would change Zound matching too.
2. **Id scope.** An id is unique per Zound only. A call on a token reaches every match anywhere in that play's nested tree.
3. **Runtime never changes the saved asset.** Settings (ZPOC values, token volume/pitch/speed, track mute/solo/enabled/volume, snapshot target) belong to a token and last across its runs. Randomness belongs to a run.
4. **What a ZPOC can sit on:** a modifier, or a track. Parameters are never exposed one by one.
5. **A modifier's ZPOC has two modes.** Set: the strongest binding follows the value and the others keep their proportion. Scale: authored depth times the value (0 = off, 1 = as authored). Values are clamped to 0..1. There is no Add mode.
6. **The Code modifier:** a modifier whose output is the ZPOC value. When it is bound, the combine mode defaults by the kind of control: Ratio for pitch and speed, Scale for levels, Set for everything else.
7. **Replayable tokens.** Play on an ended token starts a new run and keeps the settings. Play on a playing token does nothing. Restart ends the current run and starts a new one. Chance and cooldown are rolled for each run. Reset is explicit. Setting a value on an ended token stores it for the next run.
8. **The old play calls are unchanged.** A new call or option returns a token even when the run did not happen ('not played'), or an empty token when the Zound is not found.
9. **Global (project-wide) values** are a fallback: the token's own value wins, then the global value, then the authored resting value. A token can clear its own value to follow the global again. Globals are runtime-only and cleared on engine teardown. An id that no Zound declares is warned once.
10. **One universal track model.** A Klip is its own track 0. A Zequence's tracks are 0..n-1 in authored order. An index that does not exist is warned once and recorded in the diagnostics list (T-0490). Track operations: volume, pitch, speed, fade, mute, solo, enabled, stop. A track can be addressed by number or by an optional track ZPOC id.
11. **Enabled toggle on a track:** silent and never chosen. Randomizer treats its weight as 0. Round-robin skips it without marking it played (that memory is shared by every play). Playlist steps to the next enabled track. Parallel treats it as muted. If every track is disabled, the run plays nothing. Disabling the track that is currently sounding silences it (with a short fade) and does not pick another one.
12. **The multi-instance display is a summary only:** a spread band with meter ballistics (widens at once, narrows over about 0.3 s) and an instance count. Drill-down into one instance is deferred.
13. **Amber** is the code-driven colour: a permanent chip, a static band when a value is held, and a pulse plus a target tick while it is moving. Grabbing a driven control uses touch override.
14. **The Zound's own values** (Volume, Pitch, Speed, Drive) become a real row. Volume sits after the effects and Drive before them. An inserted Gain effect is converted only where it sits last in the chain, and a version marker converts it on the next edit. Pitch and volume curves become ordinary modifiers added by right-click.
15. **Envelopes on the own values are read by source position.** Verify first what the code does today, then convert with a version marker. Playheads follow the source read position: one per read head; during a Looper crossfade both, the fading one dimmed; during time-stretch, the position minus the known look-ahead.
16. **The multi-curve waveform view** shows the own values only at first; chain parameters can be added explicitly. Exactly one curve is active at a time. Each curve has its own axis. The authored points are drawn solid and the combined result lighter. Parts that cannot be known in advance are drawn as bands. Dense modulation is drawn as a min/max band per pixel.
17. **Snapshots.** Default is an ordinary snapshot that always exists. Four kinds of setting: continuous values glide; an effect's on/off becomes a crossfade; choices and whole numbers switch at the glide's midpoint; settings that size memory apply from the next run. Curve shapes switch at the midpoint. Modifier settings are included. A range is drawn once per instance when the glide starts, and a run remembers what it drew for each snapshot. The name scope matches ZPOC (same name on sibling Klips; one call glides them all). A snapshot's resting value for a ZPOC loses to a value set by code.
18. **Graceful failure** follows the missing-Zound pattern: never throw, warn once, record in the diagnostics list (T-0490).
