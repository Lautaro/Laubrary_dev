## Description

**Owner-diagnosed (2026-09-21), root cause confirmed by reading the code — pre-existing bug, unrelated to today's T-0385 PPU fix, just newly visible now that backdrops are being looked at closely.** Every place a `BackSplash`/`BackSplashSettings` image is drawn computes its width and height scale INDEPENDENTLY from the view's own width/height, ignoring the sprite's own aspect ratio entirely — a stretch-to-fill, not a zoom. Confirmed in all these places (same bug, duplicated — this codebase already has one prior lesson about that exact duplication, see `BackSplashPainter.cs`'s own header comment about "the same twenty lines written three times"):

- `Runtime/BackSplash/BackSplashBackdrop.cs:87-90` (the real runtime backdrop): `scaleX = viewWidth/spriteSize.x`, `scaleY = viewHeight/spriteSize.y` — two independent divisions, no shared ratio.
- `Editor/BackSplash/BackSplashPainter.cs:44` (the shared editor-preview paint used by Pyre/Chunks/TextSplash previews): `w = view.width * imageZoom, h = view.height * imageZoom` — always exactly `view.width × view.height` regardless of the sprite's own shape.
- `Editor/BackSplash/BackSplashElement.cs:92` and `Editor/BackSplash/BackSplashWindow.cs:175` — same shape, check both.

**Owner's exact request (2026-09-21):** *"I think you made the splash backgrounds fit to the view which distorts its ratio. Don't do that. And make the zoom default to 1. Or if possible default to an auto set value where its the smallest zoom where both edges are filled with the image."*

**The fix — one formula, and it satisfies both halves of the request as the SAME change:** replace the independent-per-axis stretch with a single, UNIFORM scale using the larger of the two ratios (a "cover" fit — aspect preserved, the image covers the whole view, the larger dimension overflows/crops rather than the smaller one leaving a gap):

```
coverScale = Mathf.Max(viewWidth / spriteWidth, viewHeight / spriteHeight)
finalScale = coverScale * imageZoom   // uniform on both axes — never scaleX/scaleY separately again
```

With this, **`imageZoom = 1` (the field's own existing default) naturally becomes exactly "the smallest zoom where both edges are filled, no distortion"** — the owner's two asks (default to 1 / auto-default to the smallest covering zoom) turn out to be the same requirement once the formula stops distorting. No new "Auto" toggle needed — `imageZoom` keeps its existing meaning as a multiplier, it's just now a multiplier on a correct, aspect-preserving baseline instead of a raw view-fill stretch.

2. Fix `BackSplashPainter.cs` (shared editor paint) — the `imgRect` width/height computation.
