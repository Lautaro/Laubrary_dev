## Handover Log

### 2026-08-17T08:08:46Z — agent — in_progress -> done
Root cause found and fixed: the Shape fill's gradient editor Output preview strip always baked the Hue/Saturation/Brightness/Contrast transforms at a fixed life=0, no matter where you looked along the ramp. For the default Over-Life fill mode, ramp position IS the life clock, so an animated Brightness curve visually collapsed to one flat value smeared across the whole strip -- exactly the "applies over the gradient instead of over time" symptom. The actual runtime render was already correct (brightness does animate frame to frame); only the authoring preview lied about it.

Fixed by making the Over-Life gradient's Output preview sample each texel's colour transforms at that texel's OWN position (matching how it will really render), instead of a single frozen life-0 snapshot. Linear/Radial/Noise fills are unaffected (there position and life are genuinely independent, so the frozen snapshot stays correct for them).

Not yet done: did not personally re-open the PyrePlus window and eyeball the Fill preview strip on screen (verified via a direct LUT-bake test instead, see proof).
**Proof of done:**
- [x] ZuiGradient.ToLut() gained an optional lifeFollowsPosition param; when true each texel life = its own ramp position instead of a fixed value
- [x] ZuiGradientEditor now takes a lifeFollowsPosition flag and passes it into ToLut() when baking the Output preview
- [x] ZuiFillControl.GradientSection passes lifeFollowsPosition: true only when fill.mode == OverLife (Linear/Radial keep the old life-0 snapshot, unchanged behaviour)
- [x] Unity recompile: 0 errors (recompile_status completed/failed:false, EditorUtility.scriptCompilationFailed == false)
- [x] Numeric proof via eval: built a ZuiGradient with a Curve brightness (0 at life0 -> 2 at life1); old ToLut(lifeFollowsPosition:false) returned a flat black strip across all 5 texels; new ToLut(lifeFollowsPosition:true) returned 0,0.06,0.25,0.56,1.0 -- correctly varying across the strip
