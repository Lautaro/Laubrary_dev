# W1.1 runtime core — what the later waves need to know (T-0226)

Commit `c94fd934` on `dev`. Everything below is fact from the code as committed, not intent.

## Public surface the window will drive

- `Laubrary.DotGen.DotGen : ScriptableObject, IVisualPreview` — `seed`, `frameSize`, `background`, `guideGrid`, `showGuideGrid`, `frameStroke`, `showFrameStroke`, `gizmoMode`, `selectedGeneratorId`, `generators`, `nextId`, `previewBackSplash` (still null until someone allocates it — do it lazily in the window exactly like `PyreWindow.backSplash`). Methods: `NewId(prefix)`, `Tree()`, `Root`, `Find(id)`, `Selected`, `ApplyDemo()`, `Normalize()`, and a private Unity `Reset()` that gives the bare one-root state.
- `DotGenEvaluator.Evaluate(doc) → DotGenResult` (`order` in hierarchy order, `byId`, `totalVisibleDots`, `totalAreas`; per generator `areas`/`baseDots`/`finalDots`/`traces`/`childIds`).
- `DotGenRenderer.Render(doc, res, size, withDots)` → `Texture2D`, plus an overload into a caller-owned `Color32[]` (use that one for the live preview — it allocates nothing), and `RenderPng(doc, size) → byte[]`.
- `DotModuleRegistry.Placements / Selectors / Mutators / Drawers` — ordered `Entry { type, typeId, displayName, defaultName, order }`, `Create(entry)` (sets `name`, leaves `id` blank — the DOCUMENT assigns ids), `TryFind(list, typeId, out entry)`.
- `DotGenerator.UsePlacement(typeId)` switches method and creates the type's instance from its own defaults the first time. `ActivePlacement` never creates — it is safe to call from the evaluator and from a repaint.
- `DotGenFills.Solid/Linear/DefaultList/NewFlat/NewGradient` — the documented default fills, so the drawer card's "+ Flat" / "+ Gradient" buttons do not restate hex codes.

## Decisions made in this task (and why)

1. **Module ids keep the POC's prefixes — `gen_`, `place_`, `sel_`, `mut_`, `draw_`, `fill_` + base36 counter — not the `g_`/`s_`/`m_`/`d_` shape written in DOTGEN-DESIGN-DECISIONS.md §2.** A child's spawn draw is `hash01(seed+37, dotIndex, childId.Length)`, so id LENGTH is an input to the picture. With three-character ids the demonstration composition evaluates to different counts than the ones the behaviour checklist measured, i.e. the tool would not reproduce its own reference. `ApplyDemo()` therefore writes its ids out literally (`gen_1`, `place_2`, … `mut_e`, `nextId = 15`) rather than allocating them, so the demo is reproducible whatever the counter did beforehand.
2. **The Margin selector has NO `zone` field**, although the HTML's data carries one. It is algebraically inert: `lerp(core, band, w)` under `zone: band` and `lerp(band, core, 1−w)` under `zone: core` are the same expression, so the flag can never change a weight. The demo's "Safe frame" is authored as the spec §20.1 states it (band width 8, softness 3, edge value 0, core value 100) and produces the reference's own 56 root dots.
3. **Nudge's "Bias angle" is always visible.** The POC hides it while Direction bias is zero; `[ZUIShowIf]` matches a sibling's VALUE, and "greater than zero" is not a value. Hand-gating it inside one card would put the rule somewhere no other module could reach. Left visible with a tooltip saying it does nothing at bias 0. **If W1.2 adds a comparison form to `ZUIShowIf`, this is its first customer.**
4. **`selectorId` on `DotMutator` and `DotDrawer` is `[HideInInspector]`**, because `ZuiReflect` skips those (`ZuiReflect.cs:133`) and a reference must be a picker over declared names, never the text field reflection would give it. The card draws that row itself.
5. **Box Row's height sliders carry a static `[Range(1,1000)]`** in both modes, as design-decisions §2 already ruled; evaluation clamps to `1 − 2×padding` when Grow outside area is off, so the wide range is inert there.
6. **The renderer has no gizmo pass and no gizmo flag.** W2.3's overlays draw over the preview texture in the editor, reading `DotGenResult`; there is nothing in the render path for an export to have to turn off.

## Numbers to hold the later waves to

- Demonstration composition: Root Frame 1 area / 56 dots (hidden), Radial Clusters 22 areas / 286 dots, Diamond Grids 9 areas / 22 dots → **308 visible dots, 32 generator areas**. Anything else means a regression, not a new result.
- Evaluate + render at 512 px: **3.5 ms** (best of six; evaluate 0.39 ms, render 3.13 ms). The preview can re-render per repaint without a cache, though caching is still worth it for scroll.
- `hash01` agrees with the reference JS exactly on `(4821,0,0)`, `(4858,13,5)`, `(-7,999,123456)`, `(0,0,0)`, `(2147483647,-1,17)`.

## Not covered by this task

- No editor code at all: no window, no cards, no gizmos, no menu item. `Laubrary/DotGen` does not exist yet.
- `previewBackSplash` is declared and serialized but nothing allocates or draws it yet.
- Double-click slider reset needs `ZuiReflect` to pass a type default (W1.2); the runtime side is ready because every module's defaults ARE its field initializers.
- `Z.AnchorGrid` does not exist; `DotAnchor` is a plain enum until W1.2 builds one.
